# Claude Code — Lumiverb repository guide

Navigation index. Read this before `ls`/`grep`/`find`. File paths and
ownership live here; logic, schemas, and thresholds do not — read the code.

---

## Stack & topology

Python 3.12 (FastAPI + SQLModel + Postgres 18), React 18 +
Vite + TanStack web UI, Swift 5.9 / SwiftUI for native macOS + iOS
(shared `LumiverbKit` package, XcodeGen project).

FastAPI and the scheduler (`lumiverb-scheduler`, all processing, on the
same box) are the persistent services; only the scheduler and the CLI
scan; macOS and iOS are browse-only. Direction is ADR-016: one server (a Linux box, or a Mac) schedules all
processing against read-only storage, human data is never overwritten by derived data, and what used
to be "collections" are projects (`/v1/projects` for every client;
`/v1/collections` is gone). Text search is PostgreSQL's own, in each
account's database (ADR-019). Auth: JWT (web) + API keys (CLI), both
`Authorization: Bearer <token>`; roles `admin` / `editor` / `viewer`; a
device's key (a computer that scans, not a person) only scans the
libraries it reads; the server admin, a person signed in, has what's the
install's rather than an account's.

## Top-level layout

```

  server/                  Python API server, DB, search, upgrade runner, scheduler (all processing)
  producers/               One folder per producer: its spec and its work; the runner
  processing/              What the scheduler and the CLI's scan share (API client, scanning, media tools, AI machines)
  client/                  Python CLI (asks the scheduler; never processes)
  shared/                  Code used by both server and client
  ui/web/                  React web app (Vite)

  api/ cli/ core/ models/ repository/ search/ storage/ upgrade/ video/ workers/

              lumiverb / lumiverb-server command it gives is one their own parsers take
```

## API conventions (do not relitigate)

- All routes under `/v1/`, `Bearer` token required.
- Tenant from token, **never** a URL param.
- Cursor pagination only (`after` / `next_cursor`). A cursor the list didn't give is a 400 `bad_cursor`: every list reads `after` through `src/server/cursors.py` (`unpacked` for a base64 JSON one, its fields' kinds checked; `plain` for an id or path), never binds it as it came (`tests/test_cursors.py`).
- Errors: `{"error": {"code", "message", "details"}}`.
- Multipart uploads. No webhooks, no source serving. Rate limiting only on login, password reset, changing your own password (by address every try; by email or person only failures, or each reset link asked for, held sooner from one address than from anywhere, so nobody is kept out by someone else's tries: `api/rate_limit.py` `name_held` / `name_counted`), what a browser says it couldn't load (`routers/me.py` `POST /v1/me/failed-requests`, the web's `api/failedRequests.ts`: requests that got no answer, logged once one gets through, for Admin › Logs), a public page's searches (`api/rate_limit.py`: query, facets, more like this, by address, for someone not signed in) and searches by picture (`search-by-image`, whose faces are found in a process of the API's own: `src/server/faces/server_face_provider.py`, the faces producer's `FaceDetector`).
- Routes match in **definition order** — static before parameterized.
- **The API requires the user's say** for surprising outcomes: the request carries the choice (e.g. `remove_from_projects`, `with_clips`) or gets a 409 in the error envelope with the facts, so every client must ask (`api/errors.py` `DecisionRequiredError`; cursor-api.md "Decisions the API requires").
- Deleting goes delete → trash → restore | delete forever, for assets, projects and libraries (a library's: `DELETE /v1/libraries/{id}`, `POST .../restore`, `POST /v1/libraries/empty-trash`).

## Gotchas

- **`active_assets` view** must be dropped + recreated when adding columns to `assets`.
- **`app.routes` holds an included router as one entry** (FastAPI 0.143+): a test that checks every route walks them with `tests/app_routes.py` `api_routes(app)`, never `app.routes` alone (which finds none and checks nothing). FastAPI is `fastapi`, not `fastapi[standard]` (it brings OpenTelemetry's exporter), and its telemetry is off (`main.py` `NO_TELEMETRY`; `tests/test_no_telemetry.py`).
- **ONNX Runtime leaks ~35 MB/inference.** Batch work is subprocess-isolated for exactly this reason — don't collapse it.
- **`ThreadPoolExecutor`**: never submit all futures at once; cap at `concurrency * 2` and `_drain()`.
- **`systemd` units**: `update.sh` (its `update-api.sh`) writes the scheduler's (when the install does processing) and the upkeep timers' units afresh but only patches the API's: an entry-point change there needs a patch of its own in `update-api.sh` (as uvicorn → `python -m src.server.api` has) or the unit fixed by hand (or `deploy-api.sh` run again).
- **Prod**: never SSH or run commands on the VPS. User handles deploys; server auto-updates after push.
