# Lumiverb API — Cursor Context
*Feed this to Cursor when working on the API server. These decisions are final — do not relitigate them.*

---

## Stack

- Python 3.12
- FastAPI + SQLModel + Alembic
- PostgreSQL 18 (per-tenant database model)
- PostgreSQL full-text search, in each account's database (ADR-019)
- What Lumiverb keeps behind one interface, the Store (ADR-020): a filesystem provider, the only one

## Non-Negotiables

- Every route lives under `/v1/`
- All routes require `Authorization: Bearer {token}` header (token is a JWT for web sessions or an API key for CLI/automation)
- Tenant context is always derived from the token (JWT claims or API key lookup) — never passed as a URL param or body field
- Pagination is cursor-based, never offset-based. `after` is a `next_cursor` the same list gave (opaque: send it back as it came); any other value (not one of its cursors, a value of another kind than it holds, one holding a NUL or a lone surrogate inside) is a 400 `bad_cursor`, never bound into a query (`src/server/cursors.py`); one in `after` as sent is the 400 `not_text` below
- What a request sends is text: anything that isn't is a 400 `not_text`, on every route, before anything reads it (`src/server/api/no_nul.py`). `details.found` says what was found: `nul` (a NUL character, U+0000), `surrogate` (a lone surrogate, U+D800 to U+DFFF: half of a UTF-16 pair, no character on its own, such as JSON's `"\ud800"`; a pair written `"😀"` is its one character and fine) or `not_utf8` (a URL whose bytes, percent-decoded, aren't UTF-8, such as `%FF`, or `%ED%A0%80`, a surrogate's bytes); PostgreSQL keeps none of them. `details.in` says where: `path`, `query` (any parameter, its name too), `body` (a JSON body's strings, keys too, and text a route reads as JSON, such as ingest's `exif`) or `form` (a form's text fields, and their names). The URL is looked at before sign-in, so a public page's request is refused the same; a body only once sign-in (and a demo session's read-only rule) has let the request through, and only a JSON (`application/json`, `application/…+json`) or form body: a file's bytes, an upload's chunks, previews and videos are never read for it. A form's bytes that aren't UTF-8 are read as they always were (as Latin-1, or U+FFFD): text either way. One that reaches the database anyway is the same 400, with no `details.in`.
- File uploads are multipart form data
- The API serves what it keeps itself (`GET /v1/assets/{id}/artifacts/...`; signed playback links for a `<video>`, which can't send a header): never a storage path, and never an original
- Error responses always use this envelope: `{"error": {"code": "...", "message": "...", "details": {...}}}`, every one of them (`api/errors.py`). A route raises `ApiError(status, code, message, details)` for its own code, or a plain `HTTPException(status, "message")`, whose code its status names: `bad_request` (400), `unauthorized` (401), `forbidden` (403), `not_found` (404, an unknown route too), `method_not_allowed` (405), `conflict` (409), `gone` (410), `too_large` (413), `invalid_request` (422), `upstream_error` (502), `unavailable` (503). A request that fails validation is a 422 `invalid_request`: `message` names the first field, `details.errors` lists them all. An unhandled error is a 500 `internal_error`. Nothing nests the envelope inside `detail`.
- A retired route stays defined, behind the role it always needed (401 without a token, 403 for a role it never let in), and answers 410 `gone`, saying what replaced it in `message` and `details.replaced_by` (`api/errors.py` `GoneError`): a client still calling it learns why, not a bare 404.
- Bounds are the same everywhere (`api/limits.py`), and out of range is a 422, never a silent clamp: a page of clips holds at most 500 (`limit`), a request body at most 10,000 ids in any `*_ids` list.
- What an impactful action acts on is said, never inferred from a missing argument: its ids, or `"all": true`. Neither (or both) is a 400 `scope_required` (emptying the trashes, deleting missing clips; upkeep's `tenants=all`).
- 503 `database_unavailable`: the database is away for now (a lost connection, a deadlock, too many connections); try again. Other database errors are 500s.
- 503 `storage_unavailable` (with `Retry-After`): where the previews are kept can't be reached now (a chosen folder's drive unplugged); try again when it's back. Nothing is taken for missing meanwhile.
- OpenAPI spec is generated automatically from route definitions — keep docstrings accurate

## Database Model

Two-layer Postgres architecture:

**Control plane DB** (shared, tiny):
- `tenants` — tenant_id, name, plan, status, vision_model_id (the vision job's model), transcript_model_id (the transcripts job's, `small` until changed), created_at
- `ai_machines` — machine_id, tenant_id, name, api_url, api_key, jobs, at_once, enabled, built_in (one per tenant), online, status_error, models, checked_at, created_at (see AI machines API)
- `api_keys` — key_id, key_hash, tenant_id, name, label, scopes, role (`admin`|`editor`|`viewer`), created_by_user_id (the user who made it, signed in or with a key of theirs; null for the scheduler's and the operator's), scheduler (true for the scheduler's own key alone: set only where the scheduler makes it, never on a key a person made or a device's), created_at, last_used_at, revoked_at
- `users` — user_id, tenant_id, email, password_hash, role (`admin`|`editor`|`viewer`), token_version (in every JWT as `tv`; bumped to revoke the user's tokens), created_at, last_login_at
- `password_reset_tokens` — token_hash, user_id, expires_at, used_at
- `public_libraries` — library_id, tenant_id, created_at
- `public_projects` — project_id, tenant_id, created_at (a public link names its account; its database is the account's `tenant_db_routing` row, as for every request)
- `revoked_tokens` — jti (PK), revoked_at. Tracks revoked JWTs for server-side logout/refresh revocation. Cleaned up by upkeep sweep (entries older than 8 days).
- `tenant_db_routing` — tenant_id, connection_string, region

**Tenant DB** (one per tenant, same Postgres instance):
- `libraries` — library_id, name, root_path, status, last_scan_at (updated on each ingest via bump_revision), is_public, revision (int, bumped on asset ingest), created_at, updated_at
- `library_path_filters` — filter_id (lpf_+ULID), library_id FK, type (include|exclude), pattern, created_at. Controls which paths are ingested per library.
- `tenant_path_filter_defaults` — default_id (tpfd_+ULID), tenant_id, type (include|exclude), pattern, created_at. Tenant defaults and library filters are merged at evaluation time (see filter evaluation rules below).
- `assets` — asset_id, library_id, rel_path, content_hash, file_size, file_mtime, media_type, width, height, duration_sec, proxy_key, proxy_sha256, thumbnail_key, thumbnail_sha256, exif (JSON), exif_extracted_at, camera_make, camera_model, taken_at, taken_at_offset_min, gps_lat, gps_lon, gps_accuracy_m, iso, exposure_time_us, aperture, focal_length, focal_length_35mm, lens_model, flash_fired, orientation, availability, status, video_indexed, video_preview_key, error_message, created_at, updated_at, deleted_at, search_synced_at, transcript_synced_at. `taken_at` is the camera's wall clock as the file writes it, stored as if UTC on every scanner; its zone, when the file says, is `taken_at_offset_min` (minutes east of UTC), so the instant is `taken_at` minus it (ADR-017).
- `asset_location` — asset_id (PK, cascades with its clip), lat, lon, radius_m (0 for a person's exact point), source (`person` | `time` | `suggestion`), status (`applied` | `suggested`), basis (JSONB: why), set_by, set_at. Only what the file doesn't say (ADR-017); `assets.gps_lat`/`gps_lon` stay the file's, written only by the scan, and (0, 0) is no fix.
- `video_scenes` — scene_id, asset_id, scene_index, start_ms, end_ms, rep_frame_ms, proxy_key, thumbnail_key, rep_frame_sha256, description, tags (JSONB), sharpness_score, keep_reason, phash, created_at, words (a tsvector computed from description and tags: what search reads)
- `asset_search` — asset_id, described, note, ocr_text, transcript_text, path_words, snippet, and the tsvectors computed from them (everything, shown, shown_capped): a clip's words as a person sees them, written by the search sync (ADR-019)
- `transcript_segments` — asset_id, seq, start_ms, end_ms, text, words (computed): a transcript a segment at a time, written with it
- `video_index_chunks` — chunk_id, asset_id, chunk_index, start_ms, end_ms, status, worker_id (CLI-generated session ID), claimed_at, lease_expires_at, completed_at, error_message, created_at
- `asset_metadata` — metadata_id, asset_id, model_id, model_version, generated_at, data (JSONB)
- `asset_embeddings` — embedding_id, asset_id, model_id, model_version, embedding_vector vector(512), created_at
- `asset_ratings` — user_id (text), asset_id FK (ON DELETE CASCADE), favorite (bool, default false), stars (int 0-5, default 0), color (text, nullable; red|orange|yellow|green|blue|purple), updated_at. PK: (user_id, asset_id). User-scoped ratings — each user has their own independent ratings per asset.
- `saved_views` — view_id (sv_+ULID), name, query_params (URL query string), icon (nullable), owner_user_id, position (int), created_at, updated_at. User-scoped bookmarked filter presets. Navigates to `/browse?{query_params}`.
- `system_metadata` — key, value, updated_at
- `faces` — face_id, asset_id, bounding_box_json, embedding_vector vector(512), detection_confidence, detection_model, detection_model_version, created_at. Populated by CLI face detection (InsightFace). HNSW index on embedding_vector for future clustering.
- `people` — person_id, display_name, created_by_user, centroid_vector vector(512), confirmation_count, representative_face_id FK, created_at. Populated via People API and cluster management UI.
- `face_person_matches` — face_id, person_id, confidence, confirmed bool, confirmed_at. Populated when faces are assigned to people. Unique constraint on face_id (one person per face).

pgvector extension is enabled at provisioning time. Used for asset embeddings (CLIP), face embeddings (ArcFace), and similarity search.

### Soft delete — always use `active_assets`

Assets are soft-deleted via `deleted_at` (set by trash operations). The `active_assets` view is defined as:

```sql
SELECT * FROM assets WHERE deleted_at IS NULL
```

**Non-negotiable rules — enforced by tests in `tests/test_soft_delete_invariants.py`:**

1. **Never query `FROM assets` directly** in any read path that should return live assets. Always use `FROM active_assets` in raw SQL, or add `.where(Asset.deleted_at.is_(None))` in ORM queries.
2. **`AssetRepository.get_by_id()` returns `None` for trashed assets.** Do not use `session.get(Asset, id)` as a substitute — it bypasses the filter.
3. **`get_by_library_and_rel_path()` intentionally returns trashed assets** because the ingest upsert path needs to detect them to avoid a unique-constraint violation on `(library_id, rel_path)`. It is the only read method that does this. Ingest clears `deleted_at` on update when the file was missing (a file present on disk is back), but never for a person's trash or archive (409).

**Why a clip is out of sight** (`deleted_reason`; `deleted_at` is when it got there). Robert's model (Oct 8): archive = out of sight, kept forever; trash = the person wants it gone, restorable until it's deleted for good after the account's trash days.

| Reason | Kind | Comes back | Deleted for good |
|---|---|---|---|
| `archived` | archive: a person archived it | `POST /v1/assets/unarchive` | never on its own; trash it first, or with its library |
| `missing` | archive: a scan no longer finds the file | by itself when the file returns (by path; by content when following moves) | never on its own; trash it first, or with its library |
| `user` | trash: a person trashed it | `POST /v1/assets/restore`, back to where it was (`trashed_from`) | after the trash days, or emptied by hand |
| `library` | trash: it went with its library | with the library (`POST /v1/libraries/{id}/restore`) | with the library |
| `handed_over` | transient, inside a copy-then-delete handover | — | in the same transaction |

Scans skip `archived` and `user` paths: the scan's plan on the server (Scans API). Trashing an archived clip makes it `user`, restarts its clock and remembers what it was (`trashed_from`), so restoring it puts it back in the archive. Purges re-check under a row lock: whatever was restored, archived or trashed again since it was listed is never deleted, and a restore arriving mid-purge waits, then finds it gone.
When writing queries, always use the tenant DB session, not the control plane session. The middleware resolves this from the bearer token before the route handler runs.

Tenant resolution runs for every request except `/health`, `/v1/admin/*`, `/v1/auth/*`, `/v1/upkeep*`, `/v1/filters/*` (the filter capabilities, the same for everyone) and `/v1/stream/*` (a signed playback link resolves its own tenant), and the OpenAPI pages: reads `Authorization: Bearer <token>`, attempts JWT decode first (signature + expiry + required claims: `sub`, `tenant_id`, `role`; checks `jti` against `revoked_tokens` table), falls through to API key lookup on JWT failure, looks up `TenantDbRouting` for the connection string, and stores `tenant_id`, `connection_string`, `user_id`, `key_id`, `role`, and `is_public_request` in `request.state`. Use the `get_tenant_session` dependency in route handlers to obtain a tenant DB session.

All API responses include security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy` (script-src 'self', frame-ancestors 'none'), `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/microphone/geolocation denied).

## Tenant Context

- **GET /v1/tenant/context** — Tenant auth required. Returns `{ "tenant_id", "vision_api_url", "vision_api_key", "vision_model_id" }`: the first enabled AI machine doing vision and the vision model, for clients that know one endpoint (the CLI's `admin vision-test`). `vision_api_url` is an account admin's (the scheduler's own key is one; `""` when no machine does vision) and null for anyone else, as every AI machine's address is (`GET /v1/ai`). The worker reads all the vision job's machines from `GET /v1/ai/jobs/vision`. `vision_api_key` is always `""`: an AI machine's key is write-only (only the scheduler's own key reads it, from `GET /v1/ai/jobs/{job}`); the CLI's `admin vision-test` takes one with `--api-key`.
- **GET /v1/tenant/settings** — Any signed-in role. Returns `{ "video_preview_max_seconds", "public_video_preview_max_seconds", "follow_moves", "trash_days", "key_idle_days", "folders" }`: how many seconds of each video playback serves signed in (`null`, the default, for the whole video) and on public pages (10 until set; `null` once lifted), and whether moves and renames are followed (`true`, the default). Public pages get the smaller of the two caps. Stored in the tenant DB's `system_metadata`. **Follow moves** on: the same content is the same asset, so ingest restores an archived asset by content, a scan moves clips (Scans API), and a file that goes missing while an empty, newer copy of it is in the library moves to the copy (see `DELETE /v1/assets`). Off: the path is the only identity, so a file at a new path is a new asset and nothing is matched by content. **Trash days** (`trash_days`, 30 until set; 1–3,650, or `null` for never): how long clips a person trashed, libraries and projects stay in the trash before upkeep deletes them for good. Archived clips aren't deleted on their own; they go only with their library. `PATCH` takes `confirm_purge`: fewer days (or turning them back on) answers 409 `trash_days_shortened` when it would delete things at once, until it's true (see Decisions). **Key-idle days** (`key_idle_days`, `null` until set: keys work until revoked; 1–3,650): upkeep ends a key a person made once nobody has used it for that many days (made that long ago, if never used), so one left in an old script or on a lost laptop stops working. Never a key nobody made (the scheduler's, or one the server admin's API made for the account), a device's (the Devices API ends those), or the account's last admin key. Each key in `GET /v1/keys` says when (`ends_at`). `PATCH` takes `confirm_end_keys`: fewer days (or turning them on) answers 409 `keys_would_end`, naming the keys, when some would stop working at once (see Decisions). Web: Settings → API Keys; CLI: `lumiverb settings key-idle-days`. **Folders** (`folders`, read only here): the folders on this server the account's libraries may be in, as a server admin gave them (`PUT /v1/admin/tenants/{tenant_id}/folders`), or `null`, every account's until given some: any folder the server reads. The web says them where a library's folder on this server is chosen (Add library, Library settings › Who reads it, the setup wizard's first library).
- **PATCH /v1/tenant/settings** — Admins only (403 otherwise). Body: any of the fields; one left out stays as it is. The caps take `<1..86400 | null>` (`null` means the whole video; 422 for anything but a whole number in range), `follow_moves` takes `true` or `false` (422 otherwise). A cap change clears the cuts made for the old caps. Returns the settings. Web: Settings → Playback and Settings → Files; CLI: `lumiverb settings video-preview` / `public-preview` / `follow-moves`.

## Roles

Every route that writes needs at least an **editor** (403 for a viewer), unless it says otherwise: machine and scanner results (vision, OCR, embeddings, faces, transcripts, probes, artifacts, ingest, scans, marking files missing), video chunks and scenes (claiming a chunk too), notes, people and faces. A viewer writes only their own ratings (`/v1/assets/ratings`, `/v1/assets/{id}/rating`) and saved views (`/v1/views`), and may send reads as POST (`/v1/assets/project-usage`, `/v1/assets/ratings/lookup`, `/v1/similar/search-by-*`). `tests/test_viewer_writes_forbidden.py` checks every write route against this list.

**Roles per library** (ADR-018 decision 8, phase 8): a person's role is per library: an account admin is every library's admin; anyone else has the role set for them on a library (Library people below), or none on a private library or when they see only the libraries they're given (`every_library` false, Users API), or else their account role. A library they can't see doesn't exist for them: a route naming it, or a clip, scan, upload, video chunk, scene or face in it, by its path or in its body or query (`asset_ids`, `items[].asset_id`, `library_id`, …), answers 404 as for one that isn't there. Editing one needs an editor's role on its library, not in the account: a viewer there gets 403, and an account viewer who is a library's editor edits it. What spans libraries shows them only what they can see: the library list and its health, search and facets (`/v1/query`, `/v1/assets/facets`, and a search saved as a project), the trash and the archive, favorites, change reports, and Processing's counts, failures and queue; what acts on every library (`all: true` on retries and Run now, `POST /v1/changes`) acts on the ones they edit. A project shows them only its clips in libraries they can see: its count, cover, clips, export, order (a reorder moves the clips they see, the others keep their places) and Processing's counts for it; a project none of whose clips they can see isn't listed or opened (404) unless they made it; restoring its clips restores those in libraries they edit. A public project shows what its owner can still see. People are shown when they have a face in a library they can see, with only those faces (counts, faces, the face they're shown by, nearest people); anyone else is a 404, named or dismissed, renamed, deleted, merged or given a face. Groups of unnamed faces (`/v1/faces/clusters`) show only their faces in those libraries; a group with none is `cluster_changed`, as one that isn't there, and naming or dismissing a group names the faces in libraries they edit, the others left as they are. An account admin is every library's admin. A key a person made acts as them, never above its own role; a key no person made (the scheduler's) has its own role on every library. A library's admin (`admin` on it) runs it: its settings, Scans pause, privacy and people (Libraries API), and sees its folder and reader; what's the account's (making it public, where its files are and who reads them, as making a library is, where its previews live, the account's people) stays an account admin's (`src/server/api/library_access.py`; `tests/test_library_access.py` tries a person who edits one library, views another and can't see a third on every route; `tests/test_library_sight.py` every list, search, project, person and group of faces).

The **server admin** looks after the install rather than an account (ADR-018 decision 8): its accounts and server admins (Admin API), where previews live (`/v1/system/storage`), who can open it (changing `/v1/system/network`), backups (`/v1/system/backups`) and the service's log (`/v1/system/logs`), and sees the Admin page's disk and backups rows. That's a person who signs in (`users.server_admin`, read at each request like the role, so naming or removing one takes effect at once), in any account and with any role there; a key is never one, whoever made it. Everyone else, an account's admin too, gets 403 `server_admin_required` there (`dependencies.require_server_admin`; `tests/test_server_admins.py` holds the routes to a list). Whoever sets the install up is one (first-run setup). A server admin is out of an account admin's reach: whoever holds their password has the install, so only another server admin makes them a new invite link, changes their role or libraries, or deletes them (Users API, 403 `server_admin_user`), and no delete leaves the install without a server admin who can sign in (409 `last_server_admin`). An install from before had every account admin doing this: where it has one account, its admins became server admins; where it has several, nobody did, and someone on the machine itself names one with `lumiverb-server server-admins add EMAIL` (also `remove`, and with no arguments who they are). On a Mac with one account, one person is both.

A **device's** key (Devices API) has no person's role: it scans the libraries the device reads and does nothing else. Every route turns it away (403 `not_for_devices`) but the ones a scan calls: checking in, `reader-changes`, `reader-work`, the Scans API's calls, `POST /v1/ingest`, the `lumiverb.preview`, `lumiverb.preview.thumbnail`, `lumiverb.video.preview` and `lumiverb.video.analysis_proxy` uploads (one request, or the Uploads API), `PUT /v1/assets/{id}/video-facet` and `/capture`. Even those, only for a library naming it as its reader: a library, scan, clip or upload of another is a 404, as one that isn't there. It can't search, browse, play or download anything, see faces or people, or edit (`src/server/api/devices.py`; `tests/test_device_keys.py` tries it on every route).

## Auth API

Routes under `/v1/auth`; no tenant auth required (these establish auth).

- **POST /v1/auth/login** — Body: `{ "email", "password" }`. Returns `{ "access_token", "token_type": "bearer", "expires_in" }`. JWT contains `sub` (user_id), `tenant_id`, `role`, `tv` (the user's token version), `jti` (unique token ID), `iat`, `exp` (1 hour), `refresh_exp` (7 days from login). Rate limited: 5 tries a minute per address, every try; by email, only failed ones, so nobody holds someone else's account back by sending its email (their right password never counts): 5 failures in 15 minutes for an email from one address hold that address back for it, and 25 from anywhere hold the email back for everyone, so one address guessing is stopped long before its owner is (it takes five failing as fast as they're let); signing in forgets that address's failures (`api/rate_limit.py`). 429 past either. Every request with a JWT reads the user from the control DB: a token whose user is gone or whose `tv` isn't the user's `token_version` is 401 `token_revoked`, and the role is the database's, not the token's. Changing a user's role or password (reset) bumps `token_version`, and deleting the user removes them, so all their tokens stop working at once.
- **POST /v1/auth/refresh** — Requires `Authorization: Bearer {token}` (may be expired). Issues a fresh JWT if the token is within its refresh window, not revoked, and its user still exists at the same token version (401 otherwise). The new token takes the role from the database and keeps the original `refresh_exp`: the window runs 7 days from login, never extended by refreshing. Revokes the old jti; a token refreshes once. Returns `{ "access_token", "token_type", "expires_in" }`. The frontend calls this transparently on 401.
- **POST /v1/auth/forgot-password** — Body: `{ "email" }`. Where the install says whoever is at its machine owns it (`LUMIVERB_RESET_ON_THIS_MACHINE=true`, a Mac's: `lumiverb-server init --reset-on-this-machine`; never a server's, where anything on it could reset any account), from that machine (as nginx saw the request, `api/client_address.py`): 200 `{ "reset_url": "/reset-password?token=…" }` at once (a Mac has no email set up), or 404 `no_such_account`. Otherwise: sends the reset email if SMTP is configured, 204 for any email (no user enumeration); without SMTP, 501 `reset_elsewhere` (that Mac's install: use it on that computer) or `reset_not_set_up`. Rate limited: 3 requests a minute per address; by email, each link asked for, 3 in 15 minutes from one address and 10 from anywhere, so one address asking for someone's link again and again is held back before their own request is (and their mailbox gets 10 in 15 minutes at most); 429 past either. `lumiverb-server reset-password` does the same on the command line.
- **POST /v1/auth/join** — Body: `{ "token", "password" }`. An invite's link: sets the new person's password (12 to 72 characters, else 400 `password_length`, and the link still works), signs them in and returns `{ "access_token", "token_type", "expires_in" }` as login does. Like reset-password, it ends what an earlier password could have made: their other unused links stop working. 400 `invite_not_valid` for a used or expired link. Rate limited as reset-password.
- **POST /v1/auth/reset-password** — Body: `{ "token", "password" }`. Sets the user's new password from a reset link, ending everything the old password could have made: every token the user holds (`token_version` bumped), the API keys they made (`created_by_user_id`: in Settings › API Keys, or with one of their keys), and their other unused links, reset and invite links alike. Keys no user made stay, so the install's processing goes on: the scheduler's, and those the server admin's API makes for an account (`POST /v1/admin/tenants`, `POST /v1/admin/tenants/{tenant_id}/keys`: the account's, whoever asked); upkeep sends `ADMIN_KEY`, the install's own key, which isn't an account's. Returns 200 `{ "api_keys_revoked" }`: how many of their keys it revoked, for the page to say so. 400 for an invalid, expired or used link; of two of a user's links used at once, one sets the password and the other gets 400. Rate limited: 5 requests/min per IP. `lumiverb-server reset-password` ends the same, and says how many keys.
- **POST /v1/auth/logout** — Revokes the JWT server-side (inserts jti into `revoked_tokens`). The token cannot be used or refreshed after logout. Returns 204.
- **GET /v1/auth/demo** — Whether anyone may try this server as a viewer (`src/server/demo.py`): `{ "on": true }` when the env file's `LUMIVERB_DEMO_VIEWER` names a viewer (an email) who isn't a server admin, in an account that isn't deleted; 404 `not_found` otherwise, as a server with no demo answers. The sign-in page offers it.
- **POST /v1/auth/demo** — No body, no password: signs in as that viewer, for a session that reads only. Returns `{ "access_token", "token_type", "expires_in" }` as login does; the JWT carries `"demo": true`, which refresh keeps. Anything but a GET (or HEAD) with it is 403 `demo_reads_only`, whatever that viewer's roles on each library: visitors share the one person, so nothing one does is seen by the next. When the setting no longer names that person (removed, or they're no viewer now), every demo session's next request is 401 `token_revoked` and its refresh 401. 404 `not_found` while there's no demo. Rate limited: 10 requests/min per IP.

## Setup API

An install's first admin (`src/server/setup.py`), from the web app. No auth: it's for before anyone can log in. Open while the server has no user at all, then closed for good. The same as `lumiverb-server setup` on the command line.

- **GET /v1/setup** — Returns `{ "needed", "on_this_machine" }`: `needed` while there's no user; `on_this_machine` when this request may set it up (it comes from the machine the server runs on).
- **POST /v1/setup** — Body: `{ "email", "password", "account_name"? }`. Makes the first admin in the server's one account (the installer's, on Linux), or in a new account named `account_name` (default `Lumiverb`) when there's none. Returns 201 `{ "access_token", "token_type", "expires_in" }`, as login does. 403 `setup_elsewhere` unless the request comes from the machine itself, as nginx saw it (`api/client_address.py`: the right-most `X-Forwarded-For` entry, counted only on a connection from this machine), addressed to it as localhost (Host `localhost`, `127.0.0.1` or `[::1]`, and an `Origin`, when sent, one of those too). Every "on the machine itself" below means the same. 409 `already_set_up` once there's a user, and 409 `several_accounts` when there's more than one account and nobody to log in (`lumiverb user create` instead). 400 `invalid_email`, `password_too_short` (under 12 characters) or `password_too_long` (over 72 bytes). Two at once make one admin (an advisory lock).

## What a server answers from elsewhere

Every route, unless the env file's `LUMIVERB_EXPOSURE` says otherwise (`src/server/api/exposure.py`; a value it doesn't know stops the server). With `demo` (a demo server, `docs/demo-server.md`), a request from anywhere but the machine itself reaches only what a visitor's pages call: `GET /v1/setup`, `/v1/auth/demo` (GET and POST), `POST /v1/auth/refresh` and `/logout`, and GETs of `/v1/me`, `/v1/tenant/settings`, `/v1/views`, the libraries' list, health, detail, revision and directories, `/v1/query`, `/v1/assets/facets`, `/v1/similar`, a clip's detail, files, playback and stream, its faces and their crops, people, their faces, groups of faces and the dismissed, and a public project and its clips (`exposure.DEMO` lists each). Every other route, typed sign-in and a password's reset among them, is 404 `not_found`, as one that isn't there, before anything else is read; decided by the route the app would run. On the machine itself (an SSH tunnel to it too), every route, as ever.

## Users API

All routes under `/v1/users`; require tenant auth and **admin** role. A server admin (Roles) is another server admin's: for anyone else, an account admin signed in or any key, a new link, a change or a delete of one is 403 `server_admin_user`, and nothing is done.

- **GET /v1/users** — List all users for the current tenant. Returns list of `{ "user_id", "email", "role", "every_library", "server_admin", "created_at", "last_login_at" }` (`every_library`: false when they see only the libraries they're given a role on; `server_admin`: they're a server admin, theirs to change only for another; see Roles).
- **POST /v1/users** — Body: `{ "email", "role": "viewer", "password"?, "every_library"? }` (`every_library` true unless said). Without a password, an invite (`src/server/invites.py`): the user is made with a password nobody knows, and the 201 carries `invite_urls` and `invite_expires_at`: a one-time link good for 7 days for the admin to send them, at each address other people open Lumiverb at, the likeliest to open first. On a Mac once Settings › Network lets other devices in, that's its name (`.local`, for Apple devices) and then its IP address (Android and some Windows need it), over HTTPS; otherwise `APP_HOST` alone. They choose their password there (`POST /v1/auth/join`). With a password (a script's), the user can sign in at once and there's no link. 409 `email_conflict` when the email is taken, whatever its case: an address is one person's however it's typed, and signing in, a forgotten password and naming a server admin find it in any case (it's kept as first typed).
- **POST /v1/users/{user_id}/invite** — A new link for someone who hasn't signed in yet: `{ "invite_urls", "invite_expires_at" }`. Their older unused links stop working. 409 `already_joined` once they've signed in (they use Forgot password instead). A server admin's only by another server admin (403 `server_admin_user`): whoever followed the link would have the install, a first admin `lumiverb-server setup` made who hasn't signed in yet included.
- **PATCH /v1/users/{user_id}** — Body: `{ "role"?, "every_library"? }`, either or both. `every_library` takes effect on their next request (no new sign-in). Updates user role. Enforces last-admin invariant (cannot demote the last admin). A new role revokes the user's tokens (they sign in again). Returns updated user.
- **DELETE /v1/users/{user_id}** — Removes user; their tokens stop working, and their reset and invite links go with them. Enforces last-admin invariant and blocks self-deletion. A server admin only by another (403 `server_admin_user`), and never the last one who can sign in, one in an account not deleted (409 `last_server_admin`; the server admins are held while it's decided, so two deleting each other at once leave one). Returns 204.

## Current User

- **GET /v1/me** — Returns `{ user_id, email, role, server_admin, demo }` for the authenticated user. For JWT auth, looks up email from the users table; `server_admin` says whether they're the install's admin too (Roles); `demo`, whether it's a demo session, which reads only (`POST /v1/auth/demo`). For API key auth, `user_id` and `email` are null and `server_admin` false (a key is never one); only `role` is returned.
- **POST /v1/me/password** — Change your own password, signed in. Body: `{ "current_password", "new_password", "end_api_keys"?: bool }`. Only for a person signed in with a session: with an API key, 403 `signed_in_only` (whoever holds a key mustn't take the account); a demo session, 403 `demo_reads_only`. 400 `wrong_password` when `current_password` isn't theirs (a 400, not a 401: the session is good), 400 `password_length` for a new one not 12 to 72 characters. Like reset-password, it ends what the old password could have made (every session, the API keys they made, devices' included, their unused links), so while they have live keys of their own, a 409 `keys_end_with_password` names them first (Decisions the API requires). Returns 200 `{ "access_token", "token_type", "expires_in", "api_keys_revoked" }`: a new session for the caller, whose old one ended with the rest. Rate limited: 5 tries a minute by address; by person, only wrong current passwords, 5 in 15 minutes from one address and 25 from anywhere, so a session of theirs used to guess elsewhere doesn't keep them from changing it from their own (which ends that session); 429 past either.
- **POST /v1/me/failed-requests** — What your browser couldn't load at all, signed in: requests that got no answer (the connection dropped, so the server never saw them), which the web app keeps and sends once a request gets through (`src/ui/web/src/api/failedRequests.ts`). Body: `{ "failed": [{ "method", "path", "error", "at", "page" }] }`, 1 to 20: `method` one of GET, POST, PUT, PATCH, DELETE; `path` the API's (`/v1/...`) without its query; `error` the browser's own words ("Load failed", "Failed to fetch"); `at` when (ISO 8601); `page` where in the app (optional); `path`, `error` and `page` up to 200 characters, one line of printed text each (no control characters or line breaks: 422). Each is a line in the server's log, with who sent it and their browser (`User-Agent`), which Admin › Logs shows ("web: …'s browser couldn't reach the server for GET /v1/projects …"). 204. With an API key, 403 `signed_in_only`; a demo session, 403 `demo_reads_only`. Rate limited: 10 a minute by address and by person.

## API Keys

All routes under `/v1/keys` require tenant auth and **editor or admin** role.

- **GET /v1/keys** — List all non-revoked keys for the current tenant. Requires editor or admin. Never includes plaintext. Each is `{ "key_id", "label", "role", "last_used_at", "created_at", "ends_at" }`: `ends_at` is when upkeep ends it unless it's used before then (the account's `key_idle_days` after it was last used, or made if never), null while those are off or for a key they don't end (one nobody made: the scheduler's, or one the server admin's API made for the account). The account's last admin key is kept even past it.
- **POST /v1/keys** — Create a new key. Body: `{ label, role? }`. `role` is the caller's own when left out, and may be any role at or below it: 403 `role_escalation` above it, 400 `invalid_role` for one that isn't `admin`, `editor` or `viewer`. 400 `scheduler_label` for the label `scheduler`, in any case: it's the scheduler's own key's, and no other key looks like it. Returns `{ key_id, label, role, plaintext, created_at }`. The `plaintext` value is shown exactly once.
- **DELETE /v1/keys/{key_id}** — Revoke a key. Returns 204. Only a key at or below the caller's own role, as with creating one: an editor can't revoke an admin key (403 `role_escalation`). A key cannot revoke itself (409). The last admin key cannot be revoked (409 `last_admin_key`).

A device's key isn't listed here, and isn't revoked here (404): it's the Devices API's.

## Devices API

A device is a computer that scans the libraries it reads, not a person (ADR-018 decision 8; `routers/devices.py`). It has one key at a time, which scans those libraries and does nothing else (Roles). A library a device reads names it as its reader (`PUT /v1/libraries/{id}/reader`, ADR-018 phase 6). The web app's Settings › Devices registers and looks after them (the key shown once, with the commands to run on the device), and a library's settings choose its reader ("Who reads it"). Lumiverb's own device client is `lumiverb device run` (cursor-cli.md; `src/processing/device.py`): with the device's key as its API key, it checks in, scans and makes what needs the originals, as this server's scheduler does for its own libraries. All routes under `/v1/devices`; **account admins** only (403 otherwise).

- **GET /v1/devices** — `{ "devices": [{ "device_id", "name", "registered_at", "has_key", "key_last_used_at", "libraries" }] }`, by name: whether it has a key (none once ended, or once the person who made it lost their access: below), when its key was last used, and the ids of the libraries it reads (in the trash too).
- **POST /v1/devices** — Body: `{ "name" }` (1–100 characters, for people: "Robert's Mac Studio"; no control characters). Registers it and returns it with `key`, shown this once: the device sends it as `Authorization: Bearer <key>`. It reads no library until one names it.
- **PATCH /v1/devices/{device_id}** — Body: `{ "name" }`. Renames it.
- **POST /v1/devices/{device_id}/key** — A new key, returned as registering does; its old one stops at once (a lost or stolen computer).
- **DELETE /v1/devices/{device_id}/key** — Ends its key: it does nothing until it gets a new one. 204.
- **DELETE /v1/devices/{device_id}** — Removes it and ends its key. 409 `device_reads_libraries` (`details.libraries`: `library_id` and `name`) while a library names it: choose another reader for those first. 204.

404 for an unknown device. A device's key is the person's who made it (registered or gave it a new key) as any key they made is: a new password of theirs (a reset), or their removal, ends it, and the device stays, for an admin to give it a new key.

## AI machines API

ADR-016 phase 3. The account's AI runs on **machines**: GPU boxes, each an OpenAI-compatible endpoint (such as Ollama) with an optional key, the **jobs** it does and how many requests it takes at once (`at_once`). Each job has **one model** for the account, and a machine does a job only if it offers that model, so an artifact is the same model's whatever machine made it (which machine isn't tracked, like the encoder). Machines live on the control plane (`ai_machines`); the one place they live. Web: Settings → AI (Robert's call, Oct 8: machines, each with jobs).

Jobs (`src/shared/ai_jobs.py`):
- `vision`, "Descriptions & text": descriptions, OCR and scene descriptions, on OpenAI-compatible chat endpoints (Ollama). Its model is the tenant's `vision_model_id`.
- `transcripts`, "Transcripts": Whisper. Its model is the tenant's `transcript_model_id`, `small` until changed (what every transcript before it recorded). A machine doing it serves OpenAI's `GET /models` and `POST /audio/transcriptions` with `response_format=verbose_json` (segments with their times): speaches, or LocalAI. A whisper.cpp server lists no models, so it can't be checked: not supported; Ollama doesn't do Whisper. The worker finds the speech in each clip itself, with faster-whisper's VAD and the transcript producer's `vad_min_silence_ms`, sends only the speech (asking the server not to skip silences of its own, `vad_filter=false`, and to time its segments, `without_timestamps=false`), and maps the times it gets back onto the clip. So the settings a transcript's lineage records (the model and the silences skipped) are the ones it was made with, whichever machine heard it. How a server decodes isn't tracked, like the encoder: current speaches also skips silences over 160 ms within what it's sent and decodes pieces of at most 30 s at temperature 0, so its cues and an occasional word can differ from the built-in's.

**The built-in machine.** Every tenant has one (`built_in: true`, listed first): the scheduler's own computer, with no URL or key, doing the jobs the scheduler does itself (Whisper: transcripts), one at a time until changed. Every account gets it (control migration `b6591b39778f`; new tenants at creation), so transcripts run with nothing set up. It can be renamed, given another `at_once`, turned off, or have transcripts taken away; not removed, given a URL or key, or given a job it can't do (409 `built_in_machine`). The server can't reach it: it offers the models faster-whisper knows, and only the worker says whether it's online (faster-whisper installed, and the model one it knows). The worker that runs it is whichever runs the transcribe step (the server's).

**One name per model.** faster-whisper calls a model by a short name (`small`) or by the Hugging Face repo it loads it from (`Systran/faster-whisper-small`), which is what speaches lists. They're one model (`src/shared/whisper_models.py`): machines' models, Connect's answer and a job's model use the short name; the worker asks each server for it by the name it lists. Any other name is a model of its own.

- **GET /v1/ai** — Signed in. Returns `{ "machines": [{ "machine_id", "name", "api_url", "has_key", "key_readable", "fingerprint", "jobs", "at_once", "enabled", "built_in", "shares_gpu", "status": { "online", "error", "models", "checked_at" } | null }], "jobs": [{ "job", "label", "model", "machines", "offering", "choices", "built_in", "fixed" }] }`, the built-in machine first, then in the order added. Keys are never returned. A machine's address is an account admin's, as it can name a host on the server's own network: `api_url` is null for anyone else (`""` for the built-in machine, to an admin), who still reads each machine's name, jobs and status, the address in its status's `error` said as the machine's name (`"GPU box didn't answer (ConnectionError)"`); the same in every answer that says a machine's address (`src/server/repository/ai_machines.py` `address_for`, `unaddressed`): `GET /v1/tenant/context`, `GET /v1/ai/jobs/{job}`, and what `GET /v1/producers` and its queue and failures say of an AI job's machines, there as "the AI machine". A key is kept sealed with the install's own key (`LUMIVERB_SECRETS_KEY` in its env file: `src/server/sealing.py`), so a database dump or backup alone reads none; `key_readable` false for one this install can't read (sealed by another install's key: a backup restored elsewhere without its env file), to be entered again. Saving a key on an install without its key is 503 `secrets_key_missing`, and nothing is kept unsealed. `fingerprint` is the certificate an https machine was added with, its SHA-256 as `openssl x509 -fingerprint -sha256` shows it (32 pairs of hex, upper case, colon-separated; `""` for none): every request Lumiverb makes to it takes that certificate and no other, whoever signed it and whatever names it has, compared after the TLS handshake and before anything is sent (`src/shared/ai_requests.py`); an https machine without one is checked as any https site is (a public authority's), and an http machine has none. Lumiverb's AI worker serves HTTPS with a certificate of its own and prints its fingerprint. `status` is the latest check (the worker's, or Connect's when the machine was saved); its `error` says why it's offline in Lumiverb's words (it refused the key, has no such model, answered 500, answered with a redirect, which Lumiverb doesn't follow, …), never what the machine answered: everyone signed in reads it, so the machine's own words are the log's (Admin › Logs, the server admin's), as Connect's are; `jobs[].machines` counts the enabled machines doing the job, `offering` those that offered its model when last checked, `choices` the models they offer (the built-in's: what the scheduler itself runs for the job, faster-whisper's sizes or CLIP's), `built_in` whether the built-in machine can do it, and `fixed` why its model can't be changed (null when it can). The jobs: `vision` (descriptions and text), `clip` (photos' CLIP vectors, ADR-022: the built-in machine as always, and Lumiverb's AI workers, `lumiverb-server ai-worker`, whose `/v1/models` lists `ViT-B-32` and `buffalo_l`; its model `ViT-B-32` is fixed, one model for a library's vectors), `faces` (faces in photos and videos' frames, the same machines; its model `buffalo_l` fixed) and `transcripts`.
- **POST /v1/ai/connect** — Admins. Body: `{ "api_url", "api_key"?, "fingerprint"?, "machine_id"? }` (`api_key` left out: that machine's saved key, when `api_url` is its URL or that URL over `https://`; `""`: none. `fingerprint` left out: that machine's certificate, for an https `api_url`; `""`: none). Asks `GET {api_url}/models`, by that certificate alone when there's a fingerprint: one that isn't it is 502 `machine_unreachable` "Its certificate isn't the one it was added with." (nothing was sent to it), and an https machine without a fingerprint whose certificate no trusted authority signed is 502 "Its certificate isn't signed by an authority this server trusts. If it's Lumiverb's AI worker, give the certificate fingerprint it prints when it starts." 422 `invalid_fingerprint` for a fingerprint that isn't a SHA-256 (64 hex digits, with or without colons, either case), or one with an http `api_url`. Returns `{ "models": [ids by their one names, sorted] }`. 502 `machine_unreachable` when it can't say: "Couldn't reach the AI machine.", and for a server admin what went wrong there too (its URL, and what it answered: `/models answered HTTP 401 (…its error's message)`, `ConnectionError: Connection refused`), which is the log's; anyone else gets the sentence alone, so Connect can't map the network around the server. Adding or changing a machine says it the same way. 422 `invalid_url` for a URL with a query, fragment or user info (a trailing `/` or `.` is trimmed); a host resolving to a link-local or cloud metadata address gets 502 "That address isn't allowed." (loopback and LAN are fine). The same rule holds at every request Lumiverb makes to a machine, its work's too (`src/shared/ai_requests.py`): the name is looked up again before each, and the address each connection reached is checked before anything is sent on it; and no request follows a redirect (a machine answering with one is at fault, as one that's unreachable).
- **POST /v1/ai/machines** — Admins. Body: `{ "name", "api_url", "api_key"?, "fingerprint"?, "jobs": [...], "at_once": 1–32 (default 2), "enabled"?, "shares_gpu"? }`. `fingerprint`: its certificate's, an https machine's only (as Connect; kept in the one form `GET /v1/ai` shows; 422 `invalid_fingerprint` otherwise). `shares_gpu`: it runs on the server the scheduler decodes video on; while video is decoded there it takes fewer requests, down to none (video work comes first; the built-in machine always shares it). Only where renders decode on the GPU (Vulkan, cuda): a Mac's decode on its media engine and the CPU's take nothing from it (`Machine.gpu_decodes_here`). PATCH takes it too. The machine is asked for its models: 502 `machine_unreachable` when it can't say, 409 `model_not_offered` (`details`: `job`, `model`, `models`) when it lacks a job's model, 409 `name_taken`; 422 for an unknown job, an empty name or URL, or `at_once` out of range. What it offered is its status. Returns 201 with the settings.
- **PATCH /v1/ai/machines/{id}** — Admins. Any of the fields above (the built-in machine: `name`, `jobs` it can do, `at_once`, `enabled`; anything else is 409 `built_in_machine`, and it's never asked: the worker checks it); `api_key` left out keeps the saved one. When its URL, key or fingerprint changes, it's given a job it hadn't, or it's turned back on, it's asked again (502, 409 as above); a rename or a new limit isn't, so a machine that's asleep can still be edited. A new URL without `api_key` drops the saved key (it never goes to another host), unless it's the same URL over `https://` (an AI worker switched to HTTPS: the same machine). `fingerprint` left out keeps the saved one (a new https address of the same machine keeps its certificate), dropped when the URL is http now; `""` none. Turning off the last machine doing a job, or taking the job from it, never asks: the job's work waits, and `GET /v1/producers` says why (`waiting`, and `waits`' `ai_machines`). Returns the settings; 404 for another tenant's or an unknown machine.
- **DELETE /v1/ai/machines/{id}** — Admins. The last machine doing a job too, without asking (its work waits); 409 `built_in_machine` for the built-in one (turn it off instead). Returns the settings; 404 for another tenant's or an unknown machine.
- **POST /v1/ai/machines/{id}/try** — Admins. Body: `{ "model"? }` (`""` or left out: descriptions & text's model). Tries a machine before it gets the work: it's sent what descriptions & text's work sends, with this account's settings, one request for each producer's (those alike share one), all at once, each waiting 45 seconds at most: a picture Lumiverb draws itself, nobody's photo (a red house on a hill and a sign reading OPEN 9 TO 5, `src/server/ai_sample.py`), and a video's three scenes as text. Returns `{ "machine", "model", "sent", "tries": [{ "titles", "answer", "result", "problem", "finish", "tokens", "limit", "seconds" }] }`: the producers each request stands for, its reply (its first 4,000 characters), what the work would save from it (the description and tags, or the text read; null when nothing could be), why it wouldn't do in a sentence (`""` when it would: it ran out of room, its `finish` `length`, a model that thinks first having spent its `limit` thinking; an answer that isn't the description and tags asked for; nothing; or the request failed: "It answered HTTP 400.", the machine's own words added for a server admin, as Connect's are; "It answered with a redirect, which Lumiverb doesn't follow."; "Its certificate isn't the one it was added with. Nothing was sent to it."; an https one's certificate no trusted authority signed, as Connect says it), the tokens it says it used (`{ "prompt", "answer" }`, null when it doesn't say) and how long it took. 409 `no_model` with no model to try; 409 `built_in_machine` for the built-in one (it does transcripts); 502 for an address the server mayn't ask (as Connect). 404 for another tenant's or an unknown machine. The CLI's `lumiverb ai machines test NAME [--model M]`.
- **PUT /v1/ai/jobs/{job}** — Admins. Body: `{ "model" }` (a faster-whisper repo is kept by its short name); `""` turns the job off. A job whose model is fixed (`clip`, `faces`) takes only its model: another is 409 `model_fixed` (`details`: `job`, `model`, the one it has). Every enabled machine doing the job is asked (what it says is its status; the built-in one isn't asked: it offers faster-whisper's models): 409 `model_not_offered` (`details.machines`: `machine_id`, `name`, `models`, `error`) when none offers the model. Changing the model leaves what the old one made made another way than now, and asks what becomes of it (ADR-018 decision 6): 409 `redo_on_change` (see Decisions) names how many clips; resend with `"redo": true` to remake them too, after everything else (the job's producers' redo resumed if an admin had stopped it), or `"redo": false` for new files only (they stay as they are, the producers' redo stopped by this person until someone remakes them: `POST /v1/producers/{artifact}/resume` with scope `redo`). Turning a job off, or on with the same settings (a default model), asks nothing. 404 for an unknown job. Returns the settings.
- **GET /v1/ai/jobs/{job}** — Editors and admins (the scheduler's key is an admin's). Returns `{ "job", "model", "machines": [{ "machine_id", "name", "api_url", "api_key", "fingerprint", "at_once", "built_in", "shares_gpu" }] }`: the enabled machines doing it, in order (`built_in`: the worker does it itself; `fingerprint`: the certificate an https machine's requests take alone, `""` for any trusted one). `api_url` is an account admin's, null for an editor (`GET /v1/ai`). `api_key` is the machine's key for the scheduler's own key alone (it sends the machine work): known by a mark only it gets (`api_keys.scheduler`, set where the scheduler makes its key at each start), never by its label `scheduler` (which no other key may have) or by no person having made it, `""` for anyone else, an account admin too: a key is write-only (Settings → AI says only whether one is saved, `has_key`). 403 for a viewer.
- **POST /v1/ai/machines/{id}/status** — Admins (the scheduler). Body: `{ "online", "error"?, "models"? }`: its check of the machine. Returns 204. The worker checks each machine before a job's work and sends requests only to online ones offering the model, each up to its `at_once`, least busy for its size first; a machine that fails a request for its own reasons (unreachable, refused, the model gone or not loading, out of memory, a server error or one that broke off, a redirect, at an address that isn't allowed, not speaking the API: no timed segments, or times that can't be seconds) is skipped (the item goes to another, trying each machine once) and checked again a minute later. Only with no machine left, or the job off, does the job's work wait, and no clip is charged a failure; the worker leaves those clips out of a cycle's work. An item the machine couldn't make sense of (a bad answer; audio a server or Whisper refused; for transcripts, a machine that didn't finish within ten minutes and four times the speech, or Whisper dying without a word) is charged only if the machine that served it is still fine when checked again; a clip one transcription machine refuses is tried on the others first. Transcripts go to each machine up to its `at_once`, while the next clips' speech is found meanwhile (the worker's old `transcribe_concurrency` is gone). Settings → AI shows each machine's status, offline ones in red, with a red dot on AI in the Settings menu.
- `GET /v1/tenant/context` and `PATCH /v1/admin/tenants/{id}` speak for the first enabled machine doing vision (`vision_api_url`, `vision_api_key` (always `""` back: write-only), `vision_model_id`), for clients that know one endpoint (the CLI's `admin vision-test`). The admin PATCH makes or moves that machine; an empty URL removes it.

## System health API

- **GET /v1/system/health** — Tenant admin (403 for editors and viewers; 401 signed out or on a public page); the disk, backups and own plug-ins rows, the install's, only for a server admin (Roles). The Admin page's overview, refreshed every 10 seconds: `{ "state", "rows": [{ "key", "title", "state", "reason", "link", "checked_at" }], "libraries": [{ "library_id", "name", "reachable", "seen_at" }], "version" }`. `version` is the Lumiverb running (`src/server/version.py`): a Homebrew keg's version (`0.1.6`), what `git describe` says of a checkout (`v0.1.6-3-g1a2b3c4`), else `unknown`; the package's own version isn't moved at a release. `state` is `green`, `yellow` or `red`; the top-level one is the worst row's. `reason` is one line; `link` is the web app's page where it's fixed (null when there's none). Rows, in order (thresholds in `src/server/system_health.py`):
- **GET /v1/system/logs** — Server admin (403 `server_admin_required`, Roles); on a server with more than one account only from the machine itself (403 `logs_elsewhere`: the log names every account's files). The service's log (Admin › Logs, `src/server/service_log.py`), newest first: `{ "source", "where", "unavailable", "entries": [{ "id", "part", "level", "text", "at" }], "next_cursor" }`. `source` is `file` (a Mac's: launchd's file, which `lumiverb-server run` rotates and names to the API in `LUMIVERB_LOG_FILE`), `journal` (Linux: journalctl for Lumiverb's units, once whoever runs the server adds the service user to `systemd-journal`, which reads the whole system journal; until then `unavailable` says how and what it opens) or null (`unavailable` says why, e.g. started from a terminal). An entry is a record and the lines continuing it (a traceback); `part` is `api`, `scheduler`, `postgres`, `nginx`, `upkeep` or `lumiverb-server` (a Mac's service itself), or `quickwit` in an older install's lines (ADR-019); `level` is `error`, `warning` or `info`, read from the text; `at` is the journal's time (a file's lines carry their own). Query: `part`, `problems=true` (warnings and errors), `q` (text, any case), `limit` (1–500, default 200), `after` (a `next_cursor`; it survives the file's rotation; 400 `bad_cursor` for another's). A page looks through at most 8 MB of the file (20,000 journal entries), so a search that finds little still answers: an empty page with a `next_cursor` goes on from there.
- **GET /v1/system/network** — Signed in. Whether other devices on the network may use a Mac's Lumiverb (Settings › Network): `{ "available", "other_devices", "https", "plain_http", "addresses", "https_addresses", "https_seen", "certificate", "http_port", "https_port" }`. `available` is true where Lumiverb runs the web server (`lumiverb-server run`'s own nginx, whose config includes the lines run writes); a Linux install's nginx is deploy-web.sh's, so false there. A new install is this machine only. `http_port` and `https_port` are where it listens, the web and the API together on each (null where it isn't available): 6464 and 6465 unless the env file (`WEB_PORT`, `WEB_TLS_PORT`) or an admin (PUT below) says otherwise. With `other_devices`, other devices reach it over plain HTTP on `http_port` (`addresses`: `http://<name>.local:6464`, then its address on the network), with nothing to set up on them. `https`: an admin added HTTPS, on `https_port` (`https_addresses`), beside plain HTTP while `plain_http`; with `plain_http` false, another device that comes over plain HTTP is sent to HTTPS (301), but for `/lumiverb-ca.crt`. This machine keeps plain HTTP on `http_port` whatever is chosen. `https_seen` is `{ "at", "address" }`: the first device seen using HTTPS since HTTPS was last turned on or off or the certificate changed (`api/https_seen.py`: a request nginx passed on over HTTPS from another device), else null. `certificate` is what HTTPS serves (`src/server/lifecycle/tls.py`), null while `https` is off and until run has made one: `{ "source": "lumiverb" | "yours", "names", "expires_at", "ca_url", "ca_addresses", "ca_fingerprint", "names_left_out" }`. `lumiverb`: issued by the install's own authority for this machine's names (its `.local` name, its name, its address, localhost), again when they change and a month before its end; each device trusts the authority once, fetching it at `ca_addresses` (plain HTTP: it can't trust HTTPS yet; `ca_url` on this machine) and comparing its SHA-256 `ca_fingerprint`. The authority vouches for nothing else: a new one carries critical name constraints, local names (`.local`, `localhost`, `home.arpa`, `.lan`, `.internal`) and this machine's names when it's made, and local addresses (loopback, the private ranges, link-local); one made before it had them is kept, as every device would have to trust a new one again. `names_left_out`: this machine's names it can't vouch for (renamed since it was made), left out of the certificate, so other devices can't use them over HTTPS (empty otherwise). `yours`: an admin's own (below), while it can be served.
- **PUT /v1/system/network** — Server admin (403 `server_admin_required`, Roles), on the machine itself (as nginx saw the request, `api/client_address.py`; 403 `network_elsewhere` otherwise). Body: `{ "other_devices"?, "https"?, "plain_http"?, "http_port"?, "https_port"? }` (booleans, then ports); each left out stays as it is. A port nginx can't listen on is refused, saying why (422 `port_not_usable`: not 1–65535, the same for both, the install's API or database port, or one something else on the machine is using; turning on `https` checks its port the same way); run moves nginx there, and back to the port before if nginx doesn't start listening after all. The page on this machine moves with `http_port`. `plain_http` is turned off only once `https_seen` (409 `https_not_seen` until a device has used HTTPS: turning on `https` in the same request starts it afresh); `https` off turns `plain_http` back on. Writes the choice to `DATA_DIR/network.json`; run applies it within a few seconds (nginx's lines rewritten, nginx restarted). Returns the same shape as GET. 409 `network_not_here` where `available` is false.
- **PUT /v1/system/network/certificate** — Server admin, on the machine itself (as PUT above). An admin's own certificate, for an address other devices already trust (public hosting): `{ "certificate", "key" }`, PEM (the certificate first, then its chain; the key RSA or ECDSA, without a passphrase). Checked before it's kept: 422 `certificate_not_usable`, the message saying why (not PEM, a passphrase, not the certificate's key, ended or not started, no subject alternative names). Served instead of Lumiverb's own within a few seconds (nginx restarted), and only while it can be (once it ends, Lumiverb's own again, and GET says so). Returns the same shape as GET.
- **DELETE /v1/system/network/certificate** — Server admin, on the machine itself: back to Lumiverb's own. Returns the same shape as GET.
- **GET /v1/system/backups** — Server admin (403 `server_admin_required`, Roles). The databases' backups (Settings › Backups, `src/server/backups.py`): every database, the control plane's and each account's, as pg_dump archives, one folder a backup (`lumiverb-<local time>-<kind>`, with `manifest.json`). Previews, the search index and models aren't in them: they're made again. `{ "folder", "folder_write_error", "default_folder", "changeable_here", "running": { "kind", "started_at", "done", "of" } | null, "last_error", "last_failed_at", "next_at", "backups": [{ "name", "made_at", "kind", "bytes", "accounts", "restore": [command, …] }] }`, newest first. `kind`: `nightly` (the 5-minute upkeep makes one when none was made since the latest 03:00 here: a Mac asleep then makes it on waking; one that failed is tried again an hour later), `now` (Back up now, `lumiverb-server backup`), `before-upgrade` (a Mac's service, before migrations it hasn't run) or `before-restore`. `next_at` is when the nightly one is next made (now or past: within minutes). `restore` is the commands that put it back, in order, run on that machine: on a Mac `brew services stop lumiverb`, `lumiverb-server restore --env <env file> <folder>`, `brew services start lumiverb`; on Linux the systemd units and `/etc/lumiverb/env`. Kept: every one from the last 7 days, the newest of each of the 4 latest weeks with one, the newest 3 before an upgrade and 3 before a restore, and always the newest; only folders it made are removed.
- **POST /v1/system/backups** — Server admin. Starts one now, in the background; 202 with the same shape as GET (`running` set). 409 `backup_running` while one is being made (one at a time per install).
- **PUT /v1/system/backups/folder** — Server admin, on the machine itself (403 `backups_elsewhere` otherwise). Body: `{ "folder": "/Volumes/Backup/Lumiverb" | null, "make_folder": bool }` (null: back to `DATA_DIR/backups`). Backups go there from now on; those made already stay where they are. A folder that isn't there: a 409 `make_folder` first (Decisions the API requires). 409 `data_folder` for one in `DATA_DIR` with a name Lumiverb keeps there but `backups` itself (`src/server/data_folder.py`: `tmp`, emptied at every start, `models`, `plugins` and the like), there yet or not and whatever its case, refused before a 409 `make_folder` would ask, with the same message as the previews' (a name of its own there is fine). 400 `folder_not_usable` when it isn't a full path to a folder Lumiverb can write, or can't be made (the message says which). Written to `DATA_DIR/backups.json`. On Linux the API may write only under `DATA_DIR` (its unit's `ProtectSystem=strict`).
- **GET /v1/system/storage** — Server admin (403 `server_admin_required`, Roles). Where the previews are (Settings › Storage): every stored artifact (proxies, thumbnails, video previews, analysis proxies, scene frames, face crops, playback cuts), in `DATA_DIR` until an admin moves them (`DATA_DIR/storage.json`, `src/shared/previews_location.py`); the database, the search index, caches and the AI models (search, faces, transcripts) stay in `DATA_DIR` (in `DATA_DIR/models`: CLIP's and Whisper's under `huggingface`, faces' under `insightface`, a copy in `~/.insightface` from before brought in once; Ollama keeps its own models). `{ "previews", "data", "previews_available", "previews_write_error", "previews_free", "previews_total", "data_free", "data_total", "same_disk", "moving": { "library_id", "library_name", "from_folder", "to_folder", "done_files", "total_files", "done_bytes", "total_bytes", "running", "error", "started_at" } | null, "changeable_here", "libraries": [{ "library_id", "name", "folder", "available", "write_error" }] }`. `previews_write_error` and `write_error` say why Lumiverb can't write to a folder whose drive is there, null when it can (tested as the disk row does); `folder_write_error` the same for the backups folder (null for the default one before the first backup makes it). `moving.library_id` is set when it's one library's move (another account's is said as the server's); `libraries` are the account's libraries with a folder of their own. `previews_available` is false when a chosen folder's marker (`.lumiverb-previews`) isn't there: its drive is unplugged, and nothing is written to it (its empty mount point is on the system disk).
- **PUT /v1/system/storage/previews** — Server admin, on the machine itself (403 `storage_elsewhere` otherwise). Body: `{ "folder": "/Volumes/Media/Lumiverb previews" | null, "move": bool, "make_folder": bool }` (null: back to `DATA_DIR`). A folder that isn't there: a 409 `make_folder` first. Without `"move": true`, a 409 `move_previews` says what moves, `details: { "from", "to", "files", "bytes", "free" }`, for the user to confirm (with nothing to move, none: 202 and they're there at once); with it, 202 and the move runs in the background (`src/server/storage/move.py`): new files go to the new folder at once, a file not moved yet is read where it is, and a delete removes it from both. Each file is renamed (the same disk) or copied and linked in, never over one written there meanwhile; playback cuts aren't moved (made again). 400 `folder_not_usable` when the folder isn't a full path to a folder Lumiverb can write, is where they are, is inside them, or lacks room for them (5% and 1 GB to spare). What's in a previews folder is moved, swept and deleted, so a folder chosen is one Lumiverb can trust as its own: 409 `originals_folder` for a library's folder this server reads (in the caller's account), one inside it or one holding it; 409 `data_folder` for one in `DATA_DIR`'s own folders (one with a name Lumiverb keeps there, `src/server/data_folder.py`: its models, plug-ins, backups, caches, database, uploads and the like, there yet or not and whatever its case, refused before a 409 `make_folder` would ask; or one there with anything but previews in it; a new folder of a name of its own there is fine) or one holding `DATA_DIR`; 422 `folder_not_owned` for one the service's user doesn't own (each message says which and why). Nothing in a previews folder is followed through a symbolic link: a key whose path goes through one is refused when read or written (a 500, logged) and passed by when listed, moved, swept or deleted (`src/server/storage/local.py` `through_a_link`). 409 `move_running` during a move. On Linux the API may write only under `DATA_DIR`.
- **POST /v1/system/storage/move** — Server admin. Try again: a move that stopped (`moving.error`: the new drive full or unplugged, the old one gone) goes on now; 202. 409 `not_moving` when none is under way. The every-account upkeep also goes on with one that stopped, 15 minutes after its error, and with one the API restarted in the middle of.

- **GET /v1/libraries/{id}/previews** — Tenant admin. Where the library's previews are: the server's folder, or one of its own (a big video library on a drive of its own). `{ "library_id", "folder", "own", "server_folder", "available", "write_error", "free", "total", "same_drive_as_originals", "moving": { … as above } | null, "changeable_here" }`. `same_drive_as_originals` (null when its originals aren't reachable here, or don't answer within 2 seconds: they're probed as the scheduler probes a root, in a thread, since a network share whose server sleeps can block a stat for minutes): unplugging that drive takes its previews too, and the library can't be browsed. 404 for a library not in the account.
- **PUT /v1/libraries/{id}/previews** — Tenant admin, on the machine itself (403 `storage_elsewhere`). Body: `{ "folder": "/Volumes/Video/Lumiverb" | null, "move": bool, "make_folder": bool }` (null: back to the server's folder). As the server's move: a 409 `make_folder` for a folder that isn't there, a 409 `move_previews` (details also `same_drive_as_originals`, said in the message; none when nothing moves and it isn't the originals' drive), then 202 and the move in the background, of that library's files alone. The server's own moves leave a library with a folder of its own where it is. 400 `folder_not_usable`, 409 `originals_folder`, 409 `data_folder` and 422 `folder_not_owned` as there, 409 `move_running` (one move at a time, whichever).

During a move, cleanup (`/v1/upkeep/cleanup`, `remove-orphan-folders`) and the repair of missing files wait: files are in two places at once. Cleanup visits each library's own folder too. A library walk never goes into `DATA_DIR` or any previews folder (the server's, a library's), even inside a library's folder. The disk row is red when a library's own folder isn't there.
  - `website`: green when the database answers a query; red when it doesn't; yellow in maintenance mode.
  - `processing`: from the scheduler's status (`GET /v1/producers/queue`). Red when it hasn't written for 30 seconds or never has, or its `state` is `paused` (every switch is); yellow when `partly` (the reason names the paused switches), clips failed in the last 24 hours, or its status can't be read; green ("Running.") otherwise.
  - `ai`: over the jobs that have a model and the enabled machines doing them. Red when a job has work and no machine can do it (the scheduler's `eta.not_counted`, `no_machine`); yellow when a machine is offline, wasn't checked in 10 minutes or ever (the scheduler checks each every minute), or a job has no machine; green otherwise.
  - `search`: yellow when 100 or more clips in sight have no search row written yet (the upkeep sweep, every 5 minutes, writes them: search can miss them meanwhile); green otherwise. Search is in the account's database (ADR-019): there's no service to be down. The count is kept for a minute per API worker.
  - `storage`: from the scheduler's looks at each library's storage (`storage` in its status), every 30 seconds whatever is paused (pausing Scans changes nothing here), except while all processing is paused: nothing touches the drives then. Yellow when the scheduler hasn't written in 30 seconds, or while all processing is paused ("All processing paused, so storage isn't checked. Media last seen 2 hours ago.": what's known is stale, not broken); red when its latest look since it started found one unreachable ("Can't reach Media. Last seen 2 hours ago."); yellow when one hasn't been looked at since the scheduler started ("Not checked yet. Media last seen 45 minutes ago." or "never seen"); green when the latest look reached every library. Times are how long ago, never a clock time. `libraries[].reachable` says the same per library: true, false, or null when it isn't known now (not looked at since a restart, all processing paused, or the scheduler isn't running); `seen_at` is when it was last seen reachable (null: never).
  - `disk`: free space where `DATA_DIR` is, and the previews' disk when they're on another (Settings › Storage: "Data: … Previews: …", the worse of the two, linking there). Red under 5% free, yellow under 15%; red when the previews' folder isn't there (its drive unplugged), or Lumiverb can't write to it or a library's own any more ("Lumiverb can't write to …: it's read-only.", no permission, the drive is full, it isn't answering). During a move it says how far it is. A folder's write is tested again at most every 5 minutes, 30 seconds after a failure, in a thread given 2 seconds (`src/server/write_check.py`).
  - `backups`: the databases' backups (below). Red with none in 2 days (or none at all and the last try failed), or when Lumiverb can't write to the backups folder any more ("… The next backup can't be made."); yellow when the last try failed after the newest one ("The last backup failed: … The one before is 20 hours old."), or none is made yet ("the first is made within minutes"); green otherwise ("Last backup 5 hours ago (12.0 MB)."), saying when one is being made.
  - `own_plugins`: Lumiverb's own plug-ins (Plug-ins API), a server admin's too. Red when one couldn't be installed, saying why ("Place names (GeoNames) couldn't be installed: There's no DATA_DIR in the env file, …. It's tried again at the next start."); yellow when an older one waits for the next start to be updated; green otherwise ("Installed: Place names (GeoNames) 1.", or uninstalled by the server admin), linking to Settings › Plug-ins.
  A row that can't be checked is yellow and says why; the others still answer. Counts are kept for a minute per API worker.

## Setting up (the first-run wizard)

- **GET /v1/tenant/setup** — Tenant admin. How far the account's admins got through setting it up (the web app's `/welcome`, opened after the first admin is made): `{ "steps": ["storage", "network", "find", "ai", "people", "library"], "done": [...], "dismissed", "finished" }`. Each step is a Settings section (where previews live with the backups folder, who can open it, face levels and place guesses, AI machines, invites, the first library); the wizard only remembers which ones were gone through, in `system_metadata` (`setup.wizard`), so it can be left and picked up again. `steps` are the caller's: the first two are the install's, so only a server admin's (Roles), and `finished` is every one of theirs done. The Admin page offers it until it's `finished` or `dismissed`.
- **PUT /v1/tenant/setup** — Tenant admin. Body: `{ "done": [step, …] }` (the whole list, kept in step order) and/or `{ "dismissed": bool }`; fields left out stay. 422 `unknown_step` (details: the steps) for a step there isn't.

## Tenant Maintenance API

All routes under `/v1/tenant/maintenance` require tenant auth and **tenant admin** role (`require_tenant_admin`). Maintenance mode is stored as a JSON value in `system_metadata` under the key `maintenance_mode`. Used to pause operations during upgrades.

- **GET /v1/tenant/maintenance/status** — Returns `{ active, message, started_at }`.
- **POST /v1/tenant/maintenance/start** — Body: `{ "message": "..." }`. Enables maintenance mode. Returns `{ active: true, message, started_at }`.
- **POST /v1/tenant/maintenance/end** — No body. Clears maintenance mode. Returns `{ active: false }`.

## Tenant Upgrade API

All routes under `/v1/tenant/upgrade` require tenant auth and **tenant admin** role (`require_tenant_admin`). These endpoints run idempotent, tenant-scoped upgrade steps (schema migrations and/or data backfills) in a fixed order.

- **GET /v1/tenant/upgrade/status** — Returns `{ has_work, steps_total, done_steps, completed_steps, pending_steps, skipped_steps, failed_steps, next_pending_step_id, remaining_pending_step_ids, steps }` where each step includes `step_id`, `version`, `display_name`, and `status` (`pending|skipped|completed|failed`).
- **POST /v1/tenant/upgrade/execute** — Body: `{ "max_steps": 1, "step_id": null, "force": false }`.
  - With `step_id=null`, runs up to `max_steps` pending steps in order.
  - With `step_id` set, runs only that step if it is pending.
  - Without `force`, the server refuses to run a targeted step when any preceding step is still `pending` or `failed`.
  - Returns `{ ran_steps, steps_completed_now, has_work_after, remaining_pending_step_ids, total_steps, done_steps, completed_steps, failed_steps }`.

## Upkeep API

All under `/v1/upkeep`. Periodic server-side maintenance tasks. Search sync uses timestamp-based tracking (`search_synced_at` and `transcript_synced_at` on assets) instead of a queue table.

**Who and what.** Upkeep skips the tenant middleware and resolves the key itself (API keys, not JWTs). An account admin's API key acts on that account. The install's own key (`ADMIN_KEY`, in its env file) acts on every account, and must say so: `?tenants=all`. Nothing acts on every account from a missing argument (Robert). Every route: 401 with no key, a key that isn't live, or a revoked one; 403 for a viewer's or editor's key, or an account key that sends `tenants=all`; 400 for the admin key without `tenants=all`; 422 for `tenants` other than `all`. The systemd timers send the admin key with `tenants=all` (`lumiverb-upkeep.timer`: `POST /v1/upkeep?tenants=all` every 5 minutes; `lumiverb-upkeep-daily.timer`: `POST /v1/upkeep/cleanup?tenants=all&dry_run=false` at 03:00).

Every-account runs happen inside the request, on purpose: the callers are the timers (oneshot units, whose exit status and journal are the run's result) and the operator by hand, who needs the result (recreating the indexes must be followed by a search sync). The handlers run on FastAPI's thread pool, so the API keeps answering, and each call's work is bounded (1,000 clips and 1,000 scenes per account per search sync; 500 trashed clips per purge). The scheduler hands out per-clip jobs per account; it has no every-account periodic task to give these to.

- **POST /v1/upkeep** — Runs all periodic upkeep tasks: search sync, face propagation (auto-assign untagged faces to known people by centroid proximity), deleting for good what has been in the trash longer than the account's trash days (clips a person trashed, 500 a run; libraries by `trashed_at`; projects, whoever owns them; never archived clips; trashing already asked about projects, so the purge doesn't), repairing artifact files reported missing (`GET /v1/assets/{id}/artifacts/{type}` found the key set and the file gone: each is checked again and, if still gone, its key cleared so the producer makes it again; a missing thumbnail is made again from the clip's preview, which stays, as ingest made it (`remade`), and only when the preview is gone too are both keys cleared, since one producer, a scan, makes both), deleting empty dismissed people (none of their faces left, and never one a person named), computing the face clusters again when faces changed since they were (`GET /v1/faces/clusters` only reads them), ending keys unused past the account's `key_idle_days` (`idle_keys.ended`; not paused with Upkeep: a pause is about the machine's work, this is who gets in), deleting scans expired a day after their last call (a client killed mid-scan never drops its own; `expired_scans.deleted`; not paused with Upkeep: it's the scan protocol's own housekeeping, as starting a scan deletes them too), and, with `tenants=all`, revoked token cleanup (purges entries older than 8 days) the nightly backup when it's due, and a previews move that stopped goes on. Returns `{ "search_sync": { "synced", "failed", "transcripts_synced", "transcripts_failed", "facts_synced" }, "face_propagate": { "assigned", "scanned", "paused", "paused_tenants" }, "trash_purge": { "clips", "libraries", "projects", "paused", "paused_tenants" }, "missing_files": { "checked", "cleared", "remade", "paused", "paused_tenants" }, "dismissed_people": { "deleted", "paused", "paused_tenants" }, "face_clusters": { "computed" }, "expired_scans": { "deleted" }, "expired_uploads": { "deleted" }, "idle_keys": { "ended" }, "backup", "previews_move", "plugins_purged" }` (`computed`: accounts whose clusters were computed again; `backup`, with `tenants=all`: the nightly backup `started` in the background, already `running`, `not due` or `not started` (it never fails upkeep; see GET /v1/system/backups), null for one account; `previews_move`, with `tenants=all`: a previews move that stopped goes on, `started`, `running`, `waiting` (15 minutes after an error), `not moving` or `not started`, null for one account; `plugins_purged`, with `tenants=all`: the plug-ins uninstalled to the trash whose 30 days were up, deleted for good from every account, null for one account). While an account's Upkeep switch is paused (`POST /v1/producers/upkeep/pause`), its face propagation, trash purge, missing-file repair and dismissed-people cleanup are skipped and logged: `paused` is true and `paused_tenants` names the accounts skipped (with `tenants=all`, any of them), so a skipped run reads apart from one with nothing to do. Search sync, face clusters and token cleanup still run.
- **POST /v1/upkeep/search-sync** — Run search sync sweep only, for the account (search is the account's; there's no library scope) or, with `tenants=all`, every account. Writes the search rows (ADR-019, `src/server/search/sync.py`) of clips whose `search_synced_at` is null or older than their latest description, OCR or correction, and the segments of transcripts whose `transcript_synced_at` is null or older than `transcribed_at`, a batch at a time by id for up to 30 seconds an account (what's left goes on next sweep); each is marked synced in the same transaction, and only if nothing wrote the clip meanwhile. Then plug-ins' facts saved under a key an installed plug-in's newer version renamed (an output's `was` in its manifest) are renamed to its key now, an empty one too, and the search text of facts saved before a newer version searched other outputs (its manifest's `searchable`) is written again from the facts saved, nothing made again for either (`facts_synced`: the facts renamed, each output once, and the search texts written). `force=true` clears every sync time first, so every clip's and transcript's rows are written again. Returns `{ "synced", "failed", "transcripts_synced", "transcripts_failed", "facts_synced" }` (`synced`, `transcripts_synced`: marked synced; `failed`, `transcripts_failed`: batches that couldn't be written, tried next sweep, or accounts whose sweep failed; `facts_synced`: plug-ins' facts whose search text was written again).
- **POST /v1/upkeep/cleanup** — Query: `dry_run` (default `"true"`), and with an account key `library_id` (that library's directory alone, and not the account's playback cuts; 404 when it isn't the account's) or `all=true` (the whole account): neither or both is a 400 `scope_required`; either with `tenants=all` is a 400. ## Names (ADR-024)

Lumiverb's own data has names, `lumiverb.` then words (`lumiverb.image.description`, `lumiverb.preview`, `lumiverb.video.transcript`), one per producer and one per file, listed in `docs/data-names.md` (written from the code: `src/producers/names.py`). The server stores, takes and sends the names (ADR-024 phase 1): every producer by what it makes (its `artifact`, and its lineage's `producer`, which is the same name: a producer is named by what it makes), a job's kind (`redo:<name>` for its remakes; the scan's stays `scan`), pause targets, failures, reader work and check-ins, 409 details and the repair summary (`missing`, by name), and every file a clip has: `GET` and `POST /v1/assets/{id}/artifacts/{name}` (`lumiverb.preview`, `lumiverb.preview.thumbnail`, `lumiverb.video.preview`, `lumiverb.video.analysis_proxy`, `lumiverb.video.scenes.picture`), the batch upload's file fields and their items' `artifact_type`, ingest's `lumiverb.preview`, an upload's `artifact`, and playback's `source`. An installed plug-in's work is its plug-in's id (`geonames`). **The old spellings' window closed with v0.1.109** (ADR-024 phase 1's part 5): from part 3 (v0.1.107) to part 4 (v0.1.108) the server also took what each was called before (its history: `docs/data-names.md`'s "Was"), and now refuses one, saying the name (a plug-in's work by `plugin_<id>`, its id; never an id a plug-in can't have, whose work was left out: nothing is called that), and keeps or changes nothing: in a URL (a producer's path, a file's, the failures list's `artifact`) 404 `renamed` with `details` `{ "sent", "name" }`; in a body or form 422: `renamed` (the same `details`) for an ingest's or batch upload's file field or `lineage` key, the field's error naming it for an `artifact` in failures, retry and Run or an upload's `artifact`, and `lineage_wrong_producer` (naming the producer) for a lineage's old `producer`. A device's key is let through to the route, which refuses it the same way. Lumiverb's own clients send the names: the CLI and `lumiverb-server` take a name with or without `lumiverb.` and refuse an old word, saying the name to type; the device and the scan; the Mac and iPhone apps; Resolve's plug-in. A reader checks in at protocol 2 only: protocol 1, which said today's ids, is 426 `reader_too_old` (Readers API). What isn't renamed takes no name: AI jobs (`/v1/ai/jobs/clip`), pools, model ids (`clip`), search hit types, and protocol 1's inputs in a plug-in's manifest (`location`, `capture_time`, `metadata`, `preview`). A plug-in's id can't be one of Lumiverb's words (its producers' and files' old ids, lineage's producers, the queue's kinds, the pools, the first word of each name, `all`, `upkeep`, `scans`, `scan`, `person`, `unknown`) or start with `lumiverb`: `lumiverb-server plugins install` refuses it. One installed before part 1 with such an id is left out of what's installed (not run, its work not a producer, its facts and places not shown), its work's rows kept as they were (`plugin_<id>`), and said with what to do on the Admin page (Installed plug-ins, red), in the log and by `lumiverb-server plugins`: uninstall it, then install it under another id.

## Producers API

ADR-016 phase 3. Each derived artifact has one producer, named by what it makes (`src/producers/`, `docs/data-names.md`): `lumiverb.video.format`, `lumiverb.capture_time`, `lumiverb.preview` (with its thumbnail), `lumiverb.video.preview`, `lumiverb.video.analysis_proxy`, `lumiverb.video.scenes`, `lumiverb.video.scene_descriptions`, `lumiverb.image.description`, `lumiverb.image.text`, `lumiverb.image.likeness`, `lumiverb.image.faces`, `lumiverb.video.faces`, `lumiverb.video.transcript`, `lumiverb.location.guess`, and an installed plug-in's work. Every write of an artifact records its **lineage** (table `artifact_lineage`, one row per clip and artifact): the producer, its version, the hash of the settings that affect its output, the content hash of the source file it was made from (`source_hash`), and whether it came out `ok`, `empty` or `failed`. An artifact is **current** when all four match what the producer makes now, **stale** when any differs, **missing** when there is none (scene descriptions: until every scene has one).

- Settings live on the server: the registry's defaults, then per-producer overrides (`system_metadata` `producer.<name>`, JSON), then each AI producer's model from its job, chosen in Settings → AI (vision, OCR and scene descriptions: the tenant's `vision_model_id`; transcripts: its `transcript_model_id`). A job's model comes from the job alone: an override can't name another. The worker reads them here and makes artifacts with them, so what it records is current.
- Every machine write says how it was made (Robert, Oct 9: the API doesn't take writes that don't): probe, proxies, video previews and analysis copies, descriptions, OCR, CLIP vectors, faces, transcripts, scenes and scene descriptions, and an ingest's for what it stores (the proxy always; a description with a model, CLIP vectors and a probe when sent). Without `lineage`, or with one that can't be read, it's 422 `lineage_required` (`details`: `artifact`, `producer`); naming another kind's producer (or `person`: only the server says a person made something) is 422 `lineage_wrong_producer`. Either is checked before anything is saved. A person's writes (corrections, a manual transcript) need none. A lineage row that's missing (written before this) is producer `unknown`'s: stale.
- A transcript a person wrote or deleted is producer `person`: current whatever the settings, never regenerated over.
- Only vectors stored under `model_id` `clip` are the CLIP producer's artifact; another model's (the `apple_vision` FeaturePrint vectors the macOS app stored while it still embedded photos itself) neither record CLIP lineage nor count as CLIP made.
- **The reconciler** (`src/server/repository/lineage.py`). An artifact is missing when it doesn't exist, whatever its lineage says; one that exists with no lineage at all is `unknown`'s, so stale. The scheduler is handed what's missing, and what was made from a file whose content has since changed (a different file at a path is a new clip, so this is a hash that changed some other way), once what it's made from exists (its queue, `src/server/scheduler/queue.py`); the repair summary's `missing` counts (`GET /v1/assets/repair-summary`: `{ "total_assets", "missing": { name: clips }, "faces_without_vectors", "stale_search_sync", "waiting_failures" }`, `missing` also counting what scans left out, `lumiverb.preview` and `lumiverb.metadata`) are the same rule. Stale from a producer or settings change is **redone** (below), after anything missing. A failure waits its turn (5 minutes, doubling up to a day); the repair summary's `waiting_failures` counts those. OCR (`asset_ocr`, one row per clip) is apart from the description: it needs only the clip, and describing a clip again leaves it alone.
- A failed try keeps its error and is tried again after 5 minutes, doubling up to a day; an artifact made earlier stays what it was.

Writes carry `lineage` as `{ "producer", "version", "settings_hash", "source_hash" }` (all strings; `source_hash`, the content hash of the file it was made from (see Content hashes; 422 `content_hash_not_valid` for one the server doesn't take), defaults to the clip's now): a JSON field on `PUT /v1/assets/{id}/video-facet`, `POST /v1/assets/{id}/vision|ocr|embeddings|transcript`, the `batch-vision|batch-ocr|batch-embeddings|batch-faces` bodies (each item may carry its own `source_hash`), `POST /v1/video/chunks/{id}/complete` (recorded for `lumiverb.video.scenes` when the last chunk completes) and `PATCH /v1/video/scenes/{id}` (`lumiverb.video.scene_descriptions`); a JSON form field on `POST /v1/video/{id}/faces` (`lumiverb.video.faces`); a JSON form field on artifact uploads (`POST /v1/assets/{id}/artifacts/{type}`; the batch upload takes one object keyed by name) and on `POST /v1/ingest` (keyed by name: `lumiverb.preview`, `lumiverb.video.format`, `lumiverb.image.description`, `lumiverb.image.likeness`, `lumiverb.capture_time`). `lumiverb.capture_time` is optional: an ingest with `exif` that gives it records the capture facts (`taken_at`, `taken_at_offset_min`, `gps_accuracy_m`) as read; one that doesn't (the macOS app) leaves them for the capture producer to read again from the original.

- **GET /v1/producers** — Signed in. Query: `library_id` or `project_id` (counts in one library or project; `project_id` needs an editor, like every project route, and a project the caller can't see is 404), `counts` (default `true`; the worker sends `false`). Returns `{ "producers": [{ "artifact", "version", "title", "media", "uniform", "settings", "settings_hash", "fields": [{ "key", "label", "kind": "int" | "float" | "text" | "bool" | "level" | "notch", "value", "default", "minimum", "maximum", "unit", "advanced", "fixed", "remakes", "choices" }], "counts": { "applicable", "current", "stale", "missing", "rechecking", "below", "failing", "given_up", "lacking" } | null, "scheduled", "redoable", "why_not", "redo_stopped", "redo_stopped_by", "redo_stopped_at", "paused", "paused_by", "paused_at", "waiting", "unit", "level", "part_of", "needs", "reads", "reads_others", "new_version", "waits", "plugin" }] }` over clips in sight. `artifact` is the name of what it makes, which is also its lineage's `producer` (ADR-024: a producer is named by what it makes). `reads`: the names of what its work reads (`lumiverb.original` for a producer that reads the originals); `reads_others`: those of them another producer makes or a person writes (`needs` is the producers among them). `plugin` (`{ "plugin_id", "title", "on" }`, null for most): the plug-in it belongs to, which it applies only while that's on in the account (Plug-ins API). An installed plug-in's work (ADR-023 phase 2) is a producer of its own, its artifact its plug-in's id (`facts`; before ADR-024's part 3, `plugin_` and the id with dashes as underscores), added while the server runs (within about half a minute of an install): its `title` and `version` its manifest's work's, its `fields` the settings that remake, each `fixed` "Set in Settings › Plug-ins" (they're the plug-in's: `PUT /v1/plugins/{id}/settings`), its counts over its media's clips that have every input it reads; `lacking` (`[{ "name", "label", "clips" }]`, one for each input it reads that a clip may never have: `lumiverb.capture_time`, "date taken", and `lumiverb.location`, "location") counts its media's clips without it, which it doesn't apply to: never missing, nothing waits for them (ADR-023: "4,392 have no location"; `[]` for Lumiverb's own producers). A `notch` setting is a quality, not an encoder's number (ADR-018 decision 6): **Quality**, `good`, `better` (default) or `best` (its `choices`, lowest first), set by name: the analysis proxy's, a clip's preview and thumbnail's (`lumiverb.preview`) and a video preview's. It's in the hash as what it stands for, and `settings` says that, not the notch, as a producer's work, a scan and a device read it (reader-changes' `made_with` too); `fields` says the notch chosen. The analysis proxy's and a video preview's stand for x264's CRF (32, 28, 23; NVENC's CQ is two more); a preview's for the JPEG a scan makes from the original and the WebP it sends and the server keeps, the thumbnail's too (`jpeg_quality` 65, 75, 90; `webp_quality` 70, 80, 90: the server re-encodes every preview and thumbnail at the account's, `src/server/preview_image.py` `quality`). Better is what every one was made with before notches, so none is made another way for them. A scan makes new files' previews with the account's notch, and remakes those made another way a few at each scan while their remakes run (Scans API, plan reason `remake`). A `level` setting (scenes' **Detail**: `low`, `normal` (default), `high`; faces' **Photos** and video faces' **Videos**: `off`, `low`, `normal` (photos' default), `high`, `low` being videos' default; its `choices`, lowest first) isn't in `settings` or the hash: lineage records the level an artifact was made at apart from it (`level`, its index), and the producer's `level` is the one now. Made below it is `below` (not current, not stale: never redone by itself, see `POST /v1/producers/{artifact}/below/redo`); made at it or above is current, so lowering it costs nothing. `part_of`: shown as a part of another producer (scenes, of scene descriptions; video faces, of faces: Settings → Processing shows one row). `needs`: the artifacts it's made from (scene descriptions and video faces: the analysis proxy and scenes). A clip lacking one waits for it and isn't counted by this producer (scene descriptions apply to videos whose scenes are found), so Settings → Processing says how many clips wait for each: the needed producer's `missing`, and whether it's paused. Faces' levels: Photos says which faces count (Low only clear ones: large, sharp, confident; Normal what was always found; High smaller and softer ones too), Videos which frames are looked at (Low each scene's picture; Normal three a scene; High those and a frame every 3 s: more moments, not smaller faces, since frames come from the 960-px analysis proxy). **Off** finds no new face in any photo, or video: the producer applies to nothing while it's off (its `counts` are all 0, nothing is missing or handed out, and it's no health warning), and the faces found, and their names, stay. `unit`: what its work grows with, `"second"` (of video) or `"clip"`. Each producer declares itself in `src/producers/<artifact>/`. `fields`: its settings as Settings → Processing shows them; `remakes` false for one that changes only what's done with what's made, not the artifact (faces: its level, `detail`, and `merge_close_clusters`, default on, merges face groups closer than `merge_distance`, a cosine distance), which isn't in `settings` or the hash; `fixed` says why one can't be changed here (an AI job's model is chosen in Settings → AI; a setting its code doesn't read yet isn't offered), null when it can. `uniform`: its output must come from one model across the library (CLIP, faces). Faces found again keep what people said: a named face, or one someone said isn't a certain person, is kept even when the new settings don't find it, and a face found again keeps its "not them". `rechecking`: made, and due to be checked again (location guesses), not missing. `scheduled`: the scheduler makes it (false: scans do, for proxies and video previews, which pausing scans stops). `redoable` / `why_not`: whether stale ones are made again yet (every producer's are today, proxies and video previews by scans; `why_not` says why for one that isn't). Scenes found again replace the clip's old ones once they're found and described, and the old ones' descriptions go with them; until then the clip shows its old scenes (see `POST /v1/video/{asset_id}/chunks`). `redo_stopped`: an admin stopped its redo (`redo_stopped_by` is shown to admins only), or a release did: the first time the scheduler sees clips an older version made, or made with defaults since changed, their redo waits for an admin to resume it (`redo_stopped_by` null). `paused`: an admin paused it: nothing more of it starts, missing or stale (`paused_by` is shown to admins only). `waiting`: why its work waits now, for a producer of an AI job: the job is off (no model), no machine does it, or none doing it is online (null otherwise). `new_version`: its redo was stopped by a release, not an admin (`redo_stopped` is true too): a new version of it, or new defaults (a prompt, what a quality stands for, its job's default model) that change what the account makes it with. What was made before is made again once an admin resumes it. A person's own change was asked about when it was made (409 `redo_on_change`), so it holds nothing; nor does a default the account doesn't use. `waits` (null when `counts` is false): why its due work waits now (Robert, Oct 12: no silent waits), `[{ "reason", "clips", ... }]`, one entry for each reason holding some of it back, in this order, each only when some clips wait for it (`ai_machines` whatever: its work would). Due work is what the scheduler would hand out: missing (or made from a file that has since changed, or due to be checked again), and stale while its redo runs; a failure waiting its turn isn't due. The reasons (`src/shared/waits.py`): `paused` (its switch, or Pause all; `clips`: what's due); `scheduler` (`why`: `not_running`, it hasn't written its status for 30 seconds; `starting`, it hasn't read the account's settings yet; `cant_list`, listing the producer's work failed, `message` the error); `ai_machines` (`job`, and `why`: `off` (no model), `no_machine`, `offline` (none doing it is online), or `unusable` (Settings → AI has one, but the scheduler can use none); `message`: why in a sentence, as `waiting`, or the scheduler's own words, a machine's address in them said as "the AI machine" to anyone but an account admin); `plugin_down` (an installed plug-in's work: the scheduler hands none of it out while its plug-in isn't running, `message` why as the plug-in runner said it (starting, preparing its data, stopped and why, or the runner isn't running), `clips` what's due; or clips a job held back because it found the plug-in down or it didn't answer in time, tried again within the hour, without `message`); `needs` (`artifact`: what its clips lack, `clips` being that producer's `missing`; `paused`: whether what makes it is, its switch or, for what scans make, the library's scans (with no `library_id`, every library's)); `storage` (for a producer that reads the originals, one entry per library in the scheduler's `storage_waits` where it has due work: `library_id`, `library_name`, and what the scheduler's looks found, `seen_at`, `away_since`, `checked`; none while all processing is paused, when nothing looks at the drives); `device` (for a producer that reads the originals, one entry per active library a device reads where it has due work: the device makes it, not the scheduler: `library_id`, `library_name`, `device_id`, `device_name`, `checked_in_at`, its latest check-in for the library or null, and `remakes_held`, why that check-in said its remakes wait, `battery` or `metered`, or null); `new_version` and `redo_stopped` (its redo stopped by a new version of it, or by an admin: `clips` are its stale ones); `scan` (clips the scheduler holds back after a try found the file missing from storage that's there, or changed since it was hashed: a scan comes first; `paused`: a library it waits on has its scans paused) and `held` (clips held back after a try that couldn't finish through no fault of theirs, the GPU out of memory, the AI machines or the server away, or a crash not yet charged: tried again within the hour), both from the scheduler's status (`held`), counted over the account or one library and not for a project (the scheduler doesn't say which clips they are); `retry_later` (failing clips waiting their turn) and `given_up` (failing ones no longer tried until someone asks); and `scan_failing` and `scan_unreadable`, a library's scans' own, said on the library's row in `GET /v1/producers/queue` (`libraries`), never a producer's: its scans keep failing (`message`, `since`, `next_try`), or files in it the scheduler isn't allowed to read, their permissions (`clips`: how many; `paths`: the first 20 by path; `reader`: who it reads as, "the lumiverb user"), a person's to fix: tried again at each scan, not left for a retry, and taken in once readable. - **POST /v1/producers/{target}/pause** — Admins. Body: `{ "scope": "work" | "redo" }` (named; 422 without it). `target` is always named; nothing acts on everything from a missing one (Robert, Oct 9), so there's no `POST /v1/producers/pause`. Scope `work`: `all` pauses every switch (Upkeep, each producer the scheduler makes) and every library's scans, so the state is `paused`. What's running finishes. Again is fine: who paused first stays. 204; 404 unknown producer; 409 `cant_redo` for a redo of a producer that isn't redone (proxies, video previews); 409 `not_scheduled` for pausing what scans make (a library's scans pause stops those); 409 `per_library` for `scans`; 422 `bad_scope` for a redo of Upkeep.

- **POST /v1/producers/failures** — Admins (the scheduler), and a device for what it makes from the originals (`lumiverb.video.format`, `lumiverb.capture_time`, `lumiverb.video.analysis_proxy`) of clips in the libraries it reads (another artifact, 403 `not_for_devices`; a clip of another library, 404 for the whole batch). Body: `{ "items": [{ "asset_id", "artifact", "error" }] }`, at most 500; an unknown `artifact` is 422. Clips that don't exist are left out. Returns `{ "recorded" }`. A machine that can't do its job (no machine doing vision or transcripts is online, or none offers the model) isn't reported here: it isn't the clip's failure (see AI machines API).
- **GET /v1/producers/queue** — Signed in. What the scheduler is doing for the account, as it last wrote (every 5 seconds): `{ "live", "at", "running": { kind: jobs }, "waiting": { kind: jobs lined up next }, "pools": { pool: [busy, slots] }, "gpu_hold", "state", "switches": [{ "target", "title", "paused", "paused_by", "paused_at", "waits" }], "libraries": [{ "library_id", "name", "reader", "reader_name", "checked_in", "paused", "paused_by", "paused_at", "waits" }], "pace", "jobs", "storage_waits", "storage", "held", "ai_waits", "settings_ready", "unlisted", "scans_failing", "scans_unreadable", "eta" }`. `live` is false when it hasn't written for 30 seconds (it isn't running). Kinds: `scan`, and each producer's by the name of what it makes (ADR-024, `docs/data-names.md`): `lumiverb.video.format`, `lumiverb.capture_time`, `lumiverb.live_photo`, `lumiverb.video.analysis_proxy`, `lumiverb.video.scenes`, `lumiverb.video.scene_descriptions`, `lumiverb.video.description`, `lumiverb.image.description`, `lumiverb.image.text`, `lumiverb.image.likeness`, `lumiverb.image.faces`, `lumiverb.video.faces`, `lumiverb.video.transcript`, `lumiverb.location.guess`, an installed plug-in's work's (its plug-in's id), and `redo:<kind>` for redoing stale ones. `gpu_hold`: requests the AI machines sharing its GPU give up while video is decoded there. `switches`: every pause switch, Upkeep, then each producer the scheduler makes, and whether an admin paused it (`paused_by` is shown to admins only), whether or not the scheduler is live. `libraries`: each library not in the trash, by name: who reads its files (`reader`: `"server"`, this server, or a device's id; `reader_name`, the device's name; `src/shared/readers.py`), its reader's latest check-in for it (`checked_in`, as `GET /v1/libraries` says it: the web app's Processing and Admin pages say "Read by Studio Mac · checked in 1 minute ago", or "not heard from in 3 days", and never call a device's library out of this server's reach) and whether its scans are paused, its own pause or Pause all (`paused_by` admins only). `state`: derived from both: `running` (none paused: green), `partly` (some: yellow) or `paused` (every switch and every library's scans: red). `pace`: `{ kind: seconds }`, the seconds a slot spends per unit of a kind's work (a second of video, or a clip: the producer's `unit`), learned from the clips its last jobs made (failures don't count) and kept across restarts. `jobs`: `[{ "kind", "units", "elapsed" }]` running now. `storage_waits`: libraries whose work on the originals waits: not reachable at the latest look, or not looked at since the scheduler started. `storage`: `{ library_id: { "seen_at", "away_since", "checked" } }`, what its looks at each library's storage found: when last seen reachable, since when unreachable (null: the latest look reached it), and `checked`, whether it was looked at since the scheduler started (otherwise it's the record from before a restart, kept in this status). The scheduler looks at each library's storage itself every 30 seconds, and at once for one not looked at since it started, whatever is paused (a scan looks again before it walks a library; a job finding it gone counts too, until the next look), except while all processing is paused (Pause all), when nothing touches the drives; on resuming, the look comes before any work on the originals. `held`: `[{ "kind", "why", "library_id", "clips" }]`, the clips it holds back for up to an hour after a try that neither saved nor charged them, by kind (a redo's under its kind), library and why: `scan` (the file was missing from its storage, or changed since it was hashed: a scan comes first) or `held` (the try couldn't finish through no fault of the clip's); one without `why` is `held`. `ai_waits`: `{ job: why }`, each AI job whose machines it can't use now (its work isn't handed out), in its own words, a machine's address said as "the AI machine" to anyone but an account admin. `settings_ready`: it has read the account's settings (until then it hands out nothing; true when a status doesn't say). `unlisted`: `{ kind: error }`, kinds whose last listing failed. `scans_failing`: `[{ "library_id", "error", "since", "next_try" }]`, libraries whose scan itself keeps failing (not a file: the scan raised): each is tried again after a minute, then 2, 4 and so on up to half an hour, from the first success as before, its reported changes waiting meanwhile (not kept over a restart, which tries each at once). `scans_unreadable`: `[{ "library_id", "files", "paths", "reader" }]`, libraries with files the scheduler isn't allowed to read (their permissions), as its scans last found them: how many, the first 20 by path, and who it reads them as ("the lumiverb user"); each is tried again at every scan, and taken in once it's readable (not kept over a restart: the next scan finds them again). `GET /v1/producers` says each of these on the producers' rows (`waits`); a library's row says its scans' own in `waits`, in the same shape: `{ "reason": "scan_failing", "clips": 0, "library_id", "library_name", "message", "since", "next_try" }` when it's in `scans_failing`, and `{ "reason": "scan_unreadable", "clips": files, "library_id", "library_name", "paths", "reader" }` when it's in `scans_unreadable`, while the scheduler is `live`. While it's `live`, `eta` says how long until things are made: `{ "producers": { artifact: seconds }, "pools": { pool: seconds }, "caught_up": seconds, "not_counted": [{ "artifact", "title", "why": "no_machine" | "not_known_yet" | "paused" }], "jobs": [{ "kind", "artifact", "unit", "units", "elapsed", "left", "late" }] }`. A producer's work left is what the scheduler will make: missing, and stale while its redo runs; not clips waiting out a failure or given up, nor those an earlier step was given up on, nor, for work that reads the originals, those in `storage_waits` libraries (counted at most every 30 seconds). At its kind's pace over its pool's slots that's its pool's time; producers sharing a pool each finish about when it does; pools run side by side, so `caught_up` is the slowest pool's. A producer with work but no machine doing it now, no pace yet, or paused has no time: it's in `not_counted`, and `caught_up` leaves it out (`null` when nothing with work is counted). Paused work has no time; a running job still says its time left, since it finishes. A running job is `late` when it has run twice its pace; scans aren't timed. `eta` is null when it isn't live, or when working it out fails.
- **GET /v1/producers/failures** — Signed in. Query: `artifact`, `library_id` (both optional), `limit` (1–500, default 50), `after` (the `next_cursor` of the page before). Clips in sight whose last try failed, newest failure first: `{ "items": [{ "asset_id", "artifact", "title", "rel_path", "library_id", "library_name", "media_type", "error", "attempts", "failed_at", "retry_at" (null once given up), "given_up" }], "next_cursor" }`. An AI job's `error` says its machine's address only to an account admin: anyone else reads "the AI machine" in its place. 404 for an unknown `artifact`.
- **POST /v1/producers/failures/retry** — Editors and admins. Body: `{ "asset_ids" }` (these clips) or `{ "all": true }` (every failing clip in sight), each narrowed by `artifact` and `library_id` when given; neither or both is a 400 `scope_required`. Tries them again now, given up or not (the back-off starts over; the last error stays until it's made); the scheduler lets go of its own hour-long hold on clips it just tried. Returns `{ "retried" }`.
- **POST /v1/producers/{artifact}/below/redo** — Admins. Make again what a producer made below its level now (scenes found at a lower Detail): raising the level never does it by itself. Body: `{ "asset_ids" }` (these clips; any not below stay as they are) or `{ "all": true }` (every one below in sight), narrowed by `library_id` when given; neither or both is a 400 `scope_required`. They're redone as any redo is (their lineage stops being current): after anything missing, at the level then, held while the producer's redo is stopped or it's paused, and their scene descriptions go with them. Returns `{ "redo", "paused", "redo_stopped" }`. 404 unknown producer; 409 `no_level` for a producer without a level setting.
- **POST /v1/producers/run** — Editors (scope `redo`: admins). Ask the scheduler to do work now (what `lumiverb enrich` does). Body: `{ "producer": "<artifact>" | "all", "scope": "new" | "redo", "library_ids": [...] }` or with `"all": true` for every library; neither or both is a 400 `scope_required`. The named producers' failing clips in those libraries are tried again now and the scheduler looks again at once; with `redo`, what they've made there (never a person's) is made again after anything missing, as new settings would (re-detecting faces is `lumiverb.image.faces` with `redo`). It goes as the scheduler goes: by tier, within its pools, and what's paused waits. Returns `{ "producers": [{ "artifact", "title", "missing", "redo", "retried", "paused", "redo_stopped" }] }` over those libraries. 404 unknown producer or library; 409 `not_scheduled` for what scans make; 403 for a redo by an editor.

## Video chunk API

All under `/v1/video`; require tenant auth, and every route but `GET .../scenes` an editor (claiming a chunk too). Used by the scenes producer to find a video's scenes in chunks of whole scene windows (about 30 s each; `src/producers/scenes/detail.py`). The server owns chunk allocation policy (lease expiration, retry on failure). No video bytes reach the server — only scene rep frame keys and metadata. The CLI generates a unique `worker_id` per session for chunk ownership verification.

- **POST /v1/video/{asset_id}/chunks** — Body: `{ "duration_sec", "scene_sec", "redo": false, "lineage" }`. Initialize chunks for the asset (idempotent): `scene_sec` (required, > 0, up to 3,600) is the scene window the indexer works in (from the video's length and the account's Detail), and the chunks are whole windows, about 30 s each (one window when a window is longer), so no scene ends at a chunk's end. With `redo` (the scheduler's redo of scenes found with other settings; editors and admins, 403 otherwise), `lineage` says how they'll be found (422 `lineage_required` without it; 409 `settings_changed` unless it's how scenes are found now): a clip whose scenes were found another way gets a new run beside them: its old chunks go (and scenes an earlier redo had staged), and the scenes it shows stay, described, with their images and search entries, until the new ones are found and described (ADR-016, principle 11; see `complete` and `PATCH /v1/video/scenes/{scene_id}`). The chunks record how their run finds scenes (`run`). A redo sent again, while its run is under way or once it's found that way, changes nothing; a redo with other settings drops what the last one staged, never the scenes shown. Each call starts a run: chunks that failed in an earlier run are pending again. Returns `{ "chunk_count", "already_initialized" }`.
- **POST /v1/video/{asset_id}/chunks/next** — Claim next pending chunk for the asset (or one whose lease ran out); a failed chunk isn't handed out again until the next run. Chunks go in order: 409 `chunk_under_way` while one is claimed (its lease not run out), `chunk_failed` while one failed this run. Returns 204 when every chunk is completed. On success returns `{ "chunk_id", "worker_id", "chunk_index", "start_ts", "end_ts", "video_duration_sec", "is_last" }`. Worker must send `worker_id` when completing or failing the chunk.
- **POST /v1/video/chunks/{chunk_id}/complete** — Body: `{ "worker_id", "lineage" (how the scenes were found: required on every chunk, with `level`, the Detail they were found at: 422 `lineage_required` before anything is saved), "scenes" }`. `scenes`: list of `{ "start_ms", "end_ms", "rep_frame_ms", "description", "tags", "sharpness_score", "keep_reason", "phash" }` (storage keys aren't taken from clients: a scene's frame lives at the key the server derives from `rep_frame_ms`). Persists scenes, numbered by the server after the clip's scenes of the same set already stored (`scene_index` is unique per clip and set: the scenes shown, or a redo's), marks chunk completed. A clip that shows scenes already (`video_indexed`) is a redo's: its scenes are staged beside them (`finding`). When the last chunk completes, in the same transaction: the discard pass merges scenes alike (one pass left to right; a run goes on while the next scene's `phash` is within the level's bound of the run's first scene, which is kept and takes the run's whole span; a scene without a `phash` is never merged; `phash` is the picture's perceptual hash, a 64-bit wavelet hash as 16 hex digits, and two of different sizes, a scene found before scenes version 5 with its 256-bit pHash, are never merged), the scenes are numbered again, the lineage (with its level) is recorded and the asset is marked `video_indexed`, so scene descriptions only ever see the scenes kept. A redo's run is merged the same way and becomes `found`, and a found scene whose `rep_frame_ms` is that of a scene the clip shows, described, takes that scene's `description`, `tags` and `lineage` (a scene is described from its one frame). When every found scene is then described as the account's describer would describe it now, they're swapped in at once, and the video's own description is made again unless they're the scenes the clip showed (the same spans on the same frames). Otherwise its scene descriptions' lineage goes, so the rest are described next, while the clip still shows its old scenes; the last one described swaps them in. With no model describing scenes (Settings › AI), nothing would describe them, so they're swapped in at once. The log says how many were found and kept. Returns `{ "chunk_id", "scenes_saved", "all_complete" }`. 409 if chunk not owned by worker.
- **POST /v1/video/chunks/{chunk_id}/fail** — Body: `{ "worker_id", "error_message" }`. Marks chunk failed. Returns `{ "chunk_id", "status": "failed" }`. 409 if chunk not owned by worker or not claimed (a completed chunk stays completed).
- **GET /v1/video/{asset_id}/scenes** — The scenes the video shows, ordered by `start_ms`. `describing=true` (the scene describer's): the ones to describe next, a redo's found scenes while it has them, else the ones shown. Response: `{ "scenes": [ { "scene_id", "start_ms", "end_ms", "rep_frame_ms", "thumbnail_key", "description", "tags", "sharpness_score", "keep_reason", "phash", "lineage" } ] }`. `lineage`: how the scene's description was made, `{ "producer", "version", "settings_hash" }` (`unknown` when the write didn't say), or null. The worker describes again each scene not made the way it would make it now (a whole video again when every scene already matches but it was handed out), so finishing a part-described video redoes scenes made with older settings too: scenes have no person's edits.
- **PATCH /v1/video/scenes/{scene_id}** — Body: `{ "model_id", "model_version", "description", "tags", "lineage" }`. Updates vision results on a scene after describing its rep frame, with how it was made. The video's `lumiverb.video.scene_descriptions` lineage is recorded once every scene has a description made the same way, so a video described half with old settings and half with new isn't current. The last of a redo's found scenes described swaps them in, in one step, with that record: the old scenes go, then their images (at keys the server derives, and not one a new scene shares) and their search entries. 409 `scene_gone` when the scene was dropped meanwhile (its video's scenes were found again and swapped in, or another redo dropped what it staged). Response: `{ "scene_id", "status": "updated" }`.
- **POST /v1/video/{asset_id}/faces** — Editors. A video's faces, from the video faces producer (`src/producers/video_faces`): one face a person seen, not one a frame. Multipart: `faces`, a JSON list of `{ "bounding_box", "detection_confidence", "embedding", "frame_ms", "seen_ms" }` (the face as shown, its box in the frame at `frame_ms`; `seen_ms`, every time in ms the person was seen at, 1 to 50,000 of them; up to 500 faces); `crops`, one WebP a face in the same order (up to 256 KB each), cut from its frame, since the server has no frames; `lineage` (JSON, required, with `level`, the Detail the frames were chosen at); `source_hash` (a content hash; 400 `content_hash_not_valid` otherwise); `detection_model`, `detection_model_version`, `embedding_model` as for a photo's. Saved as a photo's faces are (`POST /v1/assets/{asset_id}/faces`: a face found again keeps its id and what people said; one named or said not to be someone is kept when not found again), with `frame_ms` and `seen_ms` (`frame_ms` among them); `face_count` is the people seen. Refused before anything is saved: 422 `lineage_required` / `lineage_wrong_producer`; 400 `faces_not_valid`, `too_many_faces`, `crops_dont_match`, `crop_not_valid`, `not_a_video` (a photo's faces go to `POST /v1/assets/batch-faces`); 404 for a clip that isn't there or is in the trash. Returns `{ "face_count", "face_ids" }`, one id a face, in order.
- **POST /v1/video/scenes/{scene_id}/sync** — Retired: 410 `gone` (an editor's, as it was). A scene's description and tags are searchable as soon as they're saved (`PATCH /v1/video/scenes/{scene_id}`: its words are computed with its row, ADR-019); a redo's scenes once they're swapped in.

## Change reports API

The server mounts storage over the network and can't watch it, so the machine holding the disks (the Mac Studio) reports paths it sees change, and the server's scheduler scans them (ADR-016 phase 2). Tenant auth: reporting and acknowledging need editor or admin (403 for a viewer); reading needs a signed-in user of any role, even for a public library (401 signed out).

- **POST /v1/changes** — Body: `{ "paths": [...] }`, up to 10,000 absolute paths as the reporting machine sees them, which is how library roots are stored. Each path goes to the library with the deepest matching root (whole folders, Unicode NFC); a path in no live library is counted, not kept. Files or folders, changed, added or removed. 422 for relative paths, `..` or a control character (a newline, a tab: the `rel_path` rule under Assets API; a NUL is the 400 `not_text` of anything a request sends). Returns `{ "accepted", "libraries": { library_id: count }, "unmatched", "unmatched_sample" }`.
- **GET /v1/changes** — Pending counts: `{ "libraries": [{ "library_id", "pending", "oldest_reported_at" }] }`.
- **GET /v1/libraries/{library_id}/changes** — Signed in, and the library's device. Query: `limit` (default and max 10,000). A library's pending changes, oldest first: `{ "changes": [{ "change_id", "rel_path", "reported_at", "version" }], "truncated" }`. `rel_path` is `""` for the root itself. Reporting a path again keeps one row and raises its `version`.
- **POST /v1/libraries/{library_id}/changes/ack** — Editors, and the library's device. Body: `{ "changes": [{ "change_id", "version" }] }`, as read. Removes the changes a scan covered; one reported again since (a higher version) stays. Returns `{ "acknowledged" }`.

## Scans API

The client says what it found; the server decides what's new, changed, moved, skipped and gone (ADR-018 decision 12, phase 2; `src/server/scans.py`, `routers/scans.py`). A scan is a short-lived session: start it before walking, send every media file the walk saw, complete the listing to get the plan, send the hashes the plan asks for to get a decision for each, answer moves if asked, finish, then upload what was decided with `POST /v1/ingest` as today, after the finish (today's scanner archives before it ingests, so a file whose content was just archived as missing comes back at its new path). Before answering moves or finishing, the client checks its drive is still there (an unmounted share is an empty folder): the server can't. `lumiverb scan` and the scheduler's scans are this protocol's client (`src/processing/scan.py` `run_scan`): the CLI answers moves with its prompt (`"ask"`), the scheduler applies them. Editors and admins (403 for a viewer); the account is the token's, so another account's scan or library is a 404. A scan expires a day after its last call: 410 `scan_expired` once it has (and it's deleted; starting a scan deletes the account's expired ones, and so does `POST /v1/upkeep`, for a client killed mid-scan). Each step comes in its turn: 409 `scan_not_planned` before the plan, `scan_planned` for files after it (or a plan for other unlisted folders), `scan_finished` for any call but the finish once finished.

**Sent again.** A client whose answer was lost (a connection reset or dropped, the API restarting behind nginx: 502/503/504) sends the call again, so every call but the start is safe to repeat, and a repeat gets the answer the first got: `found` takes a path's latest size and time; `plan` for the same `unlisted` folders returns the same counts and the plan's first page (409 `scan_planned` for others); a plan page is a GET; `hashes` keep their decisions; `moves` with the same `apply` and none waiting returns the answer it gave (`upload` included: the only word that a move fell through); `finish` returns the answer it gave, whatever its body, and archives nothing more; `DELETE` is a 404 once the scan is gone. Starting isn't safe (a repeat leaves a scan behind): the Python client (`src/processing/api.py`) tries the others again after 0.5, 1, 2, 4, 8 and 16 s while within 35 s of the first failure, every GET too, and nothing after a 4xx or a 500. The scheduler's scans and `lumiverb scan` both go through it.

- **POST /v1/libraries/{library_id}/scans** — Start. Body (all optional): `{ "scope": "", "media_type": "all" | "image" | "video", "thorough": false, "force": false, "moves": "ask" | "apply" | "skip", "dry_run": false, "force_add": false }`. `scope`: a folder of the library (`""` the whole library; a `rel_path` under the rule in Assets API, 400 otherwise): only clips under it can be gone, and only files under it are sent. `media_type`: only clips of it can be gone, and only its files are planned. `thorough`: every file at a path a clip holds is hashed. `force`: every such file is uploaded again, and no moves are looked for. `moves` (default `"ask"`): a file at a new path whose content is a clip gone from this scan moves that clip now (`"apply"`, the scheduler's), is asked about (`"ask"`, the CLI's prompt), or isn't looked for (`"skip"`: then nothing is archived either, since anything gone may be half a move, unless the account doesn't follow moves). `dry_run`: everything is decided, nothing changes. `force_add`: a person's last resort (`lumiverb scan --force-add`): the files a person trashed, archived or deleted for good are added as if they never had been (each planned `hash` with reason `removed`, its content deciding: see hashes). Returns `{ "scan_id", "follow_moves", "expires_at" }` (`follow_moves`: the account's setting; off, a file at a new path is new). Only the library's reader scans it: anyone else gets 409 `not_the_reader` (details: `reader`), here and at the moves and the finish, so a scan started before the library was handed to another reader changes nothing. 404 for an unknown library, 409 `library_trashed`, 409 `scans_paused` (`details`: `{ "library_id" }`) while the library's scans are paused, its own pause or Pause all: whoever reads it finds nothing new in it then (the scheduler leaves it out of its pass first, and takes this 409 for a pause, not a failing scan).
- **POST /v1/scans/{scan_id}/found** — Files the walk found, up to 1,000 a call (422 beyond): `{ "files": [{ "rel_path", "file_size", "file_mtime", "settling": false }] }`. Every media file in the scope, of every media type, empty ones (`file_size` 0: on disk, never uploaded) and settling ones (written moments ago: present, so never gone, but nothing is planned for them) too. 400 for a `rel_path` that breaks the rule in Assets API, isn't a supported media file (`src/shared/file_extensions.py`) or is outside the scope; stored in Unicode NFC. A path sent again takes its latest size and time. Returns `{ "received" }`.
- **POST /v1/scans/{scan_id}/plan** — The listing is complete. Body: `{ "unlisted": [...], "remakes"? }`, folders the walk couldn't list (`""` the library's own): nothing under them is gone or the old half of a move, and while there are any nothing is archived; `remakes` false while the reader holds its remakes back (a device on battery or a metered network): no file is planned `remake`. Sent again for the same folders, the counts it gave and the plan's first page; for others, 409 `scan_planned`. Query: `limit` (1–500, default 500), `action` (as for GET). Plans every found file in one statement and returns `{ "counts": { "found", "upload", "hash", "unchanged", "skipped", "settling", "empty", "gone" }, "files": [{ "rel_path", "action", "reason", "asset_id", "legacy" }], "next_cursor" }`, `files` by `rel_path`. A file at a path a clip in sight holds (`asset_id`): `upload` when a preview the scan makes is missing, its clip's preview or a video's 10-second preview, never arrived or lost (`preview_missing`: what `reader-work` lists as `lumiverb.preview`), or when the scan forces (`force`); `hash` for `thorough`, or when its size or time differ from the clip's (`changed`); `hash` (`rekey`) when they don't but the clip's content hash was made before fp1 (see Content hashes: its fp1 takes that hash's place); `upload` (`remake`) when they don't but its previews were made another way than now (another version or settings: a quality notch changed, ADR-018 decision 6), while their remakes run (the `lumiverb.preview` and `lumiverb.video.preview` producers' redo: not stopped, no new version waiting for an admin), at most 250 a scan, the oldest clips first, never in a dry run: a client uploads these after its new and changed files, its previews made with the account's settings (`reader-changes`' `made_with`); else `unchanged`. A file at a new path: `skipped` (`live_photo`) when a Live Photo's motion there, out of sight as part of its photo (Assets API: `PUT /v1/assets/{id}/live-photo`), has this one's size and time, `force_add` or not; `hash` (`live_photo`) when they differ (the same content is skipped, other content is new); `skipped` (`removed`) when a person trashed, archived or deleted for good a file there whose content isn't known, or whose size and time are this one's; `hash` (`removed`) when they differ; `hash` (`move`) when moves are looked for and its size is a gone clip's (only those are read for it); else `upload` (`new`). Settling and empty files, and files of another media type, get no plan. `legacy`: send the whole file's `sha256:` hash too (`previous_hash`, with its hash or in an upload's `exif`), as a clip or file deleted for good of its size in the library has a content hash made before fp1 (never for `rekey`). `gone`: clips in sight of the scope and media type at no path found, under no unlisted folder, made and last changed before the scan started (another scan may have just made or moved one).
- **GET /v1/scans/{scan_id}/plan** — The plan's other pages. Query: `after` (the `next_cursor`), `limit` (1–500, default 500), `action`: those to list, comma-separated (default `upload,hash,skipped`; `unchanged` lists the unchanged files with their clips, for a client that keeps previews by clip; 422 for another). Returns `{ "files", "next_cursor" }`.
- **GET /v1/scans/{scan_id}/skipped** — The files the scan skips because a person removed them (`lumiverb scan --explain`): those planned `skipped`, and those the hashes sent so far decided `skipped`. After the plan and before the finish, which drops the scan's listing (409 `scan_not_planned` before, `scan_finished` after); a dry run's too; changes nothing. Query: `after` (the `next_cursor`), `limit` (1–500, default 500). Returns `{ "files": [{ "rel_path", "removed_as", "asset_id" }], "next_cursor" }`, by `rel_path`. `removed_as`: `trash` (a person trashed its clip), `archived` (archived it) or `deleted` (emptied it from the trash or deleted it forever: no clip, so `asset_id` is null; `asset_id` is otherwise the clip removed). The removal named is one at the file's path that is this file, as the plan and the hashes decided: its content (once hashed), its size and time, or one whose content was never known; of several, the trash's, then the archive's, then one deleted for good. A file whose clip was restored since isn't listed.
- **GET /v1/scans/{scan_id}/gone** — The clips the scan didn't find (`lumiverb scan --explain`): the plan's `gone` less the moves the hashes decided since (made, asked about or skipped), what the finish archives as missing unless it holds them back (`held_back_reason`). As `skipped`: after the plan, before the finish, changing nothing, `after` and `limit` the same. Returns `{ "clips": [{ "asset_id", "rel_path", "media_type" }], "next_cursor" }`, by `rel_path`.
- **POST /v1/scans/{scan_id}/hashes** — Files' contents, up to 1,000 a call: `{ "files": [{ "rel_path", "content_hash", "previous_hash"? }] }` (`content_hash` the file's, see Content hashes: `sha256:` and 64 lowercase hex, or `fp1:` and 64 for a file over 64 MiB; `previous_hash` the whole file's `sha256:` hash beside an fp1, when the plan says `legacy`; 422 otherwise, a bare hash too). First, the content hashes made before fp1 that these take the place of are swapped for them (the whole file's sent beside its fp1; a `rekey` file's clip's own), in the library's clips in any state, their lineage and its files deleted for good, so each file is compared as it was (a dry run swaps nothing). Returns `{ "files": [{ "rel_path", "decision", "asset_id", "moved_from" }] }`, in the order sent. At a path a clip holds: `upload` when the content differs from the clip's, the scan forces, or a preview of the clip is missing; else `unchanged`, and the file's size and time are recorded on the clip so the next scan's check matches. At a new path: `skipped` when a person removed this content there (or a file there whose content was never known), unless the scan was started with `force_add`: then `restored` when that file's clip is in the trash or archived (`asset_id`; the latest removed, back in sight now, the archive skipped too, with everything it had, and back in search; a dry run brings back nothing), else `upload`, a new clip, and the file is forgotten as deleted for good, so ingest takes it and later scans don't skip it; `moved` when it's a gone clip's content (`asset_id`, `moved_from`): the first file sent takes the first such clip by id, and the clip moves now, back in search at its new path (a dry run moves nothing); `move_candidate` the same when the scan asks first; else `upload`. A copy is never a move: a clip whose file was found isn't gone. A move that can't be made (the clip moved, changed or went meanwhile) is `upload`. A file decided as a move, skipped or restored keeps its decision when sent again. 422 `not_planned` (details `rel_paths`, the first 20, and `count`) for files the plan doesn't list (not found, settling, empty, of another media type), before anything changes; 409 `path_taken` when another clip was just put at a move's path (send them again).
- **POST /v1/scans/{scan_id}/moves** — The person's say on the moves the scan asked about: `{ "apply": true | false }`. Applied (each clip moved now, as `hashes` moves one), or skipped: the moved files take no part, neither uploaded nor their clips archived (the CLI's "Skip moves"). Returns `{ "moved", "skipped", "upload" }` (`upload`: new paths whose move couldn't be made). 409 `moves_off` for `apply` when the account no longer follows moves. Sent again with the same `apply` and no move waiting, the answer it gave.
- **POST /v1/scans/{scan_id}/finish** — Body: `{ "allow_mass_missing": false }`. Archives the gone clips (less those moved, or skipped as moves) as missing, as `DELETE /v1/assets` with `"reason": "missing"` does: the same 409 `mass_missing` (see Decisions), answered with `"allow_mass_missing": true` (the scan stays open until then), and when the account follows moves a clip with an empty newer copy of its file moves there instead. Held back, nothing archived, when folders couldn't be listed (`unlisted`), moves are skipped (`skip_moves`), or a whole library's scan found no file of its media type (`nothing_found`: more likely an unmounted volume than an empty library; not with `force`). 409 `moved_files` (see Decisions) while moves wait for an answer. A dry run archives nothing and asks nothing. Returns `{ "archived", "moved", "handed_over", "unchanged", "skipped", "held_back", "held_back_reason", "dry_run" }` (`moved` includes `handed_over`; a dry run's are what would be). All or nothing: the clips archived, those handed over to their copies, the scan's close and its answer commit together, so an API that dies halfway leaves the scan to be finished again; the copies' files and search documents go once it has. Its listing is deleted; the scan is kept, finished, with its answer, until it expires: sent again, the finish returns that answer.
- **DELETE /v1/scans/{scan_id}** — Drop a scan and its listing, finished or not; nothing else changes (an aborted scan, or a `mass_missing` the person said no to). 204; 404 if unknown.
- **GET /v1/libraries/{library_id}/reader-work** — What the library's reader has to make from its originals, every reason in one list (ADR-018 decision 3; `src/server/reader_work.py`), a page of its clips in sight at a time, by `asset_id` (oldest first). Query: `after` (the `next_cursor`), `limit` (1–500, default 500). Returns `{ "clips": [{ "asset_id", "rel_path", "media_type", "file_size", "content_hash", "work", "remakes" }], "next_cursor" }`, only clips with something in either list. `work`, in this order: `lumiverb.preview` when a preview a scan makes is missing (the clip's preview, or a video's 10-second preview: never arrived, or lost and cleared by the missing-file repair; the next scan uploads the file again, plan reason `preview_missing`), then each producer that reads the originals, by name, `lumiverb.video.format` (a video's facts), `lumiverb.capture_time` (capture time and GPS accuracy) and `lumiverb.video.analysis_proxy`, when it's missing, made from content that has since changed, or due to be checked again, less a failure waiting its turn. `remakes`: those producers' artifacts made another way than now (another version or settings), listed while the producer's redo runs, to be made again after everything else. Previews made another way are remade by scans (plan reason `remake`), not listed here. Computed from how each clip's artifacts were made whenever it's asked, never kept as jobs: what's made leaves it by itself, since its upload records how it was made. Nothing paused is listed: no `lumiverb.preview` while the library's scans are paused (Pause all too), none of a producer's work while its switch is, none of its remakes while its redo is stopped or a new version of it waits for an admin's yes. For each producer it's what this server's scheduler is handed for the libraries it reads. 404 for an unknown library, 409 `library_trashed`.

## Readers API

A library's reader checks in, and a mark per library tells it when to fetch what changed on the server (ADR-018 decision 4, phase 4; `src/server/check_ins.py`, `routers/readers.py`). A library is read by this server's scheduler, which checks in every minute or so and before each scan pass, or by a device that names it (Devices API), with its own key.

- **POST /v1/readers/check-in** — An admin's key, as the scheduler's is, or a device's (403 otherwise). Body: `{ "reader": "server", "client", "version", "protocol": 2, "libraries": [{ "library_id", "state", "waiting_files", "waiting_bytes", "last_full_scan_at", "mark" }] }`: `client` what it is, for people ("this server", "Robert's Mac Studio"); `state` `scanning`, `idle`, `paused` or `away` (its storage can't be reached from the reader); `remakes_held` (optional) why it holds its remakes back now, `battery` (it waits for mains power) or `metered` (for a network that isn't metered), as a device does (ADR-018 decision 6), else left out or null; what it has waiting to upload, the files its latest scan there found to add or read again and hasn't sent yet, and their size on disk (0 when none; the work on the originals is the server's to count, its list); its last full scan; the mark it last fetched what changed at (0: never). `reader` is `"server"` (422 otherwise), this server's; a device leaves it out, as its key says which device it is, and hears the libraries that name it. Each library's latest check-in is kept (`GET /v1/libraries`' `checked_in`). Returns `{ "libraries": [{ "library_id", "name", "root_path", "reader", "scans_paused", "mark", "scan_now", "folders" }], "gone": [...], "check_in_every_sec": 60 }`: the libraries it reads, by name (`scans_paused` its own pause or Pause all; `scan_now` a scan of the whole library asked for; `folders`, to this server's reader, the account's folders on this server, `null` for every folder the server reads, and always `null` to a device: this server reads a library only inside them, its folder and theirs resolved on disk, so a folder that's a link must lead inside them too, and one that doesn't is never read, as a root outside the root map isn't, said once in its log); `gone` the libraries it named that it no longer reads (in the trash, deleted, another reader's). Safe to send twice. 426 `reader_too_old` (`details`: `oldest_protocol`, `protocol`) for a protocol the server no longer speaks. `protocol` is the one the reader speaks: 2, the names (ADR-024), the only one the server speaks from ADR-024's part 3: the server's lists (`reader-changes`' `made_with` and `paused`, `reader-work`'s `work` and `remakes`) are in names. Protocol 1 is 426.
- **The mark** moves whenever something its reader acts on changes on the server: the library's root, status, reader or scans pause, a scan asked for; its path filters, or the account's; any pause; any producer's settings, or a new version of one seen; failing clips asked to be tried again; a clip's preview, video preview or analysis proxy lost (the missing-file repair cleared it: `reader-work` lists it again). Never for the clips a reader's own scans make. It moves in the change's own transaction, so a reader that sees a new mark sees the change. When it isn't the one the reader has, the reader fetches what changed.
- **GET /v1/libraries/{library_id}/reader-changes** — Editors and admins, and the device that reads it. Query: `since` (the reader's mark; 0 for everything). Returns `{ "mark", "everything", "library": { "library_id", "name", "root_path", "reader", "status", "scans_paused", "scan_now" }, "filters": { "account": { "includes", "excludes" }, "library": { "includes", "excludes" } }, "made_with": { "<artifact>": { "producer", "version", "settings", "settings_hash" } }, "paused": { "work", "remakes" } }`: the path filters merged as Merged filter evaluation says; what each thing a reader makes (`lumiverb.preview`, `lumiverb.video.preview`, `lumiverb.video.format`, `lumiverb.capture_time`, `lumiverb.video.analysis_proxy`) is made with now, by name; which of what it makes from the originals is paused (`work`) or has its remakes stopped. A reader takes `made_with`'s settings only as typed values its version declares (ADR-018 decision 6): Lumiverb's own hold each to the setting's bounds, or for a quality to exactly what one of its choices stands for, and refuse anything else, a value or a key, making nothing of that producer and saying so in their log (`src/shared/producers.py` `checked`; for another version than theirs, their own defaults); while one is refused they ask again at every check-in. For now everything, whatever `since`, and `everything` says so: it can become only what changed without a reader changing. Never a copy of the library: which files there are is a scan's to compare, and what needs the originals is `reader-work` (Scans API). A scan takes its filters from here. 404 for an unknown library.
- **POST /v1/libraries/{library_id}/scan-now** — Editors and admins. Asks the library's reader for a scan of the whole library, at its next check-in (`scan_now`). Asked again before it's done, the first ask stands. A scan of the whole library, every media type, not a dry run, started after the ask answers it at its finish. 204; 404 unknown; 409 `library_trashed`; 409 `scans_paused` while its scans are paused. Library settings › Scans.

## Uploads API

A clip's video preview or analysis proxy in chunks that survive a dropped connection (ADR-018 decision 9; `src/server/uploads.py`, `routers/uploads.py`; its client `src/processing/uploads.py`, which the scheduler sends its analysis proxies with). Editors and admins (403 for a viewer), and the device that reads the clip's library; another account's upload is a 404. Every call is safe to send again. A single request (`POST /v1/assets/{id}/artifacts/{type}`) still takes either, and every picture.

- **POST /v1/assets/{asset_id}/uploads** — Body: `{ "artifact": "lumiverb.video.preview" | "lumiverb.video.analysis_proxy", "size", "sha256", "lineage" }`: the file's size in bytes (at most 64 GiB), its SHA-256 (64 lowercase hex digits, checked at the finish) and how it was made (as a single upload's `lineage`; 422 `lineage_required` otherwise). Returns `{ "upload_id", "artifact", "size", "received", "chunk_url", "chunk_size", "max_chunk", "expires_at", "finished" }`. The open upload of the same file for the clip and artifact (same size and hash), if there is one, with what it has so far (`received`): a client that restarted starts again and goes on from there, keeping nothing of its own. `chunk_url` is where the chunks go; `chunk_size` the size the server suggests, `max_chunk` the most it takes. 404 unknown clip (or one out of sight), 400 not a video.
- **PUT {chunk_url}** (`/v1/uploads/{upload_id}`) — Query: `offset`, where in the file the chunk begins. Body: the chunk's bytes (`application/octet-stream`), at most `max_chunk`. The server counts bytes, not chunks: what's new in the chunk is added, so one sent again adds nothing, and a later one may be another size. Returns `{ "received" }`. 409 `upload_gap` (`details.received`) for a chunk beginning past what the server has (send from `received`); 413 past `max_chunk` or the file's size; 404 for no such upload (another account's too) and 409 `upload_finished` once it's kept, both before a byte of the chunk is read.
- **GET /v1/uploads/{upload_id}** — Where it is: as the start answers.
- **POST /v1/uploads/{upload_id}/finish** — Keeps it: every byte there (409 `upload_incomplete`, `details.received` and `size`, before), the bytes the file said (422 `upload_damaged` otherwise: the upload is dropped, start again), then checked and rewritten as a single upload is (422 `video_not_playable`, dropped too; What the server takes) and kept on the clip with its lineage. Returns `{ "key", "sha256", "duration_sec" }`; sent again, the answer the first got.
- **DELETE /v1/uploads/{upload_id}** — Drops it and its bytes. 204; 404 when there's none.

An upload waits in the server's own folder (`DATA_DIR/uploads/<account>/`) and expires a day after its last chunk; `POST /v1/upkeep` deletes it and its bytes (`expired_uploads.deleted`), and bytes no upload claims a day on.

## Writing a client: a library's reader

This reference is a client's whole contract with the server (ADR-020 decision 9): nothing depends on a client being Lumiverb's own code. A client may share none of it, or simulate a library with no files at all. What arrives is a claim, checked where it can be, and the server never assumes an original exists. `lumiverb scan` and the scheduler's scans are one such client (`src/processing/scan.py` `run_scan`), and `lumiverb device run` the whole of one, a device's (`src/processing/device.py`). Whatever reads a library's files does this:

1. **Its key.** A device's key (Devices API), sent as `Authorization: Bearer <key>`: it does all of this for the libraries the device reads, and nothing else (Roles). Or a person's (API Keys): scans, ingest and uploads are editors' writes; checking in as this server's reader is an admin's.
2. **What it reads.** The libraries naming it as their reader (`PUT /v1/libraries/{id}/reader`), as its check-in answers with them (Readers API; a person's key: `GET /v1/libraries`, those whose `reader` is `server`; another reader's scans are refused, 409 `not_the_reader`): a library's `root_path` is the folder as the server keeps it, and where that is on the client's machine is the client's own business. Then its filters, the account's and the library's: `GET /v1/libraries/{id}/reader-changes` (Readers API), merged as Merged filter evaluation says (ingest refuses a path they leave out). A library's media are its files with one of these extensions, compared lowercase:
   - Images: `.arw` `.bmp` `.cr2` `.cr3` `.crw` `.dng` `.heic` `.heif` `.jpeg` `.jpg` `.nef` `.nrw` `.orf` `.png` `.raf` `.raw` `.rw2` `.rwl` `.sr2` `.srf` `.tif` `.tiff` `.webp`
   - Videos: `.mkv` `.mov` `.mp4`

   Hidden files count. Links aren't followed. A name with a control character, or a path that breaks the `rel_path` rule (Assets API), is never sent: the server refuses it.
3. **Its check-in** (Readers API), every minute or so, a long scan or render too (the server says a reader it hasn't heard from in 5 minutes is quiet): how each library is and what its scan has left to send, and the libraries it reads with their marks. When a library's mark moves, fetch what changed (`reader-changes`); when `scan_now`, scan all of it. Speak `protocol` 2: the server's lists are in names (Names); protocol 1 is 426.
4. **The scan** (Scans API), with the path filters `reader-changes` gives.
   1. Start the scan.
   2. Send `found`: every media file in scope, with its size and modified time (ISO 8601 with its zone). Mark `settling` a file modified in the last 30 seconds: it may still be copying. A modified time minutes ahead is a camera's clock, not a copy.
   3. Ask for the `plan`, naming the folders it couldn't list in `unlisted`.
   4. Hash the files planned `hash` (Content hashes; `previous_hash` too when the plan says `legacy`) and send them to `hashes`.
   5. Answer `moves` if they were asked about.
   6. Before answering moves or finishing, check the library's storage is still there: an unmounted share is an empty folder, and the server can't tell.
   7. `finish`.

   Every call but the start is safe to send again.
5. **Uploads**, after the finish: one `POST /v1/ingest` for each file planned or decided `upload`, and each in the `upload` that `moves` answered (Ingest API).
   - `lumiverb.preview`: its preview (below). With it: `library_id`, `rel_path`, `file_size`, `file_mtime`, `media_type` (`image` or `video`, as its extension says), and `width` and `height`, the original's.
   - `exif`, a JSON object. Every field is optional, but send `content_hash`: without it the server can't tell the same file from a changed one at that path.
     - `content_hash`, the file's (Content hashes), and `previous_hash`, the whole file's `sha256:` when the plan said `legacy`;
     - `exif`: the file's tags, as read;
     - `camera_make`, `camera_model`, `lens_model`;
     - `taken_at`: the camera's wall clock, ISO 8601 with no zone (ADR-017), and `taken_at_offset_min`, its zone when the file says (minutes east of UTC);
     - `gps_lat`, `gps_lon` ((0, 0) is no fix) and `gps_accuracy_m`;
     - `duration_sec`, `iso`, `exposure_time_us`, `aperture`, `focal_length`, `focal_length_35mm`, `flash_fired`, `orientation`;
     - `live_photo_id`: the Live Photo it's part of, Apple's content identifier (exiftool's `ContentIdentifier`: an iPhone photo's maker notes, its .mov's QuickTime keys), letters, digits and dashes up to 64, or `null` when the file has none. Sent, it's what the file says (`null` clears one kept); left out, what's kept stays. A video and a photo of its library with the same one are one clip, the photo (Assets API: `live_photo`).
   - `lineage`, a JSON object by the name of each artifact (Names), each `{ "producer", "version", "settings_hash", "source_hash" }` as `GET /v1/producers` gives them (Producers API), `producer` the name of what it makes and `source_hash` the file's content hash. `lumiverb.preview` always. `lumiverb.capture_time` when the capture facts in `exif` were read as the capture producer reads them: without it they're stored, but the capture producer counts them as not made. `lumiverb.live_photo` with `live_photo_id`, the same way. `lumiverb.video.format` with a `video_facet`.
   - A video: `video_facet`, its probe (the shape `PUT /v1/assets/{id}/video-facet` takes), then its preview: `POST /v1/assets/{id}/artifacts/lumiverb.video.preview`, with its lineage. A big video (an analysis proxy) goes in chunks that survive a dropped connection (Uploads API).
6. **What only the reader can make**, listed by `GET /v1/libraries/{id}/reader-work` (Scans API): previews that are missing, a video's probe, capture facts, Live Photo identifiers and analysis proxies, and their remakes. For a library this server reads, its scans make the previews again and its scheduler the rest. A device sends the rest with its own key: a video's probe (`PUT /v1/assets/{id}/video-facet`), capture facts (`PUT /v1/assets/{id}/capture`), Live Photo identifiers (`PUT /v1/assets/{id}/live-photo`) and analysis proxies (Uploads API); from ADR-018 phase 6 this server's scheduler leaves them to it. The quality notches and the remake choice come with phase 7.

### What the server takes

- **Pictures.** A preview (`lumiverb.preview` at ingest; the `lumiverb.preview`, `lumiverb.preview.thumbnail` and `lumiverb.video.scenes.picture` uploads) and a search's image:
  - JPEG, PNG or WebP, of at most 120 megapixels: nothing else is read (`src/server/images.py`). At most 10 MB at ingest.
  - Every one is re-encoded (`src/server/preview_image.py`): its rotation applied to the pixels, its colour profile kept, every other tag dropped.
  - A proxy is kept as WebP, at most 2,048 px on its long edge: send it at 2,048 px (one smaller stays smaller). The server makes the thumbnail from it, WebP at 512 px. A scene frame is kept as JPEG.
  - A video's proxy is one frame of it; Lumiverb's scan uses the first.
- **Videos** (`lumiverb.video.preview`, `lumiverb.video.analysis_proxy`), sent as `video/*`: the web player streams them as they are, so they're what every browser plays (ADR-018 decision 11, `tests/test_browser_playable_video.py`).
  - H.264, 8-bit 4:2:0 (`yuv420p`), limited range, at most High profile. A full-range source (some drones') is converted, not just relabelled.
  - AAC-LC, at most two channels a track.
  - MP4 with its index (`moov`) before the media (`+faststart`), video and audio tracks only.
  - No metadata: a phone's video says where it was taken.
  - A video preview is its start, made with the account's `lumiverb.video.preview` settings (by default its first 10 seconds, at most 720 px high).
  - An analysis proxy is the whole video, made with the account's `lumiverb.video.analysis_proxy` settings (`GET /v1/producers`: by default at most 960 px on its long edge and 30 frames a second). Its keyframes are at 0 and every 2 seconds after, and nowhere else: scenes are found from its keyframes alone. Every audio track is kept, after a stereo mix of them all when there are several.
  - Up to 100 MB an upload; an analysis proxy up to 64 GiB.
  - The server checks each one as it arrives, read only as an MP4 or QuickTime file (`src/server/uploaded_video.py`): one video track, H.264 at most High profile, 8-bit 4:2:0, limited range, at most 4096 px on an edge; each audio track AAC-LC, at most two channels; a length. Anything else is a 422 `video_not_playable` (`details.problems`), and nothing of it is kept. What's kept is its rewrite, a stream copy (nothing decoded): MP4, its index first, its one video track and its audio tracks only (a timecode or data track is left out), and none of its metadata, the file's, a track's or a chapter's (a phone's says where it was taken). Its length is the server's measure. The same video sent again is kept the same, byte for byte.
- **Hashes:** Content hashes. **Paths:** the `rel_path` rule (Assets API), in Unicode NFC.

## Plug-ins API

Optional parts of Lumiverb that an account turns on (ADR-021, ADR-023), each a program of its own installed on this server. Lumiverb's own are programs like any other, shipped in `src/own_plugins/<id>/` and installed by Lumiverb itself as the last step of migrating (and again by the plug-in runner as it starts): one not installed, or older than the one shipped, is installed off by default, recorded as by `lumiverb`, what it reads and reaches accepted with Lumiverb (an update keeps the server admin's default and what they accepted; one they uninstalled stays uninstalled until they install it again; one that can't be installed is said, kept with why and shown on the Admin page, and tried at the next start). Others are programs of their own that the server admin installs on the machine (`lumiverb-server plugins install FOLDER --on|--off`, each with its manifest, `lumiverb-plugin.json`: what it reads and reaches, shown and accepted first), on or off by default: an account follows the default until its admin turns the plug-in on or off there, and after that its admin's choice stands. On by default, its acknowledgment (if any) is accepted by the server admin for the accounts following the default. One can declare an **acknowledgment**: what an admin reads and accepts first, such as a license, with a version. Every acceptance is kept for good: the plug-in, the version, who and when. When the text changes in a release, its version goes up (numbers with dots, compared as numbers). An earlier acceptance still stands unless the plug-in says the new text must be accepted again (its terms changed); then it's off (`waiting`) in every account that accepted an earlier version until an admin accepts the new text. `acknowledged.version` is the version accepted, which may be earlier than `acknowledgment.version`.

- **GET /v1/plugins** — Signed in (401 on a public page). `{ "plugins": [{ "plugin_id", "title", "description", "state": "on" | "off" | "waiting", "acknowledgment": { "version", "title", "text", "links": [{ "label", "url" }] } | null, "acknowledged": { "version", "by", "at" } | null, "kind": "installed", "version", "author", "homepage", "on_by_default", "follows_default", "reads": [string], "answers": [string], "lookups": [string], "downloads": [{ "url", "title", "about_mb" }], "internet", "running": { "state": "starting" | "ready" | "preparing" | "failing" | "restarting" | "stopped" | "off" | "not_running", "why", "detail", "done", "total", "since", "memory_mb", "restarts" } | null }] }`, by title. `kind` is always `installed` (every plug-in is since ADR-023 phase 3; ADR-021's `built_in` and their `data` are gone). Each one's `version`, `author` and `homepage`, its default (`on_by_default`) and whether this account follows it (`follows_default`: its admin hasn't turned it on or off here), what it reads and answers in words (`reads`: "each clip's location (…)"; `answers`: "answers place searches (…)") and the lookups it answers by name (`lookups`: `"places"`, Set location's Place search), what it downloads and whether it uses the internet. Following a default that's on, `acknowledged` is the server admin's acceptance (`by` null). `running` is what the plug-in runner last said of its process: `starting`; `ready` (perhaps with work in the background, as a newer list fetched while the old one answers: `done` of `total`, `detail`); `preparing` (`done` of `total`, `detail`: what it says it's doing); `failing` (it says it can't work, `why` its words); `restarting` (it stopped, `why`, and is started again soon: waiting longer each time it stops soon after starting); `stopped` (left stopped, `why`: it kept stopping, its data folder outgrew its `disk_mb`, or its program isn't there; installing it again tries again); `off` (on in no account, so not run: the runner starts a plug-in only while it's on by default or turned on in some account, and stops it when the last account turns it off; `why` says so); `not_running` (the runner isn't, or hasn't started it yet: `why`). `memory_mb` is what it used when last looked at (more than its manifest's `memory_mb` ends it), `restarts` how many times it was started again. `text` is paragraphs separated by a blank line. `acknowledged` is the acceptance it's on by (or waiting with), null while it's off; `by` is who (an email) for account admins only, null for others and for an API key.
- **GET /v1/plugins/kept** — Signed in. The plug-ins the server admin uninstalled with what they made kept (`lumiverb-server plugins uninstall ID --keep`) that made facts in this account: `{ "plugins": [{ "plugin_id", "title", "version", "removed_at", "clips" }] }`, by title (`clips`: those it made facts for here). Their facts are shown and searched as they were (`facts`' `removed` true), made no more.
- **DELETE /v1/plugins/{plugin_id}/facts** — Account admin. Query: `count`. A kept plug-in's facts deleted from this account for good, with everything else it left here (lineage, settings, switch; who accepted its acknowledgment is kept), as the server admin's `--delete` does for every account. 409 `confirm_delete_facts` (`details`: `count`, `title`) until `count` is the number of clips it made facts for here (Decisions the API requires). 404 for a plug-in that isn't one uninstalled with what it made kept. Returns `{ "deleted" }`, the clips.
- **PUT /v1/plugins/{plugin_id}** — Account admin (403 otherwise; 404 for no such plug-in). Body: `{ "enabled": bool, "acknowledged": "<version>" }`. Turning on a plug-in that asks an acknowledgment is a 409 `acknowledgment_required` (Decisions the API requires) until `acknowledged` is its version now. Every turn-on asks, including after it was turned off. Accepting is kept. Turning it off, or on while it's off, makes it this account's choice, which a default changed later doesn't change (`follows_default` false). Already on (by its default too): nothing changes. Off asks nothing; what it made and keeps stays. Returns the plug-in as GET lists it.
- **PUT /v1/plugins/{plugin_id}/settings** — Account admin. A plug-in's settings for this account (404 for no such plug-in). Body: `{ "settings": { "<key>": value | null } }`: each setting it changes, a value or `null` (back to its default; a secret: cleared); others stay. Each value is checked by its manifest's schema (type, bounds, pattern, length, choices) before it's saved; then, when its manifest says it checks them itself (`check_settings`) and it's running, the plug-in is asked (`POST /v1/settings/check` on its socket, with every value). Anything refused is 422 `invalid_settings`, `details.errors` by key (`details.by_plugin`: the plug-in said so), and nothing is saved. Returns the plug-in as GET lists it, with `unchecked`: why the plug-in's own check didn't run (it isn't running), the settings saved meanwhile; null when it ran or it doesn't check. A change of a setting that remakes (its manifest's `remakes`, an account's, never a secret: its work's lineage holds it) asks what becomes of what the old settings made, as a producer's settings do: 409 `redo_on_change` (details: `clips`, question `remake`) until the body says `"redo"`: `true` remakes them too, after everything else; `false` is new ones only, its redo stopped by this person until someone remakes them. Nothing made yet asks nothing.
- **PUT /v1/plugins/{plugin_id}/server-settings** — Server admin (403 `server_admin_required` otherwise). The same, for its settings of the server's scope (one value for every account: a mirror, a key for a service the whole install uses).
- **POST /v1/plugins/{plugin_id}/inputs** — Account admin (the scheduler's key; 404 for a plug-in with no work). An installed plug-in's work (ADR-023 phase 2): body `{ "asset_ids": [...] }` (1 to 500). Returns `{ "clips": { "<asset_id>": { "inputs": { … }, "inputs_hash" } } }`, each clip in sight it applies to now (on in this account, its media, every input it declares); the rest are left out. Its inputs are those its manifest declares and nothing else (`src/server/repository/clip_inputs.py`): `location` `{ "lat", "lon", "sure_m", "source": "person" | "file" | "guess" }` (the location the clip shows: a person's, else its GPS, else an applied guess; how sure, in meters), `capture_time` `{ "utc", "offset_min" }` (ISO 8601 UTC; its time zone's offset when known), `metadata` `{ "media_type", "width", "height", "duration_sec", "camera_make", "camera_model", "lens" }`; a photo's `preview` the scheduler hands it from what's stored. `inputs_hash`: their hash, sent back with what it made of them. 409 `plugin_off` while it's off here.
- **POST /v1/plugins/{plugin_id}/outputs** — Account admin (the scheduler's key). Body `{ "items": [{ "asset_id", "inputs_hash", "outputs": { "<key>": { "text", "url" } | null }, "source_hash" }], "lineage" }` (up to 500): what its work gave back, each output a fact (plain text up to 200 characters, an optional http(s) link) or null, nothing to say. Every output it declares is checked first: one it didn't, HTML, a control character, text too long or a link that isn't http(s) is 422 `invalid_outputs` (`details`: `asset_id`, `why`) and nothing is saved. `lineage` as any machine write's (422 `lineage_required`, `lineage_wrong_producer`). A clip whose inputs aren't what they were when they were handed out (`inputs_hash` differs: a person moved it) is `stale`, nothing written (it's due again, and keeps what it had until then); one out of sight or no longer one it applies to is `gone`. Returns `{ "saved", "stale": [...], "gone": [...] }`. 409 `plugin_off` when it was turned off meanwhile. What's saved shows with the clip (`GET /v1/assets/{id}`'s `facts`: `[{ "plugin_id", "title", "credit": { "text", "url", "license": { "text", "url" } | null } | null, "removed", "facts": [{ "key", "label", "text", "url", "empty" }] }]`; `removed` true for a plug-in the server admin uninstalled with what it made kept, shown and searched as it was (made no more); an output with nothing to say is its manifest's empty line when it declares one, `empty` true, never searched, else left out; shown and searched only while the clip is one of its media and has every input it reads (a clip whose location was cleared shows none, and what was made is kept); each plug-in on in the account that made it a fact, in title order, its facts in its manifest's order, one with nothing to say left out; made from inputs the clip has changed since, it shows until the new ones are saved; signed-in only, never on a public page), and the text of those its manifest says are `searchable` is searched (Search). Turned off, a plug-in's facts are hidden and not searched, and kept: on again, they show.
- GET's `settings`: `[{ "key", "type": "int" | "float" | "bool" | "text" | "choice" | "secret", "label", "help", "default", "value", "set", "minimum", "maximum", "unit", "pattern", "max_length", "choices": [{ "value", "label" }], "scope": "account" | "server", "advanced", "remakes", "editable", "readable" }]`, its manifest's order: the account's, and for a server admin the server's too. A secret's `default` and `value` are always null (it's never shown again), `set` says whether it's set, and `readable` false for one set that this install can't read (sealed by another install's key: a backup restored elsewhere without its env file), to be set again (true for every other setting); a secret is kept sealed with the install's key (`src/server/sealing.py`) and opened only to be handed to the plug-in, one that can't be read handed on as its default; for the rest `set` says whether it was chosen rather than left at its default. `editable`: whether the caller may change it (an account's: its admins; the server's: server admins). `remakes`: changing it will make what the plug-in made again (once plug-ins make things, ADR-023 phase 2).
- What a plug-in adds answers 409 `plugin_off` while it's off in the account (`details`: `plugin_id`, `title`): say where it's turned on (Settings › Plug-ins).
- `lumiverb plugins list`; `lumiverb plugins enable ID` (prints the text and asks; `--accept`, prints it and accepts); `lumiverb plugins disable ID`.

The plug-ins:
- **`geonames`, Place names (GeoNames):** Lumiverb's own (`src/own_plugins/geonames/`, ADR-023 phase 3: a program speaking the plug-in protocol, Python's standard library run with the machine's `python3`). It finds a place by name when setting a location, and names where each clip was: the landmark it's at and the nearest town (ADR-017 phase 4). Its acknowledgment is GeoNames' CC BY 4.0 license (version 3: an acceptance of version 1 or 2 stands, the license being the same), its credit GeoNames with that license. What it keeps for itself, in its data folder: GeoNames' towns of 1,000 people or more with their regions and countries, its landmarks (the kinds in `src/own_plugins/geonames/landmarks.py` with a Wikipedia article, some kinds every one), and their names in other languages for search, a SQLite list built from about 600 MB of GeoNames' files fetched from `download.geonames.org` (or its server setting `mirror`; an install's `LUMIVERB_GEONAMES_URL` becomes it once, when Lumiverb first installs it) only once it's started with none: the runner starts it only while it's on in some account, so nothing is fetched before an admin has accepted the license. Nothing about anyone's photos is sent. Its settings: `radius_km` (the account's: the nearest town within, 25 km; it remakes; carried over from the built-in Place names producer's), `mirror` (the server's). Version 2 (ADR-023 phase 3 part 4) searches `at` as well as `near` (Robert, 2026-10-19: people search by landmarks more than towns): its work's version stays 1, so nothing is named again, and the search sweep writes the text of the clips it named before again (Upkeep API's `facts_synced`).
  - Its places (`GET /v1/places`): `place_id` `"geonames:<GeoNames' id>"`, each with its `kind` (a landmark's, `"amusement park"`, `population` 0; null for a town) and `matched` (the name in another language it was found by when its own didn't match, English first where several do: `"Eiffel Tower"` for Tour Eiffel); ranked by how well a place's best name matched (exactly its own or English name, the app's language; exactly another; its own or English name starts so; another does), then the most populous, landmarks after towns, the best known first (the most other names). `"name, where"` narrows it to a region or country starting so, or a country's code. A full tie (the same name match and population) goes to the lowest id; two other names of one place equally good show the first by their characters' code points, as a Mac's database (locale C) did.
  - Its work (`geonames`): each clip with a location (a person's, else the file's GPS, else an applied guess), its facts `landmark` (`geonames.landmark`, ADR-024: the landmark it's at, within its kind's reach of its point, a building's 250 m, a site's 500 m, a mountain's 1 km, a park's 1.5 km, the nearest for its reach, for a location as sure; its name when a town is near, else its label, which says where; `at` before version 3) and `town` (`geonames.town`: the nearest town within `radius_km`, its label; with none that near, its empty line "Not near a town"; `near` before version 3), both searchable: search finds a clip by the landmark it's at and the town it's near. The Lightbox shows them in its section, "Place names (GeoNames)", credited with the license.
  - **The built-in Place names** (ADR-021) is gone since part 4: its list (the control database's `geonames_*`), its names on clips (`asset_place`, the detail's `place`) and its fallbacks. Its producer's routes, **POST /v1/places/nearest** and **POST /v1/places/names**, answer 410 `gone`, naming an installed plug-in's work (`POST /v1/plugins/{plugin_id}/inputs` and `/outputs`). A location set from one of its places keeps its place, label and credit (`basis.place.credit`, kept with every location set from a place since part 3).
- **GET /v1/places** — Signed in. Query: `q` (1 to 200 characters: a name's start; `"name, where"` narrows it to a region or country starting so, or a country's code), `limit` (1 to 25, default 10). Every plug-in on here that finds places (its manifest's `lookups` has `places`, ADR-023 phase 2d; GeoNames among them) is asked, in title order, each up to `limit` as it ranks them: `{ "places": [{ "place_id": "<plugin_id>:<its id>", "name", "region", "country", "label", "lat", "lon", "population", "kind", "matched", "source", "source_title" }], "credit": null, "credits": [{ "source", "text", "url", "license": { "text", "url" } | null }], "unavailable": [{ "plugin_id", "title", "why" }] }`. `credits` is each source's whose places are among them, to show beside them with the license its data is under when it names one (GeoNames' CC BY 4.0); `credit` is always null (it was GeoNames' alone before ADR-023 phase 3). `unavailable` is the plug-ins that couldn't answer now (not running, fetching their first list, no answer within 3 s, or places the protocol doesn't allow), the others' places standing. 409 `plugin_off` while no plug-in that finds places is on here, its message saying why: `details.plugins` `[{ "plugin_id", "title" }]`, those installed that would (off here), empty when none is installed (the server admin installs one). Set location says it under Place, which it always offers.

## Libraries API

All under `/v1/libraries`; require tenant auth (middleware). Renaming and trashing are an editor's of the library. Its Scans pause, who can see it (`private`), whether its locations are guessed (`infer_location`) and its people are its admin's (an account admin is every library's; ADR-018 decision 8); creating a library, making one public (`is_public`), choosing its folder (`root_path`) and who reads it (its reader) are an account admin's (Robert, Oct 10; the folder and reader since Oct 22: a folder or a device is the account's to give, as on creating one), at creation as on PATCH, and a PATCH whose body has a field that isn't the caller's is a 403 (`forbidden` for an account admin's, `library_admin_required` for the library admin's). A key a person made never acts above its own role, so a library's admin who isn't an account admin runs it signed in.

- **POST /v1/libraries** — Admin (403 for an editor or viewer). Body: `{ "name", "root_path", "is_public", "reader", "private", "infer_location" }` (`is_public` optional, default false; `private` optional, default false: only account admins and the people given a role on it see it; `infer_location` optional, default false: its clips without a location are guessed from those taken around the same time, ADR-017; `reader` optional, `"server"` by default, or a registered device's id: 404 `device_not_found` for one that isn't; with a device, `root_path` is the folder as the device sees it, and it's chosen from anywhere, never read here). `root_path` must be absolute, with no `.`, `..` or empty part (no trailing `/`), no backslash and no control character (a newline, a tab, NUL or DEL) (400 otherwise; the same for PATCH). Read by this server, it's in one of the account's folders when a server admin gave it any (`GET /v1/tenant/settings`' `folders`; equal to one or inside it, by whole parts: `/a/bc` isn't in `/a/b`): 403 `outside_account_folders` otherwise, `details.folders` the account's folders and a message saying them ("This account's folders are …: choose one inside them, or ask a server admin."). The same on PATCH and `PUT .../reader`. A device's library isn't held to them: its folder is on the account's own computer. Name must be unique per tenant (409 if duplicate). New libraries inherit the tenant's path filter defaults at creation time (subsequent changes to defaults do not affect existing libraries). Returns `{ "library_id", "name", "root_path", "scan_status", "is_public", "reader", "reader_name" }` (scan_status initially `"idle"`, is_public initially `false`; `reader_name`: the reader device's name, null for this server, as every library answer says it).
- **GET /v1/libraries** — Query: `include_trashed` (optional, default false). Returns list of libraries with `library_id`, `name`, `root_path`, `scan_status`, `last_scan_at`, `status` (`"active"` or `"trashed"`), `is_public`, `trashed_at` (in the trash since; its trash days count from here), `revision` (the counter `/revision` reports, so a page across libraries can follow them all from this list), `reader` (who reads its files: `"server"`, this server, for every library until devices come; ADR-018 phase 1), `scans_paused` (its own Scans pause; Pause all isn't said here: `GET /v1/producers/queue`'s `libraries` says both, and who paused), `scan_requested_at` (a scan of the whole library asked for, Scan now, until one started after it finishes; Readers API), `checked_in` (its reader's latest check-in: `{ "client", "version", "state", "waiting_files", "waiting_bytes", "last_full_scan_at", "checked_in_at", "remakes_held" }`, null before the first; Readers API), `private`, `infer_location` (its clips' locations are guessed: Location guesses, ADR-017), and `role` (the caller's role on it: `admin`, its admin, `editor` or `viewer`; ADR-018 decision 8). Only the libraries the caller can see. Trashed libraries excluded unless `include_trashed=true`. `GET`, `POST` and `PATCH /v1/libraries/{id}` return `reader`, `private`, `infer_location` and `role` too.
- **POST /v1/libraries/scans/pause**, **POST /v1/libraries/scans/resume** — The admin of each library named; `all` an account admin's. A library's own Scans pause (ADR-018 phase 1: was the account's Scans switch). Body: `{ "library_ids": [...] }` (those libraries) or `{ "all": true }` (every one); neither or both is a 400 `scope_required`, an unknown library a 404. Pausing: no new or changed files are found in it, so neither thumbnails nor video previews are made, and changes reported meanwhile wait; every other kind of work goes on; a scan running finishes; again is fine (who paused first, and when, stays). Resuming while Pause all is on scans these libraries again and leaves every switch and every other library paused, each on its own. Resume all (`POST /v1/producers/all/resume`) resumes every library's scans too. 204. `lumiverb pause|resume scans` (every library) or `scans --library NAME`.
- **GET /v1/libraries/{library_id}** — Returns single library. 404 if not found.
- **GET /v1/libraries/{library_id}/people** — Its admin's (403 `library_admin_required` otherwise). Who can see and edit it: `{ "library_id", "private", "people": [{ "user_id", "email", "account_role", "every_library", "role", "set_role", "set_by", "set_at" }] }`, everyone in the account with their role on it now (`admin`, `editor`, `viewer` or `none`) and the role set for them here (`set_role`; null when the rule gives it: see Roles). `lumiverb library people --name NAME`.
- **PUT /v1/libraries/{library_id}/people/{user_id}** — Its admin's. Body: `{ "role": "admin" | "editor" | "viewer" | "none" | null }`: their role on this library, above or below their account role (`none`: they don't see it); null, the rule's again. Takes effect on their next request. Returns the person as GET lists them. 404 for someone not in the account; 409 `account_admin` for an account admin (every library's admin); 403 `server_admin_user` for a server admin, unless a server admin asks (whoever holds their password has the install, as for the Users API). `lumiverb library role --name NAME --email EMAIL --role ROLE|default`; `lumiverb library private --name NAME --on|--off`; `lumiverb user libraries --email EMAIL --every|--only-given`.
- **GET /v1/libraries/{library_id}/ignored-paths** — Retired: 410 `gone` (signed in only, as it was: 401 for a public page's visitor). It listed the files a person trashed, archived or deleted for good, for a scanner to skip; a scan's plan skips them on the server now (Scans API, ADR-018: `skipped`, reason `removed`), and `details.replaced_by` names it.
- **DELETE /v1/libraries/{library_id}/ignored-paths** — Retired: 410 `gone` (an editor's, as it was). It forgot emptied-trash records; a scan started with `force_add` (`lumiverb scan --force-add`) adds the files a person removed and forgets those deleted for good (`replaced_by`: `POST /v1/libraries/{library_id}/scans`).
- **PATCH /v1/libraries/{library_id}** — Editor; `private` and `infer_location` are its admin's, `root_path` and `is_public` an account admin's (above: 403 `forbidden` for anyone else, the library's own admin too). A new `root_path` for a library this server reads is in the account's folders (403 `outside_account_folders`, above). Body: `{ "name", "root_path", "is_public", "private", "infer_location", "remove_guesses" }` (all optional). Updates library name, root path, public visibility, who sees it, and/or whether its clips' locations are guessed (Location guesses). Turning `infer_location` off removes the library's guesses and the producer's tries (a location a person set stays): 409 `guesses_exist` (`details.clips`: how many of its clips have a guess, in sight or not) unless `remove_guesses: true`; with none, nothing is asked. Turning it on makes its clips due. `lumiverb library infer-location --name NAME --on|--off [--yes]`. Use `root_path` to repoint a library after moving source files on disk — existing assets match by `rel_path` so the directory structure must be preserved. Setting `is_public: true` inserts a row in the `public_libraries` control plane table, enabling unauthenticated access. Setting `is_public: false` removes it. Returns full library response including `is_public`.
- **PUT /v1/libraries/{library_id}/reader** — Account admin (403 `forbidden` for anyone else, the library's own admin too). Who reads the library's files (ADR-018 decision 1): this server or a registered device, never both at once. Body: `{ "reader": "server" | "<device_id>", "root_path"?: string }` (`root_path`: the folder as the new reader sees it, as `POST /v1/libraries` takes it; left out, it stays). From the next check-ins, the new reader's lists the library and the old one's says it's `gone` (Readers API); the new reader scans it and makes what needs its originals (probing, capture, analysis proxies), and the old one's scans of it are refused (409 `not_the_reader`), even one it started before. Everything made from previews and analysis proxies (search, faces, descriptions, scenes, transcripts) is this server's whoever reads it. Handed to this server, its folder is chosen here (403 `folder_elsewhere` as on creating one), in the account's folders (403 `outside_account_folders` as on creating one: the `root_path` given, else its folder as it is). Returns the library. 404 for none, 404 `device_not_found`, 409 `library_trashed`; a device's key, 403 `not_for_devices`. A device can't be removed while a library names it (Devices API).
- **DELETE /v1/libraries/{library_id}** — Editor. Move the library to the trash with everything in it: `status` `"trashed"`, `trashed_at` now, clips in sight soft-deleted with `deleted_reason = "library"` (archived and trashed clips keep their reasons). Deleted for good after the trash days, with everything in it. If the library was public, removes its `public_libraries` control plane row. Body (optional): `{ "remove_from_projects": false }`; 409 `in_projects` (see Decisions) when any of its clips are in projects, unless it's true: in the trash they're hidden there, and deleted for good they leave them. Returns 204 on success, 404 if not found, 409 if already trashed.
- **POST /v1/libraries/{library_id}/restore** — Editor. Take the library out of the trash with the clips that went with it (`library`); clips trashed or archived before it went stay as they were, and those in a person's trash get their full trash days again. It comes back private. Returns the library; 404 if not found, 409 `not_trashed`.
- **POST /v1/libraries/empty-trash** — Admin (deleting media for good right away is an admin's; editors trash and restore). Delete trashed libraries for good (cascade: asset_metadata, asset_embeddings, video_scenes, video_index_chunks, assets, library_path_filters, libraries); once that's committed, each library's previews folder goes from every folder previews may be in, and its own folder's choice is forgotten (one on a drive not plugged in, or while previews move, stays: the daily cleanup reports it). Removes `public_libraries` control plane rows for any that were public. Body: `{ "library_ids": [...] }` (those libraries) or `{ "all": true }` (every one in the trash), with `"remove_from_projects": false`; neither or both is a 400 `scope_required`, no body a 422. 409 `in_projects` (see Decisions) when their clips are in projects, unless `remove_from_projects` is true. Returns `{ "deleted": N }`.
- **GET /v1/libraries/health** — Bulk health indicator. Returns `[{ "library_id", "healthy", "pending" }]` for every non-trashed library, in a single SQL call. `pending` is the number of assets with outstanding work (missing proxy, or anything the reconciler would hand the worker, including failures waiting their turn). `healthy` is `pending == 0`. Used by the libraries page to render a green/orange dot per library without N+1ing `/v1/assets/repair-summary`.
- **GET /v1/libraries/{library_id}/revision** — Lightweight polling endpoint. Returns `{ "library_id", "revision", "asset_count" }`. The `revision` counter increments atomically on asset create/update (ingest) and vision metadata submission. The web app polls this every 10 seconds and, when it changes, refetches the open grid, its facets and folder counts: right away, then at most every 30 seconds while it keeps changing (a long ingest bumps it on every poll), then once more when it stops.
- **GET /v1/libraries/{library_id}/directory** — Query: `path_prefix` (optional). Returns list of subdirectories within a library root. Used by browse UI for directory navigation.

## Library path filters API

All under `/v1/libraries/{library_id}/filters`; require tenant auth and the **editor** role. Path filters control which files are included or excluded during library ingest (scanner). Patterns use `**`-style globs (case-insensitive); `**` matches across path segments. Validation rejects patterns containing `..` or null bytes, longer than 1,024 characters, or of more than 64 parts between slashes (`/` or `\`): 400 with the reason, by every route that takes a pattern (a filter, its preview, an account's default; `src/shared/path_filter.py` `validate_pattern`). A pattern is matched in time that grows with its parts times the path's, however many `**` it has, as each is matched against every file a scan walks and every clip a preview counts.

- **GET /v1/libraries/{library_id}/filters** — Returns `{ "includes": [{ "filter_id", "pattern", "created_at" }], "excludes": [...] }`. 404 if library not found.
- **POST /v1/libraries/{library_id}/filters** — Body: `{ "type": "include"|"exclude", "pattern": "...", "trash_matching": false, "remove_from_projects": false }`. Creates filter. When `trash_matching` is `true` and type is `exclude`, also moves every active asset matching the pattern to the trash (deleted for good after the trash days); 409 `in_projects` first when projects use them, and nothing is added until `remove_from_projects` is true. Returns 201 with `{ "filter_id", "type", "pattern", "created_at", "trashed_count" }`. 400 if pattern invalid, 404 if library not found.
- **POST /v1/libraries/{library_id}/filters/preview** — Body: `{ "type": "exclude", "pattern": "..." }`. Returns `{ "matching_asset_count": N }` — count of active assets matching the pattern. Used by UI to show confirmation before creating an exclude filter that would trash assets.
- **DELETE /v1/libraries/{library_id}/filters/{filter_id}** — Removes filter. Returns 204 on success, 404 if not found.

## Tenant filter defaults API

All under `/v1/tenant/filter-defaults`; reading them needs an **editor**, adding or removing one an **account admin** (403 otherwise): they reach every library's reader, so what every library's scans keep, and an editor may have no role on some libraries. Tenant defaults apply dynamically to all libraries via merged evaluation (see below).

- **GET /v1/tenant/filter-defaults** — Returns `{ "includes": [{ "default_id", "pattern", "created_at" }], "excludes": [...] }`.
- **POST /v1/tenant/filter-defaults** — Body: `{ "type": "include"|"exclude", "pattern": "..." }`. Creates default. Returns 201 with `{ "default_id", "type", "pattern", "created_at" }`. 400 if pattern invalid. Account admin (403 for an editor).
- **DELETE /v1/tenant/filter-defaults/{default_id}** — Removes default. Returns 204 on success, 404 if not found. Account admin (403 for an editor).

### Merged filter evaluation

Tenant defaults and library filters are merged at evaluation time with "library wins" priority:

1. **Library exclude** matches → **BLOCKED** (absolute, highest priority)
2. **Library include** matches → **ALLOWED** (overrides tenant restrictions)
3. **Tenant exclude** matches → **BLOCKED**
4. **Tenant includes exist** but path doesn't match any → **BLOCKED**
5. **Default** → **ALLOWED**

This is enforced both client-side (during filesystem walk for efficiency) and server-side (POST /v1/ingest returns 422 for filtered paths).

## Assets API

All under `/v1/assets`; require tenant auth. List/get endpoints return only active (non-trashed) assets.

- **POST /v1/assets/upsert** — Retired: 410 `gone` (editors, as it was; 403 for a viewer). It made or updated a clip from a scanner's word; a scan session decides what's new or changed on the server (Scans API, ADR-018), and a file becomes a clip when it's ingested (`POST /v1/ingest`), both named in `details.replaced_by`.

Every write that takes a `rel_path` (`POST /v1/ingest`, a scan's `found` and `hashes`) refuses one that would leave the library, or isn't in its one form, with 400: it must be relative (no leading `/`), with no `.`, `..` or empty part, no trailing `/`, no backslash, no drive letter (`C:`) and no control character in any name (C0, U+0000–U+001F, such as a newline, a tab or NUL; or DEL, U+007F). It's stored in Unicode NFC. Change reports hold their absolute paths to the same rule below `/`. Scans never send such a name: a scan (the scheduler's, or `lumiverb scan`: `src/processing/scan.py` `run_scan`) skips a file or folder whose name has a control character, and a file whose name breaks the rule otherwise, with a warning in its log.
- **GET /v1/assets/{asset_id}** — Return single asset with full detail (EXIF, video preview info, and `video_facet` for probed videos, else null). `ai_description`, `ai_tags` and `ocr_text` are what a person sees: what a person wrote, else the machine's; `corrected` lists which of `"description"`, `"tags"`, `"ocr_text"` a person wrote. `transcript_source` is `"manual"` for a person's transcript, else the machine that made it. `face_count`: the faces found in it (null: not looked for yet; a video's, the people seen; null for a public page's visitor). `live_photo`: it's a Live Photo, its playback plays the few seconds around it (`GET /v1/assets/{id}/playback`; a visitor's too). A public page's visitor (a public library's or a public project's) gets the trimmed visitor view: shape, time, length and what's seen or heard in it (`ai_description`, `ai_tags`, `ocr_text`, the transcript within the public cap, `video_facet`), never `rel_path` or `library_id` (empty), GPS, `gps_accuracy_m`, `location`, camera or exposure details, storage keys, notes, `corrected` or `transcript_source`. Same for `GET /v1/assets/by-path`. 404 if not found or trashed. Signed in, `location` is the clip's location beyond the file's GPS (ADR-017), or null: `{ "lat", "lon", "radius_m", "source": "person"|"time"|"suggestion", "status": "applied"|"suggested", "basis_summary", "set_by" (a person's: who set it, looked up from the stored user id when a signed-in person reads it; null for an API key), "set_at" }`. The location shown is a person's, then the file's (`gps_lat`/`gps_lon`), then an applied guess; a suggestion is only offered.
- **PATCH /v1/assets/{asset_id}/corrections** — Editors. A person writes a clip's description, OCR or tags. Body: any of `{ "description": str | null, "ocr_text": str | null, "tags": [str] | null }`; only the fields sent change. Edits keep only the latest (Robert, Oct 9): what a person writes is the one copy. The machine's value of that field is dropped, no machine copy is kept under it, and describing or reading the clip again never replaces it. `tags` is the whole list: the machine no longer changes it. An empty string or list is what the person wrote too (there's none). null removes what they wrote: none is left, and the clip's description (or OCR) is missing again, so the machine makes it again (removing the description or tags drops the machine's description too, made again with them). Stored in `asset_corrections`; search documents, the Postgres search, `tag:` filters and facets use what the person sees. What a person wrote is human data. The clip goes back in the search sync's queue until search has the change. Returns the clip's detail. 404 for an unknown or trashed asset. A field whose every part a person wrote (OCR text; description and tags together) is theirs: made, never redone or counted for a new model. Web: the lightbox's Edit beside each (an unchanged Save saves nothing), and Remove beside what a person wrote; a failed save says why and keeps the edit open.
- **PUT /v1/assets/{asset_id}/capture** — The clip's library's reader: an admin (the scheduler's key), or the device that reads it; editors and viewers 403. The capture facts read again from a clip's original (the capture producer, ADR-017 phase 3). Body: `{ "taken_at", "taken_at_offset_min", "gps_accuracy_m", "lineage" }`. `taken_at` is the camera's wall clock written as UTC (no zone applied; a time with no zone is taken as written), and `null` keeps the one stored; `taken_at_offset_min` (−840..840, or `null`: the file doesn't say) replaces the stored one; `gps_accuracy_m` is kept only when the clip has the file's GPS. The file's GPS isn't touched. Returns `{ "changed" }`: whether `taken_at` or its zone differ from what was stored. 404 if not found or not in sight; 422 `lineage_required` without lineage.
- **PUT /v1/assets/{asset_id}/live-photo** — The clip's library's reader, as for `PUT /v1/assets/{asset_id}/capture`. A clip's Live Photo identifier read again from its original (the Live Photos producer, `src/producers/live_photo`, for clips scanned before; it reads only an Apple camera's clips beside a file of the other kind with their name). Body: `{ "live_photo_id", "lineage" }`, `live_photo_id` as the ingest's (`null`: it has none). Then pairs it: a video in sight that a photo of its library shares it with, once the video has its preview, is that photo's motion, out of sight as part of it (`deleted_reason` `live_photo`: never listed, searched, counted or worked on alone, nor in the archive or the trash; a scan skips its file while it's unchanged, plan reason `live_photo`). A scan's files pair the same way as they arrive (a photo's ingest, a video's preview). Deleting the photo for good deletes its motion with it once no other photo has the identifier, and a scan skips both files from then on. Returns `{ "hidden" }`: videos this made a photo's motion. 404 if not found or not in sight; 422 `lineage_required`, `not_an_identifier`.
- **PUT /v1/assets/{asset_id}/video-facet** — Store a video's probe result, replacing any earlier one. Body (all optional except as noted): `{ "duration_sec", "container", "video_codec", "width", "height"` (display dimensions, rotation applied), `"rotation"` (0/90/180/270 clockwise, default 0), `"frame_rate_num", "frame_rate_den"` (nominal rate as a fraction, e.g. 30000/1001), `"start_timecode"` (`HH:MM:SS:FF`, or `HH:MM:SS;FF` drop-frame), `"drop_frame", "audio_codec", "audio_channels", "audio_sample_rate" }`. The facet's `duration_sec` becomes the asset's `duration_sec`. Validated (timecode `HH:MM:SS[:;]FF`, positive rate and sizes, rotation 0/90/180/270, finite non-negative duration): 422 otherwise. Returns the facet. 400 for non-video assets, 404 if not found or trashed.
- **GET /v1/assets/by-path** — Query: `library_id`, `rel_path`. Look up asset by library and path. Returns asset detail or 404.
- **GET /v1/assets/page** — Retired: 410 `gone` (any signed-in role, and a public library's visitor, as it was; 401 otherwise). It listed a library's clips, with `missing_*` filters, for the macOS app's own scan and AI enrichment, both gone: a library's clips are listed with `GET /v1/query` (`f=library:<id>`, named in `details.replaced_by`), and what each producer still needs is the scheduler's to find, from the database (the reconciler, above; the repair summary counts it). A clip whose preview never arrived, or was lost, is planned again by its next scan (Scans API, `preview_missing`).
- **PATCH /v1/assets/{asset_id}** — Update asset fields. Returns updated asset.
- **DELETE /v1/assets/{asset_id}** — Editor. A person trashes one clip, in sight or archived (`deleted_reason = "user"`, `deleted_at` now: its trash days start). It stays trashed through rescans while the file is on disk. Query: `remove_from_projects` (default false); 409 `in_projects` when projects use it (see Decisions). Returns 204; 404 if not found, already in the trash, or trashed with its library. Search documents go after the response (best effort); the library's revision is bumped.
- **POST /v1/assets/project-usage** — Which projects hold these clips: what deleting them for good would take them out of. Body: `{ "asset_ids": [...], "library_ids": [...] }` (either or both; library ids mean every clip in them). Every project counts, archived, trashed and other people's included; only those the caller can see are named. Returns `{ "assets_in_projects", "projects": [{ "project_id", "name", "status", "in_trash", "clips" }], "other_projects" }`.
- **POST /v1/assets/{asset_id}/restore** — Editor. Take a clip out of a person's trash. It comes back everywhere: library, every project holding it, and search (the asset and its scenes are queued for the next search sync; transcript segments are re-indexed after the response). Returns 204; 404 if not found or in sight; 409 `archived` (unarchive it instead), `file_missing` (it comes back when the file does), `library_trashed` (restore the library) or `path_taken` (another clip in sight is at its path now: a changed file is a new clip).
- **POST /v1/assets/restore** — Editor. The same for a selection. Body: `{ "asset_ids": [...] }` (at most 10,000). Returns `{ "restored": [...], "skipped": [...], "to_archive": [...] }`: skipped = not in a person's trash, their library is in the trash, or another clip in sight is at its path now (of two at one path in one call, the first comes back); to_archive = restored ones archived before they were trashed, back in the archive (a single restore does the same).
- **POST /v1/assets/archive** — Editor. Archive clips: out of sight, kept forever with everything they have; scans leave them archived while the files are on disk, and restore by content never claims them. Body: `{ "asset_ids": [...] }` (at most 10,000), or `{ "library_id", "path" }` for every clip in sight under that folder, recursively (`""` = the whole library; `_` and `%` in names are literal). The folder only picks the clips: a file added to it later shows up as usual. 422 for neither or both, 404 for an unknown or trashed library. Returns `{ "archived": [...], "skipped": [...] }` (skipped: not in sight, or unknown). Search documents go after the response; revisions are bumped.
- **POST /v1/assets/unarchive** — Editor. Bring back clips a person archived, by id or folder as above. A missing file's clip is skipped: it comes back with its file. So is one whose path another clip in sight holds now (of two at one path in one call, the first comes back). Returns `{ "unarchived": [...], "skipped": [...] }`.
- **DELETE /v1/assets** — Batch soft-delete. Editors. Body: `{ "asset_ids": [...], "reason": "user" | "missing" (required: 422 without), "remove_from_projects": false, "confirm_missing": <count> }`. `"user"` = a person's trash: takes clips in sight and archived ones (missing or archived by hand), restarts their clock, never takes a clip trashed with its library, and asks first when projects use them (409 `in_projects` unless `remove_from_projects`). `"missing"` = the scanner no longer finds the file (archived); ingest restores it if it reappears. Marking more than 50 clips and more than half of a library's clips in sight missing asks first: 409 `mass_missing` (see Decisions) until `confirm_missing` is the count it names; scanners send a scan's missing clips in one request so the rule sees them all. **Copy, then delete the original:** when the account follows moves, an asset marked missing whose content has an active copy in the same library, made after it and untouched by people (no note, no transcript a person wrote or pasted, no rating, in no project, no confirmed or rejected person; the first made if several), moves to that copy's path with everything it had, takes the copy's size and mtime and any cover set to the copy, and the copy is deleted for good. The copy and its faces are locked before they're checked, so a person's work landing meanwhile keeps the copy; a handover that would wait on a person's action (un-assigning a face, merging people) gives way after 200 ms and the asset stays archived. A person's trash never moves. A handover that fails is logged and the asset stays archived; the request still succeeds. The archive and the handovers commit together, or not at all: an API that dies halfway leaves every clip as it was (send it again), never an original archived with its people, notes and projects beside the empty copy that should have taken them; the copies' files, playback cuts and search documents go once it has committed. Returns `{ "trashed": [...], "not_found": [...], "handed_over": [...] }`: `handed_over` = those of the trashed that moved to a copy instead (active again, at the copy's path).
- **POST /v1/assets/batch-moves** — Retired: 410 `gone` (editors, as it was; 403 for a viewer). It moved clips a scanner said moved; a scan session finds moves and makes them on the server (Scans API, ADR-018: `hashes`, `moves`), named in `details.replaced_by`.
- **POST /v1/assets/{asset_id}/artifacts/{artifact_type}** — Multipart file upload. `artifact_type` is the file's name, one of `lumiverb.preview`, `lumiverb.preview.thumbnail`, `lumiverb.video.preview`, `lumiverb.video.scenes.picture`, `lumiverb.video.analysis_proxy` (by its old kind, 404 `renamed`, naming it). An analysis proxy is a video's full-length, low-resolution copy with audio, for transcription, scenes and vision (ADR-016 phase 2; not an edit proxy): videos only (400 otherwise), `video/*` content, its own 64 GiB ceiling instead of 100 MB, and a file whose content changes on ingest (new SHA-256) loses it. Form fields: `file` (binary, required), `width` (int, optional, images only), `height` (int, optional, images only), `rep_frame_ms` (int, required for a scene's picture, ignored for other types). Kept in the Store (`src/server/storage/store.py`) as it streams in, 64 KB at a time, and seen only once whole; the batch route, `POST /v1/assets/{asset_id}/artifacts` (`lumiverb.preview`, `lumiverb.preview.thumbnail`, `lumiverb.video.preview` fields, an old kind's 422 `renamed`; its items' `artifact_type` by name), keeps each the same way. A preview, a thumbnail or a scene's picture must be a JPEG, PNG or WebP image of at most 120 megapixels (no other format is read; `src/server/images.py`), and is stored re-encoded (WebP; JPEG for a scene's picture): its rotation applied, its colour profile kept, nothing else of the original's metadata (no EXIF, XMP or comments; `src/server/preview_image.py`), so `sha256` is the stored file's. A video preview or analysis proxy is checked, then kept rewritten (Writing a client: What the server takes): 422 `video_not_playable` with `details.problems` for one no browser plays. Updates DB after file is safely on disk. Returns `{ "key", "sha256", "duration_sec" }`: `sha256` of what's kept, `duration_sec` a video's length as the server measured it (null for an image); the batch route's items carry both too. Errors: 400 invalid type, an image that isn't a JPEG, PNG or WebP of at most 120 megapixels, or missing `rep_frame_ms` for a scene's picture, 404 asset not found or trashed, 413 file too large. A proxy, video preview or analysis copy says how it was made in the form field `lineage` (JSON), and a thumbnail gives the proxy producer's (it makes both): 422 `lineage_required` otherwise, before the file is written.
- **GET /v1/assets/{asset_id}/artifacts/{artifact_type}** — Download an artifact: the one route for a clip's proxy, thumbnail, video preview, scene frame and analysis proxy, for every client (`/v1/assets/{id}/proxy`, `/thumbnail` and `/preview` are gone). Signed in, a clip out of sight (archived, in the trash) still shows its pictures: the archive and trash views need them. A public page's visitor passes `public_library_id` or `public_project_id` (both: 400) and sees only that page's clips in sight (404 for a hidden one, 403 for another page's). Proxies and thumbnails come as `image/webp`, or `image/jpeg` for older JPEG ones. 404 `artifact_not_ready` until it exists. 404 `artifact_missing` when its file is gone: the GET changes nothing, and reports the clip for upkeep to repair (`POST /v1/upkeep`). `lumiverb.video.analysis_proxy` answers `Range` requests (206) and sends its SHA-256 as the `ETag`; public pages get 403 for it, and so do viewers while the account caps playback (they play videos through `/playback`). `lumiverb.video.preview` is cut to the playback cap for whoever asks (and stripped of its metadata for a public page); while that cut is made, 503 `playback_preparing` with `Retry-After`. A public page gets 403 for scenes' pictures past the public cap.
- **GET /v1/assets/{asset_id}/playback** — A signed link that streams a video for a `<video>` element, which can't send an `Authorization` header. Public pages pass `public_library_id` or `public_project_id` as elsewhere (both: 400). Returns `{ "url": "/v1/stream/<token>", "expires_at", "source", "max_seconds", "ready", "whole" }`: `ready` is false while the capped copy is made in the background (ask again in a couple of seconds; the link answers 503 until then); `source` is `lumiverb.video.analysis_proxy` (full length, every audio track) or `lumiverb.video.preview` (the 10-second clip scan makes) until the proxy exists; `max_seconds` is the cap for this viewer (public pages: the smaller of the public and account caps), `null` for the whole video. `whole` is true when what's served is the whole clip: the proxy, or the preview of a clip no longer than it (`duration_sec` at most the 10-second preview's length), so players say "Full video" rather than "a short preview" and stop asking for the proxy (`playback.py` `whole_clip`; older servers leave it out: take the analysis proxy's `source` as whole). Links last an hour; the web player asks for a new one when a link fails. A Live Photo (`live_photo` in its detail) plays its motion, the few seconds of video around it, by the photo's own link and access. 404 asset missing or trashed, or nothing to play yet; 422 neither a video nor a Live Photo.
- **GET /v1/stream/{token}** — Streams what a playback link points at, with `Range` (206) for seeking. No `Authorization` header: the HMAC signature (keyed from `JWT_SECRET`) is the credential, and the tenant comes from the link, so the route skips the tenant middleware. The cap is read when the video is requested, so a new cap applies to links already handed out: a longer video is served as a stream-copy cut of its first N seconds (video and every audio track), kept in the account's playback cache (`{tenant}/playback/` of the previews folder, at most `LUMIVERB_PLAYBACK_CACHE_GB`, 2 by default, the least recently played going first: `src/server/storage/cache.py`). Cuts (and the probe that says whether one is needed, kept beside them so every API worker knows it) are made in the background, never in the request: two at a time, 16 waiting at most; until a cut is there the link answers 503 `playback_preparing` with `Retry-After: 2`. Cuts are cleared when a cap changes and when assets are deleted for good; the daily cleanup drops cuts of assets that are gone and writes a dead process left. 503 `storage_unavailable` while the previews can't be reached. `ETag` names the bytes (source, version, cap); an `If-Range` naming another version gets the whole new file (200), so a cap change mid-play can't splice two files. Whether a video runs past the cap goes by the served file's own length, not a stored duration. `Range`: `bytes=a-b`, `bytes=a-`, `bytes=-n` (the last n); a start past the end is a 416. 403 forged, malformed or expired, or no longer its person's: a signed-in link names who it was made for (the person and their token version, or the key) and asks again at every request, so a key revoked, a person signed out everywhere (a new password or role) or a library they can't see any more ends it at once (403 `invalid_link`; the player asks for a new link, refused as the route is); a deleted account's link plays no more, as nothing of the account is reached (401 `account_deleted`, as the middleware answers its requests; a public page's link, 404); 404 asset trashed, gone, or no longer public for a link handed to a public page; 503 `playback_cut_failed` for a minute after a cut failed. `GET /v1/assets/{id}/artifacts/video_preview` honors the cap too, and a public page's `transcript_srt` (asset detail) stops at the public cap.
- **GET /v1/assets/facets** — Same `f=` filters as `/v1/query`, and for a public page's visitor the same rules (and the same limit: a visitor's searches, `/v1/query`, facets and `/v1/similar`, are 120 a minute from one address, then 429; signed in, none) (every `library:` public, at least one; no rating, person or project filters; text search within the public cap). Project filters are checked as on `/v1/query`. Returns aggregated filter facets: `{ "media_types", "camera_makes", "camera_models", "lens_models", "iso_range", "aperture_range", "focal_length_range", "has_gps_count", "has_face_count" }`.
- **PUT /v1/assets/locations** — Editors. A person's location for clips (ADR-017). Body: `{ "asset_ids": [...] (required, non-empty, at most 10,000), "lat", "lon" | "same_as": asset_id | "place_id", "replace": "none" (default) | "person" | "all" }`. `same_as` copies that clip's location (a person's, else the file's; 400 when it has none) and skips that clip itself. `place_id` (from `GET /v1/places`, `"<plugin_id>:<its id>"`) is asked of the plug-in that found it again, as it says it now, and sets that place's point and keeps the place with who to credit for it (whatever becomes of the plug-in since): the detail's `location.basis_summary` is its name ("Port of Spain, Trinidad and Tobago") and `location.credit` (`{ "text": "GeoNames", "url", "license": { "text": "CC BY 4.0", "url" } }`: the plug-in's credit, its license null when it names none) is to be shown beside it. 409 `plugin_off` when that plug-in isn't on here, 503 `plugin_unavailable` (`details.plugin_id`) when it can't answer now, 422 `unknown_place` when it says there's no such place, or no plug-in installed found it. 400 `scope_required` without `asset_ids` (never "all"); 400 unless exactly one of a point, `same_as` and `place_id`; 422 `invalid_location` for a point that isn't a place (out of range, or 0, 0). Replacing a location needs the request's say: a clip with a person's location needs `replace` `"person"` or `"all"`, one with only the file's GPS needs `"all"` (the file's stays and still shows as "From the file"), else 409 `location_exists`. Guesses and suggestions are replaced without asking. Stores the user id in `set_by`, never an email (no email reaches a public viewer, anywhere: `tests/test_public_no_emails.py`). Records lineage with producer `person`, so it's never made again over. Returns `{ "updated", "skipped" }` (skipped: not in sight, unknown, or the `same_as` clip).
- **DELETE /v1/assets/locations** — Editors. Body: `{ "asset_ids": [...] }` (required, non-empty). Clears a person's location only; the file's GPS, guesses and suggestions stay, and its lineage goes, so the machine may guess again. Returns `{ "cleared", "skipped" }`.
- **POST /v1/assets/locations/accept** — Editors. Body: `{ "asset_ids": [...] }` (required, non-empty). These clips' suggestions become a person's location, their point and radius kept. On a clip whose file has GPS that replaces what shows: send `"replace": "all"`, else 409 `location_exists`. Returns `{ "accepted", "skipped" }`.
- **Location guesses (ADR-017 phase 3).** The `lumiverb.location.guess` producer's, in the libraries where **Infer location** is on (each library's `infer_location`, off by default: Library settings › Location guesses, `PATCH /v1/libraries/{id}`; turning it off removes that library's guesses, asked first with 409 `guesses_exist`, a person's location staying). Its one setting is the account's **Inference window**, `inference_minutes`, 360 (Settings → Processing → Location guesses). A new window asks nothing and removes nothing: guesses are checked again (`inference_minutes` doesn't remake, `remakes: false`). A guess is `source` `time` in the detail's `location`, with `radius_m` and `basis_summary` (e.g. "From iPhone 15 Pro photos 14:02–14:40 · clock 6.0 h ahead"); it counts in `has_gps`, `near` and the facets only with `include_guesses:yes`, and never on a public request. A guess is never removed to be made again; it's checked again (ADR-017 "As built"): when a fix it was made from changes (`basis_changed`: replaced, or removed with nothing found) or is trashed, archived or missing (`basis_gone`: replaced by any new guess, or kept and marked, `location.basis_gone: true`, "source removed"), when a new fix appears in its library within the window plus 14 h, or one comes back (`new_fix`), or when the window changes (`window_changed`; the new guess replaces the old only when its `radius_m` is no larger, for this and `new_fix`; `outside_window` for a guess made from a fix now outside it: replaced by any new guess, or kept and marked, `location.outside_window: true`). A guess waiting to be checked again counts as `rechecking` in the producer's counts, not as missing. The producer's routes, admins only (the scheduler's key; editors and viewers 403):
  - **POST /v1/assets/locations/clocks** — Body: `{ "asset_ids": [...] (required, non-empty), "min_similarity": 0.9, "window_min": 840 }`. For each clip, its device (make, model, serial number) and day, and that day's scene pairs: each of the device's clips with no fix that day (at most 300) with the most alike fix (CLIP) from another device in its library within `window_min` minutes as written, when at least `min_similarity` alike. Returns `{ "clips": {asset_id: key}, "days": {key: {"device", "pairs": [{ "camera_id", "camera_taken_at", "camera_offset_min", "fix_id", "fix_taken_at", "fix_offset_min", "fix_device", "similarity" }]}} }`. 400 `scope_required` without `asset_ids`.
  - **GET /v1/assets/locations/context/{asset_id}** — Query: `minutes` (1–1440, default 360), `clock_offset_min` (default 0). The clip's `taken_at`, `taken_at_offset_min` and device, and the nearest fix before it and after it in its library within `minutes`, the gap (minutes the clip was taken after the fix) taken between real instants when both zones are known, else between wall clocks, less `clock_offset_min` for a fix from another device. Returns `{ "clip", "fixes": [{ "asset_id", "taken_at", "taken_at_offset_min", "device", "lat", "lon", "accuracy_m", "source": "file"|"person", "gap_min", "label" }] }`. 404 if not in sight.
  - **PUT /v1/assets/locations/guess/{asset_id}** — Body: `{ "guess": { "lat", "lon", "radius_m", "basis" } | null, "minutes", "fixes", "lineage" }` (`minutes`: the Inference window it was made in, required; `fixes`: `[{asset_id, lat, lon, taken_at}]`, what was seen of each fix `basis.fixes` names, 422 `fixes_required` when one is missing). Stores the guess (`source` `time`, `status` `applied`), or with `null` removes the clip's guess and records that it tried (lineage outcome `empty`); a guess due to be checked again is kept or replaced by the recheck rules. Never over a person's location or the file's GPS, nor over a suggestion. Returns `{ "result": "stored" | "empty" | "kept" | "gone" | "off" | "unchanged" | "marked" | "stale" }` (kept: a person's location or the file's GPS, nothing written; gone: not in sight; off: its library's Infer location was turned off, nothing written; unchanged: the guess it had is as sure or surer; marked: its fixes went and nothing else was found, kept with `basis_gone`; stale: `minutes` isn't the setting now, or a fix in `fixes` has gone out of sight, moved or been retimed since; nothing written). 422 `lineage_required` without lineage, `invalid_location` for (0, 0), `basis_too_big` over 16,000 characters.
- **POST /v1/assets/{asset_id}/faces** — Retired: 410 `gone` (editors, as it was; 403 for a viewer). It saved one clip's faces, the macOS app's own detection; the server's scheduler finds faces now, and its faces producer saves a photo's with `POST /v1/assets/batch-faces` (below), a video's with `POST /v1/video/{asset_id}/faces`, both named in `details.replaced_by`.
- **POST /v1/assets/batch-faces** — Editors (the scheduler's key: the faces producer, `src/producers/faces/work.py`, saves a job's photos in one request). Body: `{ "items": [{ "asset_id", "detection_model" (default "insightface"), "detection_model_version" (default "buffalo_l"), "embedding_model": str (default "buffalo_l": the model that embedded them), "faces": [{ "bounding_box": dict, "detection_confidence": float, "embedding": [512 floats] | null }], "source_hash"? }], "lineage" (required) }`. Returns `{ "processed", "skipped" }` (skipped: unknown or trashed). Bounding box: normalized fractions 0.0–1.0, top-left origin. Accepts `{x, y, w, h}` (position+size) or `{x1, y1, x2, y2}` (two corners) — server normalizes to `{x, y, w, h}` before storage. For each clip, each detection that re-finds an existing face of the asset (overlapping boxes, IoU ≥ 0.1, whose embeddings are within cosine distance 0.4; boxes without embeddings at IoU ≥ 0.3; then embedding distance < 0.4 alone) updates that face in place: it keeps its `face_id`, confirmed person assignment and rejections, while machine-made (unconfirmed) assignments are re-derived. Embeddings are compared only within one `embedding_model`: across a face-model switch a face is re-found by box overlap alone, and only a substantial one (IoU ≥ 0.5). A confirmed face re-found by a new model rebuilds its person's centroid from the new embedding; centroids, auto-assignment, clustering and suggestions use only the current face model's embeddings (`people.centroid_model`), so names carried across a switch teach the new model those people. Old faces not re-found are deleted unless a person confirmed them, in which case they are kept as-is. Sets `assets.face_count` (new detections + kept faces), records the lineage (`empty` for a clip with none found), cuts each face's crop from the clip's proxy, and bumps each library's revision once. A clip's faces and their ids: `GET /v1/assets/{asset_id}/faces`.
- **POST /v1/assets/batch-ocr** — Editors (the scheduler's key: the ocr producer saves a job's clips in one request). The text read in images. Body: `{ "items": [{ "asset_id", "ocr_text" ("" when there's none), "source_hash"? }], "model_id"? (the reading model), "lineage" }`. Stored in `asset_ocr` (one row per clip), apart from the description: no description needed, and describing the clip again leaves it alone. Re-syncs search. Returns `{ "updated", "skipped" }` (skipped: unknown or trashed). `GET /v1/assets/{id}` and `/by-path` return it as `ocr_text`. The per-clip **POST /v1/assets/{asset_id}/ocr**, `/vision` and `/embeddings` are retired: 410 `gone` (editors, as they were), `details.replaced_by` naming the batch route; a client saving one clip sends one item.
- **POST /v1/assets/{asset_id}/transcript** — Upload or replace a video's SRT transcript. Body: `{ "srt": str, "language": str | null, "source": "manual" | <provider id, e.g. "whisper">, "lineage" }` (`source` is required: whose it is). A clip has one transcript, the latest (Robert, Oct 9). Stored as `assets.transcript_source`. Editors (machine output comes from the scheduler's key). A person's (`"manual"`) replaces whatever is there. Machine output never replaces a person's: it's dropped, nothing of it kept (`{ "status": "kept_manual" }`). Empty `srt` = checked, no speech (`"no_speech"`). Parses SRT to extract plain text for search indexing; re-syncs search (segments replaced). Returns `{ "asset_id", "status": "transcribed" | "no_speech" | "kept_manual" }`. Errors: 400 if not a video or invalid SRT, 403 for a viewer, 404 if asset not found.
- **DELETE /v1/assets/{asset_id}/transcript** — Editors. Remove the transcript a video shows. A person's: none is left, and the clip's transcript is missing again, so the machine makes one. The machine's: removed for good, a person's choice that nothing makes again (a machine transcript arriving later is dropped: `kept_manual`). Query: `which` (optional): `manual` (a person's) or `machine`, the one the caller means; a transcript from before `transcript_source` existed (none) is the machine's. When the clip shows the other one, 409 `transcript_changed` with `details: { "shown": "manual" | "machine" }` and nothing is removed (a second click never removes more than meant); when it shows none, nothing to do. Re-syncs search. Returns 204; 403 for a viewer; 422 for another `which`. Web: Remove, which says which of the two it does.
- **POST /v1/assets/batch-vision** — Editors (the scheduler's key). A machine's descriptions and tags: photos' (`lumiverb.image.description`'s lineage), or videos' written from their scenes' descriptions in order (`lumiverb.video.description`'s). Body: `{ "items": [{ "asset_id", "model_id", "model_version" (default "1"), "description", "tags": [...], "source_hash"? }], "lineage" }`; every clip the kind its producer describes, else 422 `wrong_media_type` (nothing saved). Each clip's status becomes `described`; re-syncs search. Returns `{ "updated", "skipped" }` (skipped: unknown or trashed). What a person wrote (`/corrections`) is never replaced: a person's description of a video is that producer's, as a photo's is its.
- **POST /v1/assets/batch-embeddings** — Editors. Body: `{ "items": [{ "asset_id", "model_id", "model_version", "vector": [floats], "source_hash"? }], "lineage" }` (lineage required when any is CLIP's, the producer's artifact). Replaces each clip's vector for that model. Returns `{ "updated", "skipped" }` (skipped: unknown or trashed).
- **PUT /v1/assets/{asset_id}/note** — Editors. Add or update a freeform note. Body: `{ "text": str }`. Stores last author (email) and timestamp; a public page's asset detail leaves the author out. Note text is indexed for search. Returns `{ "asset_id", "note", "note_author", "note_updated_at" }`.
- **DELETE /v1/assets/{asset_id}/note** — Editors. Delete a note from an asset. Returns 204.
- **GET /v1/assets/{asset_id}/faces** — Signed in only (401 for a public page's visitor). List detected faces. Returns `{ "faces": [{ "face_id", "bounding_box", "detection_confidence", "person": { "person_id", "display_name" } | null, "frame_ms", "seen_ms" }] }`. The `person` field is populated when the face is matched to a named person. A video's faces (one a person seen) have `frame_ms`, the time of the frame their box is in, and `seen_ms`, every time the person was seen at, in order; a photo's have null.

## People API

People are tenant-scoped — a person named in one library is recognized across all libraries. Every write here and under `/v1/faces` (create, rename, delete, merge, undismiss; name or dismiss a cluster; assign or unassign a face) needs an editor (403 for a viewer).

- **GET /v1/people** — Cursor-paginated list of people sorted by face count descending. Query: `after`, `limit` (1–100, default 50), `q` (optional name search, case-insensitive substring match). Returns `{ "items": [{ "person_id", "display_name", "face_count", "representative_face_id", "representative_asset_id", "confirmation_count" }], "next_cursor" }`.
- **POST /v1/people** — Create a named person. Body: `{ "display_name": str, "face_ids": [str] | null }` (at most 10,000). If `face_ids` provided, assigns those faces and computes centroid. 409 `faces_assigned` (details `conflicts: [{ "face_id", "person_id" }]`) if any face is already assigned. Returns 201 `PersonItem`.
- **GET /v1/people/dismissed** — Dismissed people (clusters someone said aren't a person), by face count. Query: `after`, `limit` (1–100, default 50). Same shape as `GET /v1/people`.
- **POST /v1/people/{person_id}/undismiss** — Editors. Give a dismissed person a name: `{ "display_name" }`. Returns `PersonItem`; 404 unless they're dismissed; 403 `faces_in_other_libraries` as for delete.
- **GET /v1/people/{person_id}/nearest** — Named people ranked by distance to this person's centroid (`limit` 1–20, default 5): `[{ "person_id", "display_name", "face_count", "distance" }]`, never the person themselves; empty when they have no centroid.
- **GET /v1/people/{person_id}** — Get a person by ID. Returns `PersonItem` or 404.
- **PATCH /v1/people/{person_id}** — Editors. Rename a person. Body: `{ "display_name": str }`. Returns `PersonItem` or 404. A name is how they're labelled in every library their faces are in, so it's 403 `faces_in_other_libraries` as for delete (`"…so only an account admin can rename them."`), and the name stays.
- **DELETE /v1/people/{person_id}** — Delete person and all face matches. Returns 204 or 404. It acts on every face they have, in every library, so it's an account admin's, or someone's who edits every library their faces are in: anyone else gets 403 `faces_in_other_libraries`, its message saying how many of their faces are in libraries the caller doesn't edit (`details: { "faces_elsewhere" }`), and nothing changes (naming a group of faces takes only those the caller edits). The same for rename, merge and undismiss.
- **GET /v1/people/{person_id}/faces** — Cursor-paginated faces matched to a person. Query: `after`, `limit` (1–100, default 50). Returns `{ "items": [{ "face_id", "asset_id", "bounding_box", "detection_confidence", "rel_path", "taken_at", "media_type", "frame_ms", "seen_ms" }], "next_cursor" }`. A video's face (`media_type` `video`) is the person in that video: `frame_ms`, the moment its crop is from, and `seen_ms`, every time they were seen at (a client opens the video there); null for a photo's.
- **GET /v1/faces/{face_id}/nearest-people** — Named people ranked by distance to this face's embedding (`limit` 1–20, default 5): `[{ "person_id", "display_name", "face_count", "distance" }]`. Empty when the face has no embedding, or one from another face model than the account's (mid-switch, it's in another space than the centroids). 404 for an unknown face.
- **GET /v1/faces/{face_id}/crop** — Serve the 128x128 WebP face crop thumbnail. A photo's is generated at face submission time from the asset proxy using bounding box + 40% padding (`src/shared/face_crop.py`), and again from it when missing; a video's comes with its faces, cut from its frame, and is never cut from the poster (another moment): 404 when it's missing. Returns 404 if no crop available (old faces). Immutable caching (1 year).
- **GET /v1/faces/clusters** — Clusters of unassigned faces, as upkeep last computed them: reading them never computes them. Upkeep (`POST /v1/upkeep`, every 5 minutes) computes them again when faces changed since: database triggers bump `face_clusters_version` when a clip with faces is trashed, restored, archived, missing or purged, its library trashed, or a face found, removed, named or un-named. Query: `limit` (1–50, default 20), `faces_per_cluster` (1–20, default 6), `min_cluster_size` (≥ 1, default 2), `sort`: `size_desc` (default, largest first), `size_asc` (smallest first) or `newest` (latest photo first, undated last); 422 for anything else. Ties go by the cluster's first face id, so the order holds between loads. Returns `{ "clusters": [{ "cluster_id", "size", "faces": [{ "face_id", "asset_id", "bounding_box", "detection_confidence", "rel_path", "media_type", "frame_ms" }], "newest" }], "truncated": bool, "max_cluster_size", "computed_at", "pending" }`: `cluster_id` names a cluster by its faces (a fingerprint of their ids), so the same faces have the same id whenever they're computed; `newest` is the cluster's latest photo, taken or else the file's time (null when none says); `computed_at` is when they were computed (null: not yet); `pending` says faces changed since. Clusters with a face named or dismissed since aren't shown. Not paginated — bounded by `limit` clusters.
- **POST /v1/faces/clusters/{cluster_id}/name** — Editors. Name every face of the cluster: `{ "display_name" }` makes a new person, `{ "person_id" }` adds them to one (400 for neither). A cluster any of whose faces are named or dismissed isn't shown, so it's gone from the next load before upkeep computes them again (and back if the dismissal is undone). The faces are locked first: of two requests for one cluster, the second gets the 409. 409 `cluster_changed` when no cached cluster has this id or some of its faces were named or dismissed since: load the clusters again. Returns 201 `PersonItem`.
- **POST /v1/faces/clusters/{cluster_id}/dismiss** — Editors. Not a person: the faces go to a new dismissed person (returned for undo: `{ "person_id" }`; deleting it undoes), which also absorbs similar faces later. 409 `cluster_changed` as for naming.
- **GET /v1/faces/clusters/{cluster_id}/nearest-people** — Named people ranked by distance to the cluster's centroid (`limit` 1–20, default 5). 409 `cluster_changed` for an id no cluster has.
- **GET /v1/faces/clusters/{cluster_id}/faces** — Every face of the cluster, cursor-paginated: `after` (a face id), `limit` (1–100, default 50). Returns `{ "items": [{ "face_id", "asset_id", "bounding_box", "detection_confidence", "rel_path", "taken_at", "media_type", "frame_ms", "seen_ms" }], "total", "next_cursor" }` (a video's face as for a person's faces). 409 `cluster_changed` for an id no cluster has.
- **POST /v1/faces/{face_id}/assign** — Assign a face to a person (stored as confirmed). Body: `{ "person_id": str }` (existing person) or `{ "new_person_name": str }` (creates new person). Clears an earlier rejection of this face for that person. 409 `face_assigned` (details `current_person_id`) if the face is already assigned. Returns `{ "person_id", "display_name" }`.
- **DELETE /v1/faces/{face_id}/assign** — Remove a face from its assigned person. Clears `faces.person_id`, recomputes person centroid, and records a rejection (`face_person_rejections`) so auto-assignment and the upkeep sweep never put the face back on that person. Assigning a cluster to that person skips the face; merging the person carries the rejection to the merge target. Returns 204 or 404.
- **POST /v1/people/{person_id}/merge** — Merge source person into target. Body: `{ "source_person_id": str }`. Reassigns all face matches, updates `faces.person_id`, recomputes centroid, picks best representative face, deletes source. Rejections ("not this person", from un-assigning) carry over to the target. Where a face ends up both matched to and rejected for the merged person, a machine match always loses, and between a confirmation and a rejection the later decision wins, so the result is the same whichever way two people are merged. Serialized via `SELECT ... FOR UPDATE` on source. Returns updated target `PersonItem`. Returns 400 if merging into self; 403 `faces_in_other_libraries` when either has faces in a library the caller doesn't edit (as for delete).

## Ingest API

Atomic ingest: create + populate assets in one request. The server re-encodes the proxy (WebP, 2048px max; every one, a WebP within the size too: What the server takes), generates a thumbnail (WebP, 512px), and stores all provided metadata atomically.

- **POST /v1/ingest** — Multipart form. Creates asset record AND ingests proxy + metadata atomically. The asset only appears on the server once fully populated. If the clip in sight at the same `(library_id, rel_path)` has the same content (or either content isn't known: no `exif.content_hash`, the file's content hash; 400 for one the server doesn't take, see Content hashes), it is updated (idempotent). An fp1 in `exif.content_hash` may come with the whole file's `sha256:` hash in `exif.previous_hash` (its scan's plan said `legacy`; 400 for anything else there): the hashes made before fp1 it takes the place of are swapped first, as `POST /v1/scans/{id}/hashes` does. A different file at the path is a new clip (Robert, Oct 9: nothing carries over), and the old one is archived as missing where it was (its projects too), back if its content is; it goes even when the new file is refused (its file isn't there any more), and when an empty copy of its content is elsewhere it moves there, as a copy-then-delete does. A file whose own clip is archived or trashed at that path is that clip: back if it went missing, refused if a person trashed or archived it; so a path holds one clip in sight and may hold archived ones. Restoring or unarchiving a clip onto a path another clip in sight holds skips it. Required fields: `lumiverb.preview` (the preview, a file: 422 `preview_required` without it; by its old kind, 422 `renamed`), `library_id`, `rel_path`, `file_size`. Optional: `file_mtime` (ISO8601), `media_type` (default `image/jpeg`), `width`/`height` (source dimensions), `exif` (JSON), `vision` (JSON), `embeddings` (JSON array), `video_facet` (JSON, video only; same shape as `PUT /v1/assets/{id}/video-facet`; 400 if not a video; an invalid facet is logged and ignored so it never blocks ingest). The preview (a JPEG, PNG or WebP of at most 120 megapixels, as artifact uploads; anything else is a 400) is stored re-encoded as WebP, at most 2048 px, with nothing of the original's metadata (as artifact uploads). Returns `{ "asset_id", "proxy_key", "proxy_sha256", "thumbnail_key", "thumbnail_sha256", "status", "width", "height", "created" }`. 400 unless `rel_path`'s extension is a supported one of its `media_type` (`src/shared/file_extensions.py`). Enforces library path filters: 422 if `rel_path` is excluded. 409 if the library is in the trash, if a person trashed or archived the asset (`deleted_reason` `"user"` or `"archived"`) or emptied that file from the trash (another file at that path is its own clip; a scan started with `force_add` brings such a file back first); an asset the scanner marked missing is restored instead and goes back in search (asset and scenes re-queued, transcript re-indexed). **The archive model** (when the account follows moves): a `rel_path` the library doesn't know, whose `exif.content_hash` matches an asset in the same library whose file is missing (never a person's trash or archive), restores that asset at the new path with everything it had (ratings, notes, projects, faces, transcript); with several matches, the most recently archived. Two ingests at once can't both claim one archived asset: the other gets an asset of its own. A new clip whose content went missing elsewhere while it was made (a copy and the overwritten original ingested at once) takes that clip, as copy-then-delete: the response gives the clip's `asset_id` with `created` false. 409 when another ingest just put a clip at this path ("scan again"): one clip in sight holds a path.
- **POST /v1/assets/{asset_id}/ingest** — Ingest into an existing asset record. Same proxy + metadata fields minus `library_id`/`rel_path`/`file_size`. A `content_hash` in `exif` that isn't the clip's is 409 `different_file` (details `asset_content_hash`, `content_hash`): a different file is a new clip, made by `POST /v1/ingest`.

## Decisions the API requires

When an action would surprise the user, the API refuses until the request states the user's choice, so every client (web, CLI, macOS, iOS) has to show the facts and ask. The refusal is **409** in the standard envelope, `{ "error": { "code", "message", "details" } }`, with the facts in `details`:

- `in_projects` — trashing clips (`DELETE /v1/assets` with `"reason": "user"`, `DELETE /v1/assets/{id}`, an exclude filter with `trash_matching`: nothing is added until answered), trashing a library (`DELETE /v1/libraries/{id}`), or deleting them for good (`DELETE /v1/trash/empty`, `POST /v1/libraries/empty-trash`) when projects use the clips. In the trash they're hidden there; the trash deletes them for good on its own later, and then they leave those projects, so the question comes when they're trashed. `details` is the project usage (see `POST /v1/assets/project-usage`). Resend with `"remove_from_projects": true` (a query parameter for `DELETE /v1/assets/{id}`).
- `keys_would_end` — `PATCH /v1/tenant/settings` with fewer `key_idle_days` (or turning them on) when keys unused for longer would stop working within minutes. `details`: `{ "key_idle_days", "keys": [{ "key_id", "label", "role", "last_used_at" }] }`, longest unused first. Resend with `"confirm_end_keys": true`.
- `keys_end_with_password` — changing your own password (`POST /v1/me/password`) while you have live API keys of your own: a new password ends them, devices' keys you made included. `details`: `{ "keys": [{ "key_id", "label", "role", "device", "last_used_at" }] }`, oldest first. Resend with `"end_api_keys": true`. Nothing changes until answered.
- `trash_days_shortened` — `PATCH /v1/tenant/settings` with fewer `trash_days` (or turning them back on) when things already in the trash longer would be deleted for good within minutes (once upkeep is resumed, while the Upkeep switch is paused). `details`: `{ "trash_days", "clips", "libraries", "projects" }`. Resend with `"confirm_purge": true`.
- `redo_on_change` — changing an AI job's model (`PUT /v1/ai/jobs/{job}`) or a producer's settings (`PUT /v1/producers/{artifact}/settings`) when clips were made with the old ones (ADR-018 decision 6): new files only, or remake those too, after everything else (until that's done results mix the old and the new). `clips` counts only what would be remade. `details`: `{ "job", "model", "clips", "question", "artifacts": [{ "artifact", "title", "clips", "paused" }] }` for a model; `{ "artifact", "clips", "redo_stopped", "paused", "question", "artifacts" }` for settings; `question` is `"remake"`. The message says when a producer it would make is paused, so none of it is made until it's resumed. Resend with `"redo": false` (new files only, the default a client offers first: "New files only") or `"redo": true` ("Also remake 1,200 clips"). What's kept stays a standing offer: Settings › Processing's "Remake" resumes the redo.
- `mass_missing` — marking files missing (`DELETE /v1/assets` with `"reason": "missing"`, or finishing a scan, `POST /v1/scans/{id}/finish`) when it would take more than 50 clips and more than half of a library's clips in sight: what a half-mounted volume looks like. `details`: `{ "count", "libraries": [{ "library_id", "missing", "in_sight" }] }`. Resend with `"confirm_missing": <count>` (a different count asks again), or a scan's finish with `"allow_mass_missing": true`. The CLI scan answers only under `--allow-mass-delete`; the Mac app skips them. Nothing is archived until answered.
- `moved_files` — finishing a scan that asks about moves (`"moves": "ask"`) while files moved: `lumiverb scan`'s prompt. `details`: `{ "count", "moves": [{ "from", "to" }] }` (the first 10). Answer with `POST /v1/scans/{id}/moves` (`"apply": true` or `false`), then finish again.
- `location_exists` — setting a location (`PUT /v1/assets/locations`), or accepting a suggestion (`POST /v1/assets/locations/accept`), on clips that already have one the file or a person gave, which `replace` doesn't cover. `details`: `{ "count", "person", "file", "total" }` (count: those not covered; person and file: every target with one). Resend with `"replace": "person"` or `"all"`.
- `plugin_unavailable` (503) — the installed plug-in a place came from can't answer now (`PUT /v1/assets/locations` with its `place_id`): not running, too slow, or what it said isn't what the protocol says. `details.plugin_id`. Try again once it's running (Settings › Plug-ins says what it's doing).
- `invalid_outputs` (422) — what an installed plug-in's work gave back isn't what its manifest declares (`POST /v1/plugins/{id}/outputs`). `details`: `asset_id`, `why`. Nothing was saved.
- `invalid_settings` (422) — a plug-in's settings it doesn't take (`PUT /v1/plugins/{id}/settings` or `/server-settings`). `details.errors`: what's wrong, by key, to show beside each field; `details.by_plugin`: the plug-in's own check said so. Nothing was saved.
- `acknowledgment_required` — turning on a plug-in that asks an acknowledgment (`PUT /v1/plugins/{id}` with `"enabled": true`), such as a license. `details`: `{ "plugin_id", "version", "title", "text", "links" }`. Show it in full; resend with `"acknowledged": "<version>"`, that version. Not accepting leaves the plug-in off.
- `guesses_exist` — turning a library's Infer location off (`PATCH /v1/libraries/{id}` with `"infer_location": false`) when its clips have location guesses: they go, with the producer's tries; a location a person set stays. `details`: `{ "clips" }` (its clips with a guess, in sight or not). Resend with `"remove_guesses": true`.
- `make_folder` — choosing a folder that isn't there (`PUT /v1/system/storage/previews`, `PUT /v1/libraries/{id}/previews`, `PUT /v1/system/backups/folder`). `details`: `{ "folder", "free", "same_drive_as_data" }` (the message says so when it would be on the data folder's drive: a Linux mount point whose drive is missing, say). Resend with `"make_folder": true`. Never offered where a drive that isn't there would be (`src/server/drives.py`): right in `/`, in `/Volumes` or a Linux desktop's `/media`, `/media/<user>`, `/run/media/<user>` ("There's no drive at … Is it plugged in?"), or under a mount point `/etc/fstab` lists that isn't mounted ("… Is it mounted?"); a 400, as is choosing such a folder that is there (an empty mount point). It's made only for a request that goes through: one refused, or answered with `move_previews`, takes it away again (`src/server/api/new_folder.py`).
- `move_previews` — moving previews (the same two routes) when files would move, or a library's folder is on its originals' drive. `details`: `{ "from", "to", "files", "bytes", "free", "same_drive_as_originals"? }`. Resend with `"move": true`.
- `clips_in_trash` — restoring a project (`POST /v1/projects/{id}/restore`) whose clips someone trashed. `details`: `{ "trashed_clips", "missing_clips" }`. Resend with `"with_clips": true` (restore them everywhere) or `false` (leave them).

Moving a project to the trash, archiving clips, or pausing processing (all of it, its scans or one producer's) is reversible and needs no decision.

## Trash API

- **GET /v1/trash** — Signed in. Clips a person trashed, most recently trashed first; clips of a library in the trash go with the library and aren't listed. Query: `library_id`, `path` (a folder, recursive), `after` (cursor), `limit` (1–500, default 100). Returns `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", "media_type", "trashed_at", "expires_at" }], "next_cursor", "total", "trash_days", "listed_at" }` (`listed_at`: send it back as `trashed_before` when emptying what was shown, so nothing trashed since goes); `expires_at` is when it's deleted for good (`null` when the trash days are off). Thumbnails and proxies of hidden clips load for signed-in people (never on public pages).
- **DELETE /v1/trash/empty** — Permanently delete trashed assets. Admins. Body: `{ "asset_ids": ["ast_..."] }` (at most 10,000) or `{ "all": true }` (every clip in the trash, as of now unless `trashed_before`), never neither (400 `scope_required`); with `"trashed_before": "2026-01-01T00:00:00Z"` (an ISO 8601 time; 422 otherwise), `"library_id"`, `"path"` (only that library's trash, under that folder: what a filtered view showed) and `"remove_from_projects": false`. Clips of a library in the trash are never reached: they go with the library. 409 `in_projects` (see Decisions) when any of the clips are in projects, unless `remove_from_projects` is true. Only a person's trash is purged (`deleted_reason = "user"`): archived clips are never deleted this way; trash them first. Whatever was restored since it was listed is left alone, so `deleted` can be lower than the number of ids sent. Scope: the intersection of what's given. Deletes DB rows in FK-safe order, then, once that's committed, every file of theirs Lumiverb stored: previews, analysis proxies, scenes' frames and pictures, faces' crops, playback cuts (their search rows go with them). Assets the user trashed leave an `ignored_files` record (library, path, content hash), because Lumiverb never deletes originals and the file may still be on disk; scans and ingest keep skipping that file at that path (a different file there is a new clip) unless a person asks a scan to add it anyway (`force_add`, `lumiverb scan --force-add`). Returns `{ "deleted": N }`.

## Archive API

Archived clips are out of sight but kept forever with everything they have: a person archived them (`POST /v1/assets/archive`, back with `POST /v1/assets/unarchive`), or their file went missing (back by itself when the file is). Deleting an archived clip moves it to the trash.

- **GET /v1/archive** — Signed in. Archived clips, most recently archived first; clips of a library in the trash aren't listed. Query: `kind` (`all` default, `by_hand`, `missing`), `library_id`, `path` (a folder, recursive), `after` (cursor; 400 if malformed), `limit` (1–500, default 100). Returns `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", "media_type", "archived_at", "file_missing" }], "next_cursor", "total" }`.
- **DELETE /v1/archive/missing** — Admins. Delete for good the clips whose files went missing (Robert, Oct 9: hundreds of licensed clips taken off the storage). Body: `{ "library_id", "path"?, "count"?, "missing_before"?, "remove_from_projects"? }`: that library's, under that folder; or `{ "all": true, ... }` for every library's (a `path` then applies in each). Neither (or both) is a 400 `scope_required`. The API asks first: 409 `confirm_delete_missing` with `details.count` and `details.listed_at` until the request says that `count` and `missing_before` (the `listed_at`): only clips missing since before then go, so nothing that went missing after the admin looked; a different number asks again. Then, about all of them at once and before any goes, 409 `in_projects` (as emptying the trash) unless `remove_from_projects`. Clips archived by hand, in the trash or in sight never go. Returns `{ "deleted" }`. A file that comes back afterwards is a new clip.

## Projects API

Projects are transient, many-to-many sets of clips for one job (ADR-016), across libraries; what ADR-006 called collections. "Collection" is reserved for a future long-lived container. The pre-rename `/v1/collections` paths and the legacy `collection_id` field are gone (Robert, Oct 9: the API as it should be). New ids start `prj_`; ids from before the rename start `col_`.

**Lifecycle**: `status` is `active` or `archived`. Archived projects leave the default list (sidebar, pickers) but keep their clips and stay readable and exportable.

**Trash** (same pattern as assets: delete → trash → restore or delete forever): `DELETE` sets `deleted_at`. A trashed project is gone everywhere else (lists, pickers, detail, clips, export, public link: 404) until restored; only its owner sees it, in `?status=trashed` (one nobody owns, an account admin). Trash is separate from `status`, so a restored project comes back active or archived as it was. Its clips are untouched throughout; emptying the trash removes only the project.

- **POST /v1/projects** — Body: `{ "name", "description" (optional), "sort_order": "manual"|"added_at"|"taken_at" (default "manual"), "visibility": "private"|"shared"|"public" (default "private"), "asset_ids": [...] (optional), "from_search": { "filters": [{ "type", "value" }, ...], "sort"?, "direction"? } (optional) }`. Creates project owned by current user. When `asset_ids` provided, creates and populates atomically. A project is an explicit list of clips (Robert, Oct 9): `from_search` is a search as filter JSON: one `{ "type", "value" }` per filter, with the types and values of `GET /v1/query`'s `f=type:value` (`GET /v1/filters/capabilities`), and `sort` (a `GET /v1/query` sort column) and `direction` (`asc` | `desc`). It puts in the clips the search finds now, in its order, as the creator sees them (their ratings), and the project doesn't follow the search after; to keep the search, save the search (`/v1/views`). 422 `bad_search` (the message says what) for anything it can't read: an unknown key (only `filters`, `sort`, `direction`; a filter only `type` and `value`), an unknown type, a value that isn't text or doesn't parse, an unknown sort or direction. Never dropped, since that would widen the search. 422 `search_too_big` (details `max`) when more than 10,000 clips match, or when any of a text search's index searches (clips, scenes, transcripts, exact or prefix) comes back full at 5,000, since some matches would be left out. 400 with both `asset_ids` and `from_search`. The clips are checked before the project is made: one not found or in the trash is a 404 and no project. Only a tenant admin creates a project `public`: 403 for an editor whose body has it, before anything is made (as for a library's `is_public`; Robert, Oct 12). A project created public gets its public link at once. Returns 201 with `ProjectItem`.
- **GET /v1/projects** — Query: `status` (`active` default, `archived`, `all` = active and archived, `trashed` = the caller's trash). List projects owned by user + shared projects. Returns `{ "items": [ProjectItem] }`. Each item includes `ownership` ("own" or "shared"), resolved `cover_asset_id` and computed `asset_count`.
- **GET /v1/projects/{id}** — Get project detail. Returns `ProjectItem`. 404 if not found or not visible to user.
- **PATCH /v1/projects/{id}** — Body: `{ "name", "description", "visibility", "sort_order", "cover_asset_id", "status" }` (all optional, only provided fields updated). Owner only (403). `"visibility": "public"` is a tenant admin's too: 403 for an editor whose body has it, even for a project that's already public, and nothing in that body is applied. `private` and `shared` stay the owner's, so an editor who owns a public project can still take it down. Returns updated `ProjectItem`. One nobody owns: an account admin's, 403 `project_without_owner` for anyone else (as for every change below). 422 `invalid_request` for a `visibility`, `sort_order` or `status` that isn't one of its values (the same on `POST /v1/projects`).
- **DELETE /v1/projects/{id}** — Move the project to the trash. Owner only (403). Clips untouched. Returns 204. 404 if not found or already in the trash.
- **POST /v1/projects/{id}/restore** — Take the project out of the caller's trash, back to active or archived as it was. Body (optional): `{ "with_clips": true | false }`. If clips in it were trashed by someone, the body must say whether to restore them too (everywhere: library, search, other projects) or leave them: 409 `clips_in_trash` otherwise (see Decisions). Returns `{ "restored_clips", "trashed_clips" (left in the trash), "missing_clips" (files missing from disk), "archived_clips" (back in the archive, where they were) }`. 404 unless it's in the caller's trash (one nobody owns is an account admin's).
- **POST /v1/projects/empty-trash** — Delete trashed projects for good. Body: `{ "project_ids": [...] }` or `{ "all": true }` (the caller's whole trash); neither or both is a 400 `scope_required`, no body a 422. Clients should send the ids they showed, so nothing trashed meanwhile is swept up. Only the caller's own trash (an account admin's has the projects nobody owns too); active projects and other people's are never touched. Clips stay in their libraries; a public project's link is removed. Returns `{ "deleted": N }`.
- **POST /v1/projects/{id}/restore-clips** — Restore the project's clips that someone trashed, everywhere (library, search, other projects). Clips trashed because their files went missing are only counted; they come back when the files do; clips whose library is in the trash are never restored here. Editors who can see the project may call it (it's the same as restoring each clip); tenant viewers get 403. Returns `{ "restored", "missing", "archived" }`: `archived` = taken out of the trash but back in the archive, where they were (still hidden). 404 if the project is trashed or not visible.
- **POST /v1/projects/{id}/assets** — Body: `{ "asset_ids": [...] }`. Add assets to project. Owner only (403). Idempotent (duplicates ignored via ON CONFLICT DO NOTHING). Rejects trashed assets (404). Returns `{ "added": N }`.
- **DELETE /v1/projects/{id}/assets** — Body: `{ "asset_ids": [...] }`. Remove assets from project. Owner only (403). Does not affect source assets. Returns `{ "removed": N }`.
- **GET /v1/projects/{id}/assets** — Query: `after` (cursor), `limit` (1–500, default 200). Paginated asset list ordered by project's `sort_order`. Owner or shared visibility required. Returns `{ "items": [ProjectAssetItem], "next_cursor" }`.
- **PATCH /v1/projects/{id}/reorder** — Body: `{ "asset_ids": [...] }`. Reorder assets. Owner only (403). Must include ALL active asset IDs in the project. 400 if partial. Returns `{ "ok": true }`.

**ProjectItem**: `{ "project_id", "name", "description", "cover_asset_id", "owner_user_id", "visibility", "ownership", "sort_order", "asset_count", "trashed_asset_count", "missing_asset_count", "library_trashed_asset_count", "archived_asset_count", "created_at", "updated_at", "status", "archived_at", "deleted_at" }`. `asset_count` counts clips that are shown; `trashed_asset_count` counts clips someone trashed (hidden and not exported until restored); `missing_asset_count` counts clips a scan trashed because their files went missing (back when the files are); `library_trashed_asset_count` counts clips whose library is in the trash (back if the library is restored); `archived_asset_count` counts clips a person archived.

**ProjectAssetItem**: `{ "asset_id", "rel_path", "file_size", "media_type", "width", "height", "taken_at", "status", "duration_sec", "camera_make", "camera_model" }`

**Key behaviors**: Projects are user-owned (`owner_user_id`). Visibility: `private` (owner only), `shared` (all tenant users can view), `public` (anyone with link; only a tenant admin makes a project public). Mutations (add/remove/reorder/delete) require ownership. A project from before projects had owners (`owner_user_id` null) is read as any other, by whoever sees it; changing, trashing, restoring and deleting it is an account admin's (403 `project_without_owner` for anyone else; it's in no one else's trash). Asset count is computed at query time (no denormalized column). The cover shown is the chosen `cover_asset_id` while that clip is in the project and in sight, else the first active clip by position (Robert, Oct 9). The choice is cleared when a person trashes its clip (restoring the clip doesn't bring it back) or it leaves the project (removed, or deleted for good); a clip whose file went missing shows the first active clip meanwhile and is the cover again when the file is back. Trashing an asset hides it from projects but preserves the `project_assets` row; restoring the asset restores project membership and position, in every project, trashed ones included. Deleting an asset for good removes it from every project (409 `in_projects` first, see Decisions).

**Send to editor (ADR-016 v1):**

- **GET /v1/projects/{id}/export** — Query: `format` (`fcp7` = DaVinci Resolve / Premiere Pro, xmeml v5; `fcpxml` = Final Cut Pro, FCPXML 1.8). Returns the file as an attachment (`Content-Disposition` with an ASCII `filename` and the real name in `filename*`). Master clips point at the originals as the libraries know them: each library's root plus `rel_path` (Robert, Oct 9: just the server's paths; the editor relinks where its paths differ). Photos are in it too, as stills of 5 s (video only, no audio): an image asset of no length on a rate-less format in FCPXML, shown 5 s in the event and as a `<video>` on the timeline. FCP7 output is a bin of master clips (video + audio track) plus a sequence laying them end to end in bin order, since Resolve imports FCP7 XML as timelines; FCPXML is an event of asset clips plus a project whose spine does the same. The timeline takes its rate and frame size from the first probed video (no video with a known size: 1920×1080, and only photos: 30 fps); a video at another rate is rounded down onto that grid so it never runs past its media, and a still is rounded to the nearest frame (5 s is 150 frames at 29.97). Timing comes from the video facet: duration in frames, nominal rate snapped to a standard rate within 1%, start timecode (drop-frame aware; malformed ones ignored); unprobed clips use 30 fps and EXIF duration. Pages through every clip (no 1,000 cap). Headers: `X-Lumiverb-Stills` (photos, in it as stills), `X-Lumiverb-Skipped-No-Duration` (videos with no known length, left out), `X-Lumiverb-Unprobed` (videos exported at the fallback rate), `X-Lumiverb-Skipped-Trashed` (clips someone trashed, left out), `X-Lumiverb-Skipped-Missing` (clips whose files went missing, left out), `X-Lumiverb-Skipped-Library-Trashed` (clips whose library is in the trash, left out), `X-Lumiverb-Skipped-Archived` (clips a person archived, left out). Archived projects export too. 400 unknown format, 404 not found or not visible.
- **GET /v1/export/formats** — `{ "items": [{ "id", "label", "file_extension" }] }` for the format chooser.

**Paging**: `GET /v1/projects/{id}/assets` pages with `next_cursor`. Projects sorted by `taken_at` page by capture time, `COALESCE(taken_at, file_mtime, created_at)`.

**Public project endpoints (no auth required):**

- **GET /v1/public/projects/{id}** — Returns privacy-stripped project metadata: `{ "project_id", "name", "description", "cover_asset_id", "asset_count" }`. 404 if project not found, not public, or in the trash. Resolved via `public_projects` control plane table.
- **GET /v1/public/projects/{id}/assets** — Query: `after` (cursor), `limit` (1–500, default 200). Returns privacy-stripped asset list: `{ "items": [{ "asset_id", "media_type", "width", "height", "taken_at", "duration_sec" }], "next_cursor" }`. No rel_path, no camera info, no GPS.
- Asset thumbnails, proxies and video previews served via `/v1/assets/{id}/artifacts/{type}?public_project_id={id}` — verifies asset membership in the public project.

## Unified Query API

One endpoint for browsing and searching, across all libraries the caller can see. `/v1/browse` and `/v1/search` were removed in its favor.

- **GET /v1/query** — Filters are repeated `f=prefix:value` params, ANDed together. `has_gps` and `near` read the effective location: a person's, then the file's GPS; with `include_guesses:yes` applied guesses count too, and suggestions never do. Prefixes: `query` (text search), `library` (comma-separated ids), `path` (rel_path prefix), `media` (`image`|`video`), `camera_make`, `camera_model`, `lens`, `iso`, `aperture`, `focal_length`, `exposure`, `has_exposure`, `has_gps`, `near` (`lat,lon[,km]`: within km of the place, 1 unless said; a place off the earth or a distance not above 0 and at most 20,000 km is a filter that doesn't parse, ignored), `include_guesses` (`yes`: a modifier for `has_gps` and `near`; alone it matches every clip), `date` (`YYYY-MM-DD,YYYY-MM-DD`, either side optional), `favorite` (`yes`), `stars` (`4`, `4+`, `2-4`, `-3`), `color` (comma-separated), `has_color`, `has_rating`, `has_faces` (`yes`|`no`), `person`, `tag`, `project` (clips in that project), `not_project` (clips not in it). A project filter shows what someone put in a project, so it's for an editor who can see the project, as `GET /v1/projects/{id}` (its owner, or shared): 403 for a viewer or a public page's visitor, 404 for a project they can't see, one in the trash, or no id (never dropped, which would widen the search). The facets and a project made from a search (`from_search`) check it the same way. Unknown prefixes are ignored; a NUL, or bytes that aren't UTF-8, in any `f` value is a 400 `not_text`, as anywhere in a URL (the facets' too; no filter's value holds one). `GET /v1/filters/capabilities` lists every filter for generic client rendering. Other params: `sort` (`taken_at` default, `created_at`, `changed_at` (a clip's last modified time: the most recent of every time related to it, its file changing, anything Lumiverb made for it, what a person changed, as a description, note, location or face named; not a rating, which is one person's, nor a try that failed; the database keeps it), `file_size`, `iso`, `exposure_time_us`, `aperture`, `focal_length`, `rel_path`, `asset_id`), `dir`, `after` (cursor), `limit` (1–500, default 200). With a `query:` filter, the text search (see Search) produces up to 5,000 candidates, the other filters apply to them, and results are ordered by relevance; each item carries `search_context` `{ "score", "hit_type": "asset"|"scene"|"transcript", "snippet", "start_ms", "end_ms" }`. Rating filters join the caller's own ratings. Returns `{ "items": [QueryItem], "next_cursor", "total_estimate", "search_source": "postgres"|"none"|null }` (`none`: search terms without a word in them). A public page's visitor (no auth) may query a public library: every `library:` must be public and there must be one (else 403/404); rating and person filters are refused (403); a public page's text search never reads notes or paths, and while public playback is capped it leaves out the whole transcript and scene and transcript hits from past the cap.

**QueryItem**: asset fields (`asset_id`, `rel_path`, `file_size`, `media_type`, dimensions, `taken_at`, `duration_sec`, camera and exposure fields, GPS, `face_count`, `thumbnail_key`, `proxy_key`, `created_at`, `changed_at`) plus `library_id`, `library_name` and `search_context`. A public library's visitor gets the visitor view: no `rel_path` (empty), size, camera, exposure, GPS, keys, face count or last modified time; and the location filters (`has_gps`, `near`, `include_guesses`) and camera and exposure filters (`camera_make`, `camera_model`, `lens`, `iso`, `aperture`, `focal_length`, `exposure`, `has_exposure`) are 403 for them, as are rating and person filters (repeated `near` searches would find where a clip was shot). Folder browsing stays public (`/directories`, `path`). `/v1/similar` hits leave out paths and keys for them too, and public facets count no cameras, exposure ranges or locations.

## Ratings API

User-scoped asset ratings: favorites (heart), stars (1-5), color labels. Each user has independent ratings per asset. Ratings are private — never visible to other users. All endpoints require auth; user identity comes from JWT `sub` or API key `key:{key_id}`.

Rating filters are available on `GET /v1/query` (`f=favorite:yes`, `f=stars:3+`, `f=color:red`, `f=has_rating:yes`). They LEFT JOIN `asset_ratings` for the current user; without rating filters, no JOIN is added (zero cost).

**Face filter**: `f=has_faces:yes|no` on `GET /v1/query`. `yes` returns only assets with `face_count > 0`; `no` returns assets with no detected faces (face_count=0 or NULL). Applied in SQL.

- **GET /v1/assets/favorites** — List favorited assets across all libraries for the current user, newest first. Query: `after` (cursor), `limit` (1–500, default 200). Returns: `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", ... }], "next_cursor" }`. Paginated by `updated_at DESC`.

- **PUT /v1/assets/{asset_id}/rating** — Set or update rating on a single asset. Body: `{ "favorite": bool, "stars": int (0-5), "color": string|null }`. All fields optional — only provided fields are updated. Color values: `red`, `orange`, `yellow`, `green`, `blue`, `purple`, or `null` to clear. If all fields are default (favorite=false, stars=0, color=null), the rating row is deleted. Returns: `{ "asset_id", "favorite", "stars", "color" }`. 404 if asset not found or trashed. 422 for invalid stars/color.
- **PUT /v1/assets/ratings** — Batch rate multiple assets. Body: `{ "asset_ids": [...], "favorite": bool, "stars": int, "color": string|null }`. Same merge semantics as single — only provided fields are updated across all listed assets. Returns: `{ "updated": int }`. 404 if any asset not found. 422 for invalid values, empty asset_ids, or more than 10,000.
- **POST /v1/assets/ratings/lookup** — Bulk read ratings. Body: `{ "asset_ids": [...] }`. Returns: `{ "ratings": { "asset_id": { "favorite", "stars", "color" }, ... } }`. Assets with no rating are omitted from the map. At most 10,000 asset_ids (422 past it).

Ownership: when a user is deleted via `DELETE /v1/users/{user_id}`, all their ratings are removed from the tenant DB.

## Admin API

The server admin's routes (Roles), under `/v1/admin`: a server admin signed in, or the install's own key, `Authorization: Bearer {ADMIN_KEY}` from its env file (what runs on it: Linux's first account in deploy-api.sh, the CLI's `lumiverb admin` there). An account's keys, a server admin's included, get 403 `server_admin_required`.

- **POST /v1/admin/tenants** — Body: `{ "name", "plan": "free|pro|enterprise", "email", "vision_api_url", "vision_api_key" }` (a vision URL becomes the tenant's first AI machine doing vision, named after its host). Creates tenant, provisions tenant DB (pgvector + Alembic), creates routing row, creates default API key. Returns `{ "tenant_id", "api_key", "database": "provisioned" }`. On failure, cleans up and returns 500. With an `email`, its first admin too, invited as a user is (`invite_urls`, `invite_expires_at`: the link to send them, shown once; 409 `email_conflict` when someone signs in with it already): the web app's Admin › Accounts.
- **GET /v1/admin/tenants** — Returns list of tenants with `tenant_id`, `name`, `plan`, `status` (`active`, or `deleted`), `users` (the people who sign in to it), `created_at` and `folders` (below; `null`: every folder the server reads) (no API keys, no vision credentials).
- **PUT /v1/admin/tenants/{tenant_id}/folders** — Body: `{ "folders": [...] | null }` (required: a list of at most 100, or `null`). The folders on this server the account's libraries may be in: a library this server reads for it is then made, moved and handed to this server only inside one of them (Libraries API, 403 `outside_account_folders`), and this server's reader reads one only where its folder, resolved on disk, leads inside them (Readers API). `null`, every account's until a server admin gives it folders, is every folder the server reads, as before: a server with one account needs none. `[]`: none on this server, so only the account's own devices read its libraries. Each folder is in the form a library's `root_path` is (absolute, no `.`, `..` or empty part, no trailing `/`, no backslash, no control character, at most 4,096 characters): 422 `invalid_folder` (`details.folder`) otherwise; kept once each, in the order given, as written (before the root map). Where the server's root map bounds what it reads (`LUMIVERB_ROOT_MAP` naming folders: a Linux install's), one outside it is 422 `folder_not_read` (`details`: `folder`, `root_map`). 409 `folders_overlap` for one equal to, inside or holding another live account's (`details`: `folder`, `account`, `tenant_id`, `theirs`; a deleted account's count for nothing). 409 `libraries_outside` when a library this server reads for the account, in the trash too, would be outside them (`details.libraries`: `library_id`, `name`, `root_path`, `trashed`; the message names them): move them first, or include their folders. 503 `account_unavailable` when its database can't be read, so its libraries can't be checked (`null` needs nothing read). 404 for no such account, or a deleted one. A library's folder being saved and a change of the account's folders wait for each other, and one change of any account's folders goes at a time, so neither is decided on what the other is changing. Returns `{ "tenant_id", "folders" }`. The web app's Admin › Accounts, which says when, with more than one account, any has no folders of its own.
- **PATCH /v1/admin/tenants/{tenant_id}** — Body: `{ "name", "vision_api_url", "vision_api_key", "vision_model_id" }` (`name`: renamed, 1 to 100 characters, no control characters) (all optional; only provided fields are updated). Updates tenant vision API config. Returns `{ "tenant_id", "vision_api_url", "vision_model_id" }`. 404 if tenant not found or deleted. Returns its `name` too.
- **POST /v1/admin/tenants/{tenant_id}/keys** — Body: `{ "name" }` (human-readable label). Creates new API key for tenant. Returns `{ "api_key", "name", "tenant_id" }`. Raw key returned once and never stored. 404 if tenant does not exist or is soft-deleted; 400 `scheduler_label` for the name `scheduler`, in any case (the scheduler's own key's).
- **GET /v1/admin/tenants/{tenant_id}/keys** — Returns list of key metadata: `name`, `tenant_id`, `created_at` (never raw keys). 404 if tenant does not exist or is soft-deleted.
- **DELETE /v1/admin/tenants/{tenant_id}** — Query: `confirm`. Deletes an account: kept (its database and rows), never reached again: nobody signs in to it (login 403, a token or key 401 `account_deleted`), its API keys are revoked, its public links answer nothing, and upkeep and the scheduler don't work on it. 409 `confirm_delete_account` (`details`: `name`, `users`, `libraries`, `clips`; the last two null when its database can't be read) until `confirm` is its name as it is (Decisions the API requires). 409 `own_account` for the account of the server admin signed in asking; 409 `last_server_admin` when it holds the only server admins of accounts not deleted (the server admins are held while it's decided, so two deleting each other's accounts at once leave one). 404 for no such account, or one deleted already. Returns 204.
- **GET /v1/admin/server-admins** — The install's server admins, by email: `{ "server_admins": [{ "user_id", "email", "tenant_id", "account" }] }` (`account`: their account's name).
- **POST /v1/admin/server-admins** — Body: `{ "email" }`: someone who signs in here, in any account, becomes a server admin at once (one already is: nothing changes). Their links not yet used (an invite, a reset) end with it: one an account admin made them before would set a server admin's password, and only a server admin gives a server admin a link. Returns the list as GET, with `links_ended`: how many still-good links stopped working (0 when none). 404 `user_not_found` when nobody here has that email. `lumiverb-server server-admins add` does the same and says so.
- **DELETE /v1/admin/server-admins/{user_id}** — They're no longer a server admin, at once; their sign-in and account stay. 204. 404 when they aren't one; 409 `last_server_admin` for the last one who can sign in, one in an account not deleted (name another first; on the machine itself `lumiverb-server server-admins remove` takes the last too, as whoever is there can always name another).

## Content hashes

A clip's `content_hash` is its file's content hash (`src/shared/content_hash.py`), what moves, a person's trash, a changed file and lineage (`source_hash`) compare. Every content hash names how it was made, its scheme:

```
content-hash = scheme ":" value
scheme       = 1 to 32 of a-z 0-9              (lowercase letters and digits)
value        = 1 to 128 of A-Z a-z 0-9 . _ ~ -  (the scheme's to define)
```

Two hashes name the same content only when scheme and value are both equal; hashes of different schemes are never compared, and nothing is stored that isn't one. The server's own schemes are fixed, and the only ones the API takes for now (a bare hash, or any other, is refused: 422 in a JSON body, 400 in a form, the message naming what it takes):

- `sha256:` and 64 lowercase hex: the SHA-256 of every byte, for a file up to 64 MiB;
- `fp1:` and 64 lowercase hex: a SHA-256 of 3 MiB of a bigger file (its size, its first and last MiB and 16 samples of 64 KiB between), however big. It misses an edit between its samples that keeps the size.

Any other way of hashing is another scheme. A reader that isn't this server's own (a client with its own scanner) can say which scheme it hashes with only once the API takes others; until then it hashes as these say. A clip over 64 MiB hashed before fp1 has its whole file's `sha256:` hash until a scan finds it unchanged and swaps it for its fp1 (with its lineage's: nothing is stale); until then a file of its size is hashed whole too (`legacy`), so it's compared with what was. A clip's content hash changes only that way (another file is another clip), so lineage given the whole file's hash of a clip known by its fp1 since (work handed out before the swap) is recorded as made from its fp1.

## Search

Search is PostgreSQL's full-text search in the account's database (ADR-019), and only `src/server/search/text_search.py` knows the engine: a clip's own words (`asset_search`: its description and tags as a person sees them, text read in it, note, transcript and path), its scenes' (`video_scenes.words`) and its transcript's segments (`transcript_segments`), each searched among the clips in sight. Words are read as English and stemmed ("dogs" finds "dog"), a path's too, in any language's letters, with accents set aside both ways ("zurich" finds "Zürich" and the other way round; what's shown keeps them) and a hyphenated word as its parts (a quoted "John Wayne Airport" finds "John Wayne Airport-Orange County"; "Raleigh-Durham" as typed still finds it), as typed words are read the same way. Chinese and Japanese aren't split into words. Descriptions, tags and notes weigh most, then an installed plug-in's facts (its searchable outputs, `plugin_outputs.words`, read by an account's own search for the plug-ins on in it: never a public page's; a fact that matches is the hit's `snippet` when it scores above the clip's own words), then text read in a picture and transcripts, then paths.

**Query syntax**: unquoted input is loose — `negative space` matches any document containing either word, with a soft ranking boost when both appear as an adjacent phrase. Wrapping input in double quotes requires the exact contiguous phrase — `"negative space"` only matches documents where those two words appear adjacent. Mixed input like `"negative space" beach` is treated as "must contain the phrase AND must contain beach". An unquoted word of three letters or more also matches as a prefix, ranked at half a whole word (`disney` finds "Disneyland"); quoted phrases are not prefix-expanded (`"disney"` will not match "disneyland"). Several `query:` filters must each match. Unmatched trailing quotes are ignored.

**Size**: a search is at most 32 words (a quoted phrase's words each count), and at most 16 `query:` filters are combined, far above what anyone types, a public page's search too (`text_search.py` `MAX_WORDS`, `MAX_TERMS`). Past either, `GET /v1/query`, the facets and a project made from the search (`from_search`) answer 400 `search_too_long`, the message saying which and how many (the web app shows it under its search box), `details`: `{ "max_words": 32, "max_searches": 16 }`.

Text search runs through `GET /v1/query` with an `f=query:...` filter (see Unified Query API). Asset, scene and transcript hits are merged per asset; `search_context.hit_type` says which matched.

**Similarity:**

- **GET /v1/similar** — Find visually similar assets by vector similarity (pgvector). Query params: `asset_id` (required), `library_id` (required), `limit` (default 20, max 100), `offset` (default 0, max 10000). Optional scope filters: `from_ts`, `to_ts` (Unix timestamp seconds, inclusive capture-time range; uses `assets.taken_at`); `asset_types` (comma-separated: `image`, `video`; restricts by `media_type` prefix); `camera_make` and `camera_model` (repeatable; pairs by index, OR across pairs). Returns `{ source_asset_id, hits, total, embedding_available }`. Excludes the source asset from results. If both `from_ts` and `to_ts` are set, `from_ts` must be ≤ `to_ts` (422 otherwise). Person-aware reranking: if the source asset has identified faces, candidates containing the same named person(s) receive a similarity boost (distance *= 0.85).
- **POST /v1/similar/search-by-image** — Body: `{ "library_id", "image_b64", "limit", "offset", "from_ts", "to_ts", "asset_types", "cameras" }`. Upload a query image (base64) and find similar assets. Returns `{ "hits", "total" }`. Server CLIPs the upload — only works for libraries indexed with `model_id="clip"` — and looks for faces in it, fusing the clips with those people in, as by vector in hybrid mode (below); with no faces, or a face path that fails, the ranking is by look alone. iOS's photo search and the CLI's `similar image` use it. `limit` 1–100 (default 20), `offset` 0–10,000, `image_b64` at most about 8 MB decoded: 422 `invalid_request` outside them. The image must be a JPEG, PNG or WebP of at most 120 megapixels (`src/server/images.py`): no other format is read, and its size is checked before anything is decoded. 422 `invalid_image` for text that isn't base64, or an image that isn't one of those (its details say what is: `{ "formats": ["JPEG", "PNG", "WEBP"], "max_pixels": 120000000 }`). The embedding and face detection run in the request: they are the search. The faces are found in a process of the API's own, the faces producer's (`src/server/faces/server_face_provider.py`): the API's process never loads the face model, whose runtime leaks with every picture; the process is replaced after 20 pictures, given up on after 60 s (the search goes on by look alone) and let go of after 5 idle minutes. 20 searches by picture a minute from one address, then 429.
- **POST /v1/similar/search-by-vector** — Body: `{ "library_id", "vector", "model_id", "model_version", "limit", "offset", "from_ts", "to_ts", "asset_types", "cameras", "image_b64" (optional) }`. Search by a pre-computed embedding vector (1–4,096 floats); the same bounds and `invalid_image` as by image. For clients that embed locally (none of Lumiverb's own now: iOS sends the picture by image). The model_id / model_version must match how the library was indexed. **Hybrid mode**: when `image_b64` is also supplied, the server runs InsightFace face detection on the image, embeds each face with ArcFace, runs per-face cosine search against `faces.embedding_vector`, and fuses the identity matches with the scene cosine results via Reciprocal Rank Fusion (k=60). RRF operates on ranks, not raw distances, so it's robust across embedding model spaces. The face path degrades gracefully when no faces are detected, the InsightFace runtime is unavailable, or the image (a JPEG, PNG or WebP within the limit, as by image) fails to decode — the response falls back to scene-only ranking. Returns `{ "hits", "total" }`.

## Migrations

Alembic manages schema. Two migration contexts:
- `control_plane` — migrations for the shared control plane DB
- `tenant` — migrations applied to each tenant DB on provisioning and upgrade

When adding a column or table to the tenant schema, always add a corresponding Alembic migration in the tenant context.

A rollback, on the machine with the service stopped, is the newer release's: `lumiverb-server migrate --to REVISION` takes every account's database down (or up) to that revision, and `--control-to REVISION` the control plane's (`src/server/lifecycle/migrate.py` `migrate_to`). It's refused while anything is connected to the databases (as a restore is), and starts a Mac's own PostgreSQL for the while. Around an upgrade, `lumiverb producers --compare BEFORE AFTER` compares two saved `GET /v1/producers?counts=true` answers by name: each producer's counts, settings, pause, stopped redo and `new_version` (exit 1 when any changed).
