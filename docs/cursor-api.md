## Stack

- Python 3.12
- FastAPI + SQLModel + Alembic
- PostgreSQL 18 (per-tenant database model)
- Quickwit (BM25 search)
- Object storage via abstraction layer (GCS / S3 / B2 / MinIO)

## Non-Negotiables

- Every route lives under `/v1/`
- All routes require `Authorization: Bearer {token}` header (token is a JWT for web sessions or an API key for CLI/automation)
- Tenant context is always derived from the token (JWT claims or API key lookup) — never passed as a URL param or body field
- Pagination is cursor-based, never offset-based
- File uploads are multipart form data
- File serving uses signed URLs (cloud) or direct proxy (self-hosted) — never expose raw object storage URLs
- Error responses always use this envelope: `{"error": {"code": "...", "message": "...", "details": {...}}}`
- OpenAPI spec is generated automatically from route definitions — keep docstrings accurate

## Database Model

Two-layer Postgres architecture:

**Control plane DB** (shared, tiny):
- `tenants` — tenant_id, name, plan, status, vision_model_id (the vision job's model), transcript_model_id (the transcripts job's, `small` until changed), created_at
- `ai_machines` — machine_id, tenant_id, name, api_url, api_key, jobs, at_once, enabled, built_in (one per tenant), online, status_error, models, checked_at, created_at (see AI machines API)
- `api_keys` — key_id, key_hash, tenant_id, name, label, scopes, role (`admin`|`editor`|`viewer`), created_at, last_used_at, revoked_at
- `users` — user_id, tenant_id, email, password_hash, role (`admin`|`editor`|`viewer`), created_at, last_login_at
- `password_reset_tokens` — token_hash, user_id, expires_at, used_at
- `public_libraries` — library_id, tenant_id, connection_string, created_at
- `public_projects` — project_id, tenant_id, connection_string, created_at
- `revoked_tokens` — jti (PK), revoked_at. Tracks revoked JWTs for server-side logout/refresh revocation. Cleaned up by upkeep sweep (entries older than 8 days).
- `tenant_db_routing` — tenant_id, connection_string, region

**Tenant DB** (one per tenant, same Postgres instance):
- `libraries` — library_id, name, root_path, status, last_scan_at (updated on each ingest via bump_revision), is_public, revision (int, bumped on asset ingest), created_at, updated_at
- `library_path_filters` — filter_id (lpf_+ULID), library_id FK, type (include|exclude), pattern, created_at. Controls which paths are ingested per library.
- `tenant_path_filter_defaults` — default_id (tpfd_+ULID), tenant_id, type (include|exclude), pattern, created_at. Tenant defaults and library filters are merged at evaluation time (see filter evaluation rules below).
- `assets` — asset_id, library_id, rel_path, sha256, file_size, file_mtime, media_type, width, height, duration_sec, proxy_key, proxy_sha256, thumbnail_key, thumbnail_sha256, exif (JSON), exif_extracted_at, camera_make, camera_model, taken_at, gps_lat, gps_lon, iso, exposure_time_us, aperture, focal_length, focal_length_35mm, lens_model, flash_fired, orientation, availability, status, video_indexed, video_preview_key, error_message, created_at, updated_at, deleted_at, search_synced_at
- `video_scenes` — scene_id, asset_id, scene_index, start_ms, end_ms, rep_frame_ms, proxy_key, thumbnail_key, rep_frame_sha256, description, tags (JSONB), sharpness_score, keep_reason, phash, created_at, search_synced_at
- `video_index_chunks` — chunk_id, asset_id, chunk_index, start_ms, end_ms, status, worker_id (CLI-generated session ID), claimed_at, lease_expires_at, completed_at, error_message, anchor_phash, scene_start_ms, created_at
- `asset_metadata` — metadata_id, asset_id, model_id, model_version, generated_at, data (JSONB)
- `asset_embeddings` — embedding_id, asset_id, model_id, model_version, embedding_vector vector(512), created_at
- `asset_ratings` — user_id (text), asset_id FK (ON DELETE CASCADE), favorite (bool, default false), stars (int 0-5, default 0), color (text, nullable; red|orange|yellow|green|blue|purple), updated_at. PK: (user_id, asset_id). User-scoped ratings — each user has their own independent ratings per asset.
- `saved_views` — view_id (sv_+ULID), name, query_params (URL query string), icon (nullable), owner_user_id, position (int), created_at, updated_at. User-scoped bookmarked filter presets. Navigates to `/browse?{query_params}`.
- `system_metadata` — key, value, updated_at
- `faces` — face_id, asset_id, bounding_box_json, embedding_vector vector(512), detection_confidence, detection_model, detection_model_version, created_at. Populated by CLI face detection (InsightFace). HNSW index on embedding_vector for future clustering.
- `people` — person_id, display_name, created_by_user, centroid_vector vector(512), confirmation_count, representative_face_id FK, created_at. Populated via People API and cluster management UI.
- `face_person_matches` — face_id, person_id, confidence, confirmed bool, confirmed_at. Populated when faces are assigned to people. Unique constraint on face_id (one person per face).

pgvector extension is enabled at provisioning time. Used for asset embeddings (CLIP), face embeddings (ArcFace), and similarity search.

### Soft delete — always use `active_assets`

Assets are soft-deleted via `deleted_at` (set by trash operations). The `active_assets` view is defined as:

```sql
SELECT * FROM assets WHERE deleted_at IS NULL
```

**Non-negotiable rules — enforced by tests in `tests/test_soft_delete_invariants.py`:**

1. **Never query `FROM assets` directly** in any read path that should return live assets. Always use `FROM active_assets` in raw SQL, or add `.where(Asset.deleted_at.is_(None))` in ORM queries.
2. **`AssetRepository.get_by_id()` returns `None` for trashed assets.** Do not use `session.get(Asset, id)` as a substitute — it bypasses the filter.
3. **`get_by_library_and_rel_path()` intentionally returns trashed assets** because the ingest upsert path needs to detect them to avoid a unique-constraint violation on `(library_id, rel_path)`. It is the only read method that does this. Ingest clears `deleted_at` on update when the file was missing (a file present on disk is back), but never for a person's trash or archive (409).

**Why a clip is out of sight** (`deleted_reason`; `deleted_at` is when it got there). Robert's model (Oct 8): archive = out of sight, kept forever; trash = the person wants it gone, restorable until it's deleted for good after the account's trash days.

| Reason | Kind | Comes back | Deleted for good |
|---|---|---|---|
| `archived` | archive: a person archived it | `POST /v1/assets/unarchive` | never on its own; trash it first, or with its library |
| `missing` | archive: a scan no longer finds the file | by itself when the file returns (by path; by content when following moves) | never on its own; trash it first, or with its library |
| `user` | trash: a person trashed it | `POST /v1/assets/restore`, back to where it was (`trashed_from`) | after the trash days, or emptied by hand |
| `library` | trash: it went with its library | with the library (`POST /v1/libraries/{id}/restore`) | with the library |
| `handed_over` | transient, inside a copy-then-delete handover | — | in the same transaction |

Scans skip `archived` and `user` paths (`ignored-paths`). Trashing an archived clip makes it `user`, restarts its clock and remembers what it was (`trashed_from`), so restoring it puts it back in the archive. Purges re-check under a row lock: whatever was restored, archived or trashed again since it was listed is never deleted, and a restore arriving mid-purge waits, then finds it gone.
When writing queries, always use the tenant DB session, not the control plane session. The middleware resolves this from the bearer token before the route handler runs.

Tenant resolution runs for every request except `/health`, `/v1/admin/*`, `/v1/auth/*`, and `/v1/upkeep*`: reads `Authorization: Bearer <token>`, attempts JWT decode first (signature + expiry + required claims: `sub`, `tenant_id`, `role`; checks `jti` against `revoked_tokens` table), falls through to API key lookup on JWT failure, looks up `TenantDbRouting` for the connection string, and stores `tenant_id`, `connection_string`, `user_id`, `key_id`, `role`, and `is_public_request` in `request.state`. Use the `get_tenant_session` dependency in route handlers to obtain a tenant DB session.

All API responses include security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy` (script-src 'self', frame-ancestors 'none'), `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/microphone/geolocation denied).

## Tenant Context

- **GET /v1/tenant/context** — Tenant auth required. Returns `{ "tenant_id", "vision_api_url", "vision_api_key", "vision_model_id" }`: the first enabled AI machine doing vision and the vision model, for clients that know one endpoint (the Mac app). The worker reads all the vision job's machines from `GET /v1/ai/jobs/vision`. `vision_api_key` is `""` unless the caller is an editor or admin.
- **GET /v1/tenant/settings** — Any signed-in role. Returns `{ "video_preview_max_seconds", "public_video_preview_max_seconds", "follow_moves", "trash_days" }`: how many seconds of each video playback serves signed in (`null`, the default, for the whole video) and on public pages (10 until set; `null` once lifted), and whether moves and renames are followed (`true`, the default). Public pages get the smaller of the two caps. Stored in the tenant DB's `system_metadata`. **Follow moves** on: the same content is the same asset, so ingest restores an archived asset by content, scanners apply moves (`POST /v1/assets/batch-moves`), and a file that goes missing while an empty, newer copy of it is in the library moves to the copy (see `DELETE /v1/assets`). Off: the path is the only identity, so a file at a new path is a new asset and nothing is matched by content. **Trash days** (`trash_days`, 30 until set; 1–3,650, or `null` for never): how long clips a person trashed, libraries and projects stay in the trash before upkeep deletes them for good. Archived clips aren't deleted on their own; they go only with their library. `PATCH` takes `confirm_purge`: fewer days (or turning them back on) answers 409 `trash_days_shortened` when it would delete things at once, until it's true (see Decisions).
- **PATCH /v1/tenant/settings** — Admins only (403 otherwise). Body: any of the fields; one left out stays as it is. The caps take `<1..86400 | null>` (`null` means the whole video; 422 for anything but a whole number in range), `follow_moves` takes `true` or `false` (422 otherwise). A cap change clears the cuts made for the old caps. Returns the settings. Web: Settings → Playback and Settings → Files; CLI: `lumiverb settings video-preview` / `public-preview` / `follow-moves`.

## Auth API

Routes under `/v1/auth`; no tenant auth required (these establish auth).

- **POST /v1/auth/login** — Body: `{ "email", "password" }`. Returns `{ "access_token", "token_type": "bearer", "expires_in" }`. JWT contains `sub` (user_id), `tenant_id`, `role`, `jti` (unique token ID), `iat`, `exp` (1 hour), `refresh_exp` (7 days). Rate limited: 5 requests/min per IP.
- **POST /v1/auth/refresh** — Requires `Authorization: Bearer {token}` (may be expired). Issues a fresh JWT if the token is within its 7-day refresh window and not revoked. Revokes the old jti. Returns `{ "access_token", "token_type", "expires_in" }`. The frontend calls this transparently on 401.
- **POST /v1/auth/forgot-password** — Body: `{ "email" }`. Sends password reset email if SMTP configured. Always returns 204 (no user enumeration). Rate limited: 3 requests/min per IP.
- **POST /v1/auth/reset-password** — Body: `{ "token", "password" }`. Resets password using a reset token. Returns 204. Rate limited: 5 requests/min per IP.
- **POST /v1/auth/logout** — Revokes the JWT server-side (inserts jti into `revoked_tokens`). The token cannot be used or refreshed after logout. Returns 204.

## Users API

All routes under `/v1/users`; require tenant auth and **admin** role.

- **GET /v1/users** — List all users for the current tenant. Returns list of `{ "user_id", "email", "role", "created_at", "last_login_at" }`.
- **POST /v1/users** — Body: `{ "email", "password", "role": "viewer" }`. Creates user. Returns 201 with user details.
- **PATCH /v1/users/{user_id}** — Body: `{ "role" }`. Updates user role. Enforces last-admin invariant (cannot demote the last admin). Returns updated user.
- **DELETE /v1/users/{user_id}** — Removes user. Enforces last-admin invariant and blocks self-deletion. Returns 204.

## Current User

- **GET /v1/me** — Returns `{ user_id, email, role }` for the authenticated user. For JWT auth, looks up email from the users table. For API key auth, `user_id` and `email` are null; only `role` is returned.

## API Keys

All routes under `/v1/keys` require tenant auth and **editor or admin** role.

- **GET /v1/keys** — List all non-revoked keys for the current tenant. Requires editor or admin. Never includes plaintext.
- **POST /v1/keys** — Create a new key. Body: `{ label }`. The key inherits the caller's role (body cannot override it). Returns `{ key_id, label, role, plaintext, created_at }`. The `plaintext` value is shown exactly once.
- **DELETE /v1/keys/{key_id}** — Revoke a key. Returns 204. A key cannot revoke itself (409). The last admin key cannot be revoked (409).

## AI machines API

ADR-016 phase 3. The account's AI runs on **machines**: GPU boxes, each an OpenAI-compatible endpoint (such as Ollama) with an optional key, the **jobs** it does and how many requests it takes at once (`at_once`). Each job has **one model** for the account, and a machine does a job only if it offers that model, so an artifact is the same model's whatever machine made it (which machine isn't tracked, like the encoder). Machines live on the control plane (`ai_machines`); the one place they live. Web: Settings → AI (Robert's call, Oct 8: machines, each with jobs).

Jobs (`src/shared/ai_jobs.py`):
- `vision`, "Descriptions & text": descriptions, OCR and scene descriptions, on OpenAI-compatible chat endpoints (Ollama). Its model is the tenant's `vision_model_id`.
- `transcripts`, "Transcripts": Whisper. Its model is the tenant's `transcript_model_id`, `small` until changed (what every transcript before it recorded). A machine doing it serves OpenAI's `GET /models` and `POST /audio/transcriptions` with `response_format=verbose_json` (segments with their times): speaches, or LocalAI. A whisper.cpp server lists no models, so it can't be checked: not supported; Ollama doesn't do Whisper. The worker finds the speech in each clip itself, with faster-whisper's VAD and the transcript producer's `vad_min_silence_ms`, sends only the speech (asking the server not to skip silences of its own, `vad_filter=false`, and to time its segments, `without_timestamps=false`), and maps the times it gets back onto the clip. So the settings a transcript's lineage records (the model and the silences skipped) are the ones it was made with, whichever machine heard it. How a server decodes isn't tracked, like the encoder: current speaches also skips silences over 160 ms within what it's sent and decodes pieces of at most 30 s at temperature 0, so its cues and an occasional word can differ from the built-in's.

**The built-in machine.** Every tenant has one (`built_in: true`, listed first): the scheduler's own computer, with no URL or key, doing the jobs the scheduler does itself (Whisper: transcripts), one at a time until changed. Every account gets it (control migration `b6591b39778f`; new tenants at creation), so transcripts run with nothing set up. It can be renamed, given another `at_once`, turned off, or have transcripts taken away; not removed, given a URL or key, or given a job it can't do (409 `built_in_machine`). The server can't reach it: it offers the models faster-whisper knows, and only the worker says whether it's online (faster-whisper installed, and the model one it knows). The worker that runs it is whichever runs the transcribe step (the brain's).

**One name per model.** faster-whisper calls a model by a short name (`small`) or by the Hugging Face repo it loads it from (`Systran/faster-whisper-small`), which is what speaches lists. They're one model (`src/shared/whisper_models.py`): machines' models, Connect's answer and a job's model use the short name; the worker asks each server for it by the name it lists. Any other name is a model of its own.

- **GET /v1/ai** — Signed in. Returns `{ "machines": [{ "machine_id", "name", "api_url", "has_key", "jobs", "at_once", "enabled", "built_in", "shares_gpu", "status": { "online", "error", "models", "checked_at" } | null }], "jobs": [{ "job", "label", "model", "machines", "offering", "choices", "built_in" }] }`, the built-in machine first, then in the order added. Keys are never returned. `status` is the latest check (the worker's, or Connect's when the machine was saved); `jobs[].machines` counts the enabled machines doing the job, `offering` those that offered its model when last checked, `choices` the models they offer (the built-in's: faster-whisper's), and `built_in` whether the built-in machine can do it.
- **POST /v1/ai/connect** — Admins. Body: `{ "api_url", "api_key"?, "machine_id"? }` (`api_key` left out: that machine's saved key, when `api_url` is its URL; `""`: none). Asks `GET {api_url}/models`. Returns `{ "models": [ids by their one names, sorted] }`. 502 `machine_unreachable` with a plain message when it can't say (unreachable, timed out, refused the key, not OpenAI-compatible, no models).
- **POST /v1/ai/machines** — Admins. Body: `{ "name", "api_url", "api_key"?, "jobs": [...], "at_once": 1–32 (default 2), "enabled"?, "shares_gpu"? }`. `shares_gpu`: it runs on the server the scheduler decodes video on; while video is decoded there it takes fewer requests, down to none (video work comes first; the built-in machine always shares it). PATCH takes it too. The machine is asked for its models: 502 `machine_unreachable` when it can't say, 409 `model_not_offered` (`details`: `job`, `model`, `models`) when it lacks a job's model, 409 `name_taken`; 422 for an unknown job, an empty name or URL, or `at_once` out of range. What it offered is its status. Returns 201 with the settings.
- **PATCH /v1/ai/machines/{id}** — Admins. Any of the fields above (the built-in machine: `name`, `jobs` it can do, `at_once`, `enabled`; anything else is 409 `built_in_machine`, and it's never asked: the worker checks it); `api_key` left out keeps the saved one. When its URL or key changes, it's given a job it hadn't, or it's turned back on, it's asked again (502, 409 as above); a rename or a new limit isn't, so a machine that's asleep can still be edited. A new URL without `api_key` drops the saved key (it never goes to another host). Turning off the last machine doing a job, or taking the job from it, never asks: the job's work waits, and `GET /v1/producers` says why (`waiting`). Returns the settings; 404 for another tenant's or an unknown machine.
- **DELETE /v1/ai/machines/{id}** — Admins. The last machine doing a job too, without asking (its work waits); 409 `built_in_machine` for the built-in one (turn it off instead). Returns the settings; 404 for another tenant's or an unknown machine.
- **PUT /v1/ai/jobs/{job}** — Admins. Body: `{ "model" }` (a faster-whisper repo is kept by its short name); `""` turns the job off. Every enabled machine doing the job is asked (what it says is its status; the built-in one isn't asked: it offers faster-whisper's models): 409 `model_not_offered` (`details.machines`: `machine_id`, `name`, `models`, `error`) when none offers the model. Changing the model makes the job's artifacts stale, and they're made again after anything missing (see Producers API): 409 `redo_on_change` (see Decisions) asks first, naming how many clips; resend with `"redo": true`. Turning a job off, or on with the same settings (a default model), asks nothing. Saving a new model resumes the job's producers' redo if an admin had stopped it. 404 for an unknown job. Returns the settings.
- **GET /v1/ai/jobs/{job}** — Editors and admins (the scheduler). Returns `{ "job", "model", "machines": [{ "machine_id", "name", "api_url", "api_key", "at_once", "built_in" }] }`: the enabled machines doing it, with their keys, in order (`built_in`: the worker does it itself). 403 for a viewer.
- **POST /v1/ai/machines/{id}/status** — Editors and admins (the scheduler). Body: `{ "online", "error"?, "models"? }`: its check of the machine. Returns 204. The worker checks each machine before a job's work and sends requests only to online ones offering the model, each up to its `at_once`, least busy for its size first; a machine that fails a request for its own reasons (unreachable, refused, the model gone or not loading, out of memory, a server error or one that broke off, not speaking the API: no timed segments, or times that can't be seconds) is skipped (the item goes to another, trying each machine once) and checked again a minute later. Only with no machine left, or the job off, does the job's work wait, and no clip is charged a failure; the worker leaves those clips out of a cycle's work. An item the machine couldn't make sense of (a bad answer; audio a server or Whisper refused; for transcripts, a machine that didn't finish within ten minutes and four times the speech, or Whisper dying without a word) is charged only if the machine that served it is still fine when checked again; a clip one transcription machine refuses is tried on the others first. Transcripts go to each machine up to its `at_once`, while the next clips' speech is found meanwhile (the worker's old `transcribe_concurrency` is gone). Settings → AI shows each machine's status, offline ones in red, with a red dot on AI in the Settings menu.
- `GET /v1/tenant/context` and `PATCH /v1/admin/tenants/{id}` speak for the first enabled machine doing vision (`vision_api_url`, `vision_api_key`, `vision_model_id`), for clients that know one endpoint (the Mac app). The admin PATCH makes or moves that machine; an empty URL removes it.

## Tenant Maintenance API

All routes under `/v1/tenant/maintenance` require tenant auth and **tenant admin** role (`require_tenant_admin`). Maintenance mode is stored as a JSON value in `system_metadata` under the key `maintenance_mode`. Used to pause operations during upgrades.

- **GET /v1/tenant/maintenance/status** — Returns `{ active, message, started_at }`.
- **POST /v1/tenant/maintenance/start** — Body: `{ "message": "..." }`. Enables maintenance mode. Returns `{ active: true, message, started_at }`.
- **POST /v1/tenant/maintenance/end** — No body. Clears maintenance mode. Returns `{ active: false }`.

## Tenant Upgrade API

All routes under `/v1/tenant/upgrade` require tenant auth and **tenant admin** role (`require_tenant_admin`). These endpoints run idempotent, tenant-scoped upgrade steps (schema migrations and/or data backfills) in a fixed order.

- **GET /v1/tenant/upgrade/status** — Returns `{ has_work, steps_total, done_steps, completed_steps, pending_steps, skipped_steps, failed_steps, next_pending_step_id, remaining_pending_step_ids, steps }` where each step includes `step_id`, `version`, `display_name`, and `status` (`pending|skipped|completed|failed`).
- **POST /v1/tenant/upgrade/execute** — Body: `{ "max_steps": 1, "step_id": null, "force": false }`.
  - With `step_id=null`, runs up to `max_steps` pending steps in order.
  - With `step_id` set, runs only that step if it is pending.
  - Without `force`, the server refuses to run a targeted step when any preceding step is still `pending` or `failed`.
  - Returns `{ ran_steps, steps_completed_now, has_work_after, remaining_pending_step_ids, total_steps, done_steps, completed_steps, failed_steps }`.

## Upkeep API

All under `/v1/upkeep`. Periodic server-side maintenance tasks. Search sync uses timestamp-based tracking (`search_synced_at` on assets and video_scenes) instead of a queue table.

- **POST /v1/upkeep** — Runs all periodic upkeep tasks: search sync, face propagation (auto-assign untagged faces to known people by centroid proximity), deleting for good what has been in the trash longer than the account's trash days (clips a person trashed, 500 a run; libraries by `trashed_at`; projects, whoever owns them; never archived clips; trashing already asked about projects, so the purge doesn't), and revoked token cleanup (purges entries older than 8 days). Returns `{ "search_sync": { "synced", "failed", "scenes_synced", "scenes_failed" }, "face_propagate": { "assigned", "scanned" }, "trash_purge": { "clips", "libraries", "projects" } }`.
- **POST /v1/upkeep/search-sync** — Run search sync sweep only. Finds assets/scenes where `search_synced_at` is null or older than the last update, builds Quickwit documents, and ingests them. Returns `{ "synced", "failed", "scenes_synced", "scenes_failed" }`.
- **POST /v1/upkeep/cleanup** — Query: `dry_run` (default `"true"`), `library` (optional name). Removes orphaned proxy/thumbnail files from storage. Returns `{ "orphan_tenants", "orphan_libraries", "orphan_files", "bytes_freed", "skipped_libraries", "errors", "dry_run" }`.
- **POST /v1/upkeep/recluster** — Force recompute face clusters for all tenants. Stores result in materialized cache. Returns `{ "clusters", "total_faces" }`.
- **POST /v1/upkeep/face-crops** — Backfill face crop thumbnails for faces missing `crop_key`. Query: `batch_size` (default 500). Returns `{ "generated", "skipped", "failed" }`.

## Producers API

ADR-016 phase 3. Each derived artifact kind has one producer (`src/shared/producers.py`): probe, proxy (with its thumbnail), video_preview, analysis_proxy, scenes, scene_vision, vision, ocr, clip, faces, transcript. Every write of an artifact records its **lineage** (table `artifact_lineage`, one row per clip and artifact): the producer, its version, the hash of the settings that affect its output, the SHA-256 of the source file it was made from, and whether it came out `ok`, `empty` or `failed`. An artifact is **current** when all four match what the producer makes now, **stale** when any differs, **missing** when there is none (scene descriptions: until every scene has one).

- Settings live on the server: the registry's defaults, then per-artifact overrides (`system_metadata` `producer.<artifact>`, JSON), then each AI producer's model from its job, chosen in Settings → AI (vision, OCR and scene descriptions: the tenant's `vision_model_id`; transcripts: its `transcript_model_id`). A job's model comes from the job alone: an override can't name another. The worker reads them here and makes artifacts with them, so what it records is current.
- Every machine write says how it was made (Robert, Oct 9: the API doesn't take writes that don't): probe, proxies, video previews and analysis copies, descriptions, OCR, CLIP vectors, faces, transcripts, scenes and scene descriptions, and an ingest's for what it stores (the proxy always; a description with a model, CLIP vectors and a probe when sent). Without `lineage`, or with one that can't be read, it's 422 `lineage_required` (`details`: `artifact`, `producer`); naming another kind's producer (or `person`: only the server says a person made something) is 422 `lineage_wrong_producer`. Either is checked before anything is saved. A person's writes (corrections, a manual transcript) need none. A lineage row that's missing (written before this) is producer `unknown`'s: stale.
- A transcript a person wrote or deleted is producer `person`: current whatever the settings, never regenerated over.
- Only vectors stored under `model_id` `clip` are the CLIP producer's artifact; another model's (the macOS app's FeaturePrint) neither record CLIP lineage nor count as CLIP made.
- **The reconciler** (`src/server/repository/lineage.py`). An artifact is missing when it doesn't exist, whatever its lineage says; one that exists with no lineage at all is `unknown`'s, so stale. The scheduler is handed what's missing, and what was made from a file whose content has since changed (a different file at a path is a new clip, so this is a hash that changed some other way); `missing_*` on `GET /v1/assets/page` and the repair summary's counts are the same rule. Stale from a producer or settings change is **redone** (below), after anything missing. A failure waits its turn (5 minutes, doubling up to a day); the repair summary's `waiting_failures` counts those. OCR (`asset_ocr`, one row per clip) is apart from the description: it needs only the clip, and describing a clip again leaves it alone.
- A failed try keeps its error and is tried again after 5 minutes, doubling up to a day; an artifact made earlier stays what it was.

Writes carry `lineage` as `{ "producer", "version", "settings_hash", "source_sha256" }` (all strings; `source_sha256` defaults to the clip's file now): a JSON field on `PUT /v1/assets/{id}/video-facet`, `POST /v1/assets/{id}/vision|ocr|embeddings|faces|transcript`, the `batch-vision|batch-ocr|batch-embeddings|batch-faces` bodies (each item may carry its own `source_sha256`), `POST /v1/video/chunks/{id}/complete` (recorded for `scenes` when the last chunk completes) and `PATCH /v1/video/scenes/{id}` (`scene_vision`); a JSON form field on artifact uploads (`POST /v1/assets/{id}/artifacts/{type}`; the batch upload takes one object keyed by kind) and on `POST /v1/ingest` (keyed by kind: `proxy`, `probe`, `vision`, `clip`).

- **GET /v1/producers** — Signed in. Query: `library_id` or `project_id` (counts in one library or project; `project_id` needs an editor, like every project route, and a project the caller can't see is 404), `counts` (default `true`; the worker sends `false`). Returns `{ "producers": [{ "artifact", "producer", "version", "title", "media", "uniform", "settings", "settings_hash", "fields": [{ "key", "label", "kind": "int" | "float" | "text", "value", "default", "minimum", "maximum", "unit", "advanced", "fixed" }], "counts": { "applicable", "current", "stale", "missing", "failing", "given_up" } | null, "redoable", "why_not", "paused", "paused_by", "paused_at", "waiting", "unit" }] }` over clips in sight. `unit`: what its work grows with, `"second"` (of video) or `"clip"`. Each producer declares itself in `src/producers/<artifact>/`. `fields`: its output-affecting settings as Settings → Processing shows them; `fixed` says why one can't be changed here (an AI job's model is chosen in Settings → AI; a setting its code doesn't read yet isn't offered), null when it can. `uniform`: its output must come from one model across the library (CLIP, faces). `redoable` / `why_not`: whether stale ones are made again yet (scenes, proxies and video previews aren't: `why_not` says why). `paused`: an admin stopped its redo (`paused_by` is shown to admins only). `waiting`: why its work waits now, for a producer of an AI job: the job is off (no model), no machine does it, or none doing it is online (null otherwise).

**Redo on change.** Changing a model or an output-affecting setting is the approval (Robert, Oct 9): what was made with the old ones is stale, and the scheduler makes it again everywhere, after anything missing (its tier 4), unless an admin stopped that producer's redo. A person's work (a transcript they wrote) is never redone; one made from a file that has since changed is due as missing, not as a redo. Clips made again but still not current (settings read just before a change) wait an hour before they're taken again.

- **PUT /v1/producers/{artifact}/settings** — Admins. Body: `{ "settings": { key: value | null }, "redo": false }`: the settings to change, null putting one back to its default; others stay as they are. 422 `unknown_setting`, `setting_fixed` (the message says why) or `bad_setting` (the wrong kind: a whole number, a number, or text that isn't empty and is up to 4,000 characters; or outside its bounds, which NaN and infinity always are). New settings make what the old ones made stale; it's made again after anything missing (Robert, Oct 9: the change is the approval): 409 `redo_on_change` with `details.clips`, the clips the new settings would make again, until `redo` is true, as a model change in Settings → AI asks; nothing asks when none would be (settings put back before their redo ran). Saving new settings resumes a stopped redo, and the question says so (`details.paused`). Saves to one producer take turns. Only what differs from the defaults is stored. Returns the producer as `GET /v1/producers` lists it (no counts); 404 unknown producer.
- **POST /v1/producers/{artifact}/redo/stop** — Admins. Stop redoing the producer's stale clips: they stay as they are until it's resumed or its settings change; what's missing is still made. Again is fine. 204; 404 unknown producer; 409 `cant_redo` for a producer that isn't redone (scenes, proxies, video previews).
- **POST /v1/producers/{artifact}/redo/resume** — Admins. Redo them again, after anything missing. 204; 404 unknown producer.
- **POST /v1/producers/failures** — Editors and admins (the scheduler). Body: `{ "items": [{ "asset_id", "artifact", "error" }] }`, at most 500; an unknown `artifact` is 422. Each is kept with its error and not handed out again for 5 minutes, then 10, 20 and so on up to a day, and given up after 10 tries (about two days) until someone asks for it to be tried again; an artifact made earlier stays what it was. Clips that don't exist are left out. Returns `{ "recorded" }`. A machine that can't do its job (no machine doing vision or transcripts is online, or none offers the model) isn't reported here: it isn't the clip's failure (see AI machines API).
- **GET /v1/producers/queue** — Signed in. What the scheduler is doing for the account, as it last wrote (every 5 seconds): `{ "live", "at", "running": { kind: jobs }, "waiting": { kind: jobs lined up next }, "pools": { pool: [busy, slots] }, "gpu_hold" }`. `live` is false when it hasn't written for 30 seconds (it isn't running). Kinds: `scan`, `probe`, `render`, `clip`, `vision`, `ocr`, `scene_vision`, `faces`, `transcript`, `scenes`, and `redo_<kind>` for redoing stale ones. `gpu_hold`: requests the AI machines sharing its GPU give up while video is decoded there. `pace`: `{ kind: seconds }`, the seconds a slot spends per unit of a kind's work (a second of video, or a clip: the producer's `unit`), learned from the jobs it finished and kept across restarts. `jobs`: `[{ "kind", "units", "elapsed" }]` running now. While it's `live`, `eta` says how long until things are made: `{ "producers": { artifact: seconds }, "pools": { pool: seconds }, "caught_up": seconds, "jobs": [{ "kind", "artifact", "unit", "units", "elapsed", "left" }] }`. A producer's time is its work left (missing, and stale while its redo runs; given-up clips aren't counted) at its kind's pace over its pool's slots; producers sharing a pool add up; pools run side by side, so `caught_up` is the slowest pool's. `null` where it isn't known yet: no pace, or no machine doing its work. `eta` is null when it isn't live.
- **GET /v1/producers/failures** — Signed in. Query: `artifact`, `library_id` (both optional), `limit` (1–500, default 50), `after` (the `next_cursor` of the page before). Clips in sight whose last try failed, newest failure first: `{ "items": [{ "asset_id", "artifact", "title", "rel_path", "library_id", "library_name", "media_type", "error", "attempts", "failed_at", "retry_at" (null once given up), "given_up" }], "next_cursor" }`. 404 for an unknown `artifact`.
- **POST /v1/producers/failures/retry** — Editors and admins. Body: `{ "artifact"?, "library_id"?, "asset_ids"? }` (any combination; none = every failing clip in sight). Tries them again now, given up or not (the back-off starts over; the last error stays until it's made); the scheduler lets go of its own hour-long hold on clips it just tried. Returns `{ "retried" }`.

## Video chunk API

All under `/v1/video`; require tenant auth. Used by the CLI (`lumiverb ingest`) to process video assets in 30-second chunks. The server owns chunk allocation policy (lease expiration, retry on failure). No video bytes reach the server — only scene rep frame keys and metadata. The CLI generates a unique `worker_id` per session for chunk ownership verification.

- **POST /v1/video/{asset_id}/chunks** — Body: `{ "duration_sec" }`. Initialize chunks for the asset (idempotent). Returns `{ "chunk_count", "already_initialized" }`.
- **GET /v1/video/{asset_id}/chunks/next** — Claim next pending chunk for the asset. Returns 204 if none. On success returns `{ "chunk_id", "worker_id", "chunk_index", "start_ts", "end_ts", "overlap_sec", "anchor_phash", "scene_start_ts", "video_duration_sec", "is_last" }`. Worker must send `worker_id` when completing or failing the chunk.
- **POST /v1/video/chunks/{chunk_id}/complete** — Body: `{ "worker_id", "lineage" (how the scenes were found: required on every chunk, 422 `lineage_required` before anything is saved), "scenes", "next_anchor_phash", "next_scene_start_ms" }`. `scenes`: list of `{ "scene_index", "start_ms", "end_ms", "rep_frame_ms", "proxy_key", "thumbnail_key", "description", "tags", "sharpness_score", "keep_reason", "phash" }`. Persists scenes, updates next chunk anchor state, marks chunk completed. When all chunks for the asset are complete, marks the asset as `video_indexed`. Returns `{ "chunk_id", "scenes_saved", "all_complete" }`. 409 if chunk not owned by worker.
- **POST /v1/video/chunks/{chunk_id}/fail** — Body: `{ "worker_id", "error_message" }`. Marks chunk failed. Returns `{ "chunk_id", "status": "failed" }`. 409 if chunk not owned by worker.
- **GET /v1/video/{asset_id}/scenes** — Returns all scenes for an asset ordered by `start_ms`. Used by VideoVisionWorker. Response: `{ "scenes": [ { "scene_id", "start_ms", "end_ms", "rep_frame_ms", "thumbnail_key", "description", "tags", "sharpness_score", "keep_reason", "phash", "lineage" } ] }`. `lineage`: how the scene's description was made, `{ "producer", "version", "settings_hash" }` (`unknown` when the write didn't say), or null. The worker describes again each scene not made the way it would make it now (a whole video again when every scene already matches but it was handed out), so finishing a part-described video redoes scenes made with older settings too: scenes have no person's edits.
- **PATCH /v1/video/scenes/{scene_id}** — Body: `{ "model_id", "model_version", "description", "tags", "lineage" }`. Updates vision results on a scene after describing its rep frame, with how it was made. The video's `scene_vision` lineage is recorded once every scene has a description made the same way, so a video described half with old settings and half with new isn't current. Response: `{ "scene_id", "status": "updated" }`.
- **POST /v1/video/scenes/{scene_id}/sync** — Body: `{ "asset_id" }`. Enqueues a search sync entry for the given scene. Response: `{ "scene_id", "status": "enqueued" }`.

## Change reports API

The brain mounts storage over the network and can't watch it, so the machine holding the disks (the Mac Studio) reports paths it sees change, and the brain's scheduler scans them (ADR-016 phase 2). Tenant auth: reporting and acknowledging need editor or admin (403 for a viewer); reading needs a signed-in user of any role, even for a public library (401 signed out).

- **POST /v1/changes** — Body: `{ "paths": [...] }`, up to 10,000 absolute paths as the reporting machine sees them, which is how library roots are stored. Each path goes to the library with the deepest matching root (whole folders, Unicode NFC); a path in no live library is counted, not kept. Files or folders, changed, added or removed. 422 for relative paths, `..` or a NUL byte. Returns `{ "accepted", "libraries": { library_id: count }, "unmatched", "unmatched_sample" }`.
- **GET /v1/changes** — Pending counts: `{ "libraries": [{ "library_id", "pending", "oldest_reported_at" }] }`.
- **GET /v1/libraries/{library_id}/changes** — Query: `limit` (default and max 10,000). A library's pending changes, oldest first: `{ "changes": [{ "change_id", "rel_path", "reported_at", "version" }], "truncated" }`. `rel_path` is `""` for the root itself. Reporting a path again keeps one row and raises its `version`.
- **POST /v1/libraries/{library_id}/changes/ack** — Body: `{ "changes": [{ "change_id", "version" }] }`, as read. Removes the changes a scan covered; one reported again since (a higher version) stays. Returns `{ "acknowledged" }`.

## Libraries API

All under `/v1/libraries`; require tenant auth (middleware).

- **POST /v1/libraries** — Body: `{ "name", "root_path" }`. Name must be unique per tenant (409 if duplicate). New libraries inherit the tenant's path filter defaults at creation time (subsequent changes to defaults do not affect existing libraries). Returns `{ "library_id", "name", "root_path", "scan_status", "is_public" }` (scan_status initially `"idle"`, is_public initially `false`).
- **GET /v1/libraries** — Query: `include_trashed` (optional, default false). Returns list of libraries with `library_id`, `name`, `root_path`, `scan_status`, `last_scan_at`, `status` (`"active"` or `"trashed"`), `is_public`, `trashed_at` (in the trash since; its trash days count from here), `revision` (the counter `/revision` reports, so a page across libraries can follow them all from this list). Trashed libraries excluded unless `include_trashed=true`.
- **GET /v1/libraries/{library_id}** — Returns single library. 404 if not found.
- **GET /v1/libraries/{library_id}/ignored-paths** — Signed in only (401 for a public page's visitor). Paths a scan must skip because a person trashed or archived them. Query: `after` (rel_path cursor), `limit` (default 500, max 1000). Returns `{ "items": [{ "rel_path", "reason": "trashed" | "archived" | "emptied", "files": [{ "sha256", "file_size", "file_mtime" }, ...] | null }], "next_cursor" }`, one item per path, ordered by `rel_path`. `trashed` = in the trash; `archived` = a person archived it; `emptied` = deleted for good from the trash (the first of these when a path has several). `files` = the files skipped there, with their size and modified time when a person removed them; `null` when one's content isn't known, and then whatever is at the path is skipped. Another file at the path is a new clip, so a scanner skips a file it finds at one of these paths when its size and time match one listed (untouched), else hashes it and skips it only if its content is listed. A path a clip in sight holds is never listed: the file there is that clip's (a changed file is a new clip, and the old one may be trashed). Scanners count a skipped file as on disk all the same, so it never makes a clip missing.
- **DELETE /v1/libraries/{library_id}/ignored-paths** — Editor. Body: `{ "rel_paths": [...] }`. Forgets emptied-trash records so the next scan ingests those files again (assets still in the trash are restored with `POST /v1/assets/{id}/restore`). Returns `{ "removed": N }`.
- **PATCH /v1/libraries/{library_id}** — Body: `{ "name", "root_path", "is_public" }` (all optional). Updates library name, root path, and/or public visibility. Use `root_path` to repoint a library after moving source files on disk — existing assets match by `rel_path` so the directory structure must be preserved. Setting `is_public: true` inserts a row in the `public_libraries` control plane table, enabling unauthenticated access. Setting `is_public: false` removes it. Returns full library response including `is_public`.
- **DELETE /v1/libraries/{library_id}** — Editor. Move the library to the trash with everything in it: `status` `"trashed"`, `trashed_at` now, clips in sight soft-deleted with `deleted_reason = "library"` (archived and trashed clips keep their reasons). Deleted for good after the trash days, with everything in it. If the library was public, removes its `public_libraries` control plane row. Body (optional): `{ "remove_from_projects": false }`; 409 `in_projects` (see Decisions) when any of its clips are in projects, unless it's true: in the trash they're hidden there, and deleted for good they leave them. Returns 204 on success, 404 if not found, 409 if already trashed.
- **POST /v1/libraries/{library_id}/restore** — Editor. Take the library out of the trash with the clips that went with it (`library`); clips trashed or archived before it went stay as they were, and those in a person's trash get their full trash days again. It comes back private. Returns the library; 404 if not found, 409 `not_trashed`.
- **POST /v1/libraries/empty-trash** — Admin (deleting media for good right away is an admin's; editors trash and restore). Delete trashed libraries for good (cascade: asset_metadata, asset_embeddings, video_scenes, video_index_chunks, assets, library_path_filters, libraries). Removes `public_libraries` control plane rows for any that were public. Body (optional): `{ "library_ids": [...], "remove_from_projects": false }`: those libraries, or all in the trash; 409 `in_projects` (see Decisions) when their clips are in projects, unless `remove_from_projects` is true. Returns `{ "deleted": N }`.
- **GET /v1/libraries/health** — Bulk health indicator. Returns `[{ "library_id", "healthy", "pending" }]` for every non-trashed library, in a single SQL call. `pending` is the number of assets with outstanding work (missing proxy, or anything the reconciler would hand the worker, including failures waiting their turn). `healthy` is `pending == 0`. Used by the libraries page to render a green/orange dot per library without N+1ing `/v1/assets/repair-summary`.
- **GET /v1/libraries/{library_id}/revision** — Lightweight polling endpoint. Returns `{ "library_id", "revision", "asset_count" }`. The `revision` counter increments atomically on asset create/update (ingest) and vision metadata submission. The web app polls this every 10 seconds and, when it changes, refetches the open grid, its facets and folder counts: right away, then at most every 30 seconds while it keeps changing (a long ingest bumps it on every poll), then once more when it stops.
- **GET /v1/libraries/{library_id}/directory** — Query: `path_prefix` (optional). Returns list of subdirectories within a library root. Used by browse UI for directory navigation.

## Library path filters API

All under `/v1/libraries/{library_id}/filters`; require tenant auth and **admin** API key. Path filters control which files are included or excluded during library ingest (scanner). Patterns use `**`-style globs (case-insensitive); `**` matches across path segments. Validation rejects patterns containing `..` or null bytes.

- **GET /v1/libraries/{library_id}/filters** — Returns `{ "includes": [{ "filter_id", "pattern", "created_at" }], "excludes": [...] }`. 404 if library not found.
- **POST /v1/libraries/{library_id}/filters** — Body: `{ "type": "include"|"exclude", "pattern": "...", "trash_matching": false, "remove_from_projects": false }`. Creates filter. When `trash_matching` is `true` and type is `exclude`, also moves every active asset matching the pattern to the trash (deleted for good after the trash days); 409 `in_projects` first when projects use them, and nothing is added until `remove_from_projects` is true. Returns 201 with `{ "filter_id", "type", "pattern", "created_at", "trashed_count" }`. 400 if pattern invalid, 404 if library not found.
- **POST /v1/libraries/{library_id}/filters/preview** — Body: `{ "type": "exclude", "pattern": "..." }`. Returns `{ "matching_asset_count": N }` — count of active assets matching the pattern. Used by UI to show confirmation before creating an exclude filter that would trash assets.
- **DELETE /v1/libraries/{library_id}/filters/{filter_id}** — Removes filter. Returns 204 on success, 404 if not found.

## Tenant filter defaults API

All under `/v1/tenant/filter-defaults`; require tenant auth and **editor** role. Tenant defaults apply dynamically to all libraries via merged evaluation (see below).

- **GET /v1/tenant/filter-defaults** — Returns `{ "includes": [{ "default_id", "pattern", "created_at" }], "excludes": [...] }`.
- **POST /v1/tenant/filter-defaults** — Body: `{ "type": "include"|"exclude", "pattern": "..." }`. Creates default. Returns 201 with `{ "default_id", "type", "pattern", "created_at" }`. 400 if pattern invalid.
- **DELETE /v1/tenant/filter-defaults/{default_id}** — Removes default. Returns 204 on success, 404 if not found.

### Merged filter evaluation

Tenant defaults and library filters are merged at evaluation time with "library wins" priority:

1. **Library exclude** matches → **BLOCKED** (absolute, highest priority)
2. **Library include** matches → **ALLOWED** (overrides tenant restrictions)
3. **Tenant exclude** matches → **BLOCKED**
4. **Tenant includes exist** but path doesn't match any → **BLOCKED**
5. **Default** → **ALLOWED**

This is enforced both client-side (during filesystem walk for efficiency) and server-side (POST /v1/ingest returns 422 for filtered paths).

## Assets API

All under `/v1/assets`; require tenant auth. List/get endpoints return only active (non-trashed) assets.

- **POST /v1/assets** — Single-file upsert. Body: `{ "library_id", "rel_path", "file_size", "file_mtime" (ISO8601), "media_type", "force": false }`. Upserts by `(library_id, rel_path)`. Returns `{ "action": "added|updated|skipped" }`.
- **GET /v1/assets/{asset_id}** — Return single asset with full detail (EXIF, video preview info, and `video_facet` for probed videos, else null). `ai_description`, `ai_tags` and `ocr_text` are what a person sees: what a person wrote, else the machine's; `corrected` lists which of `"description"`, `"tags"`, `"ocr_text"` a person wrote. `transcript_source` is `"manual"` for a person's transcript, else the machine that made it. A public page's visitor (a public library's or a public project's) gets neither `corrected` nor `transcript_source`: they see the result only. Same for `GET /v1/assets/by-path`. 404 if not found or trashed.
- **PATCH /v1/assets/{asset_id}/corrections** — Editors. A person writes a clip's description, OCR or tags. Body: any of `{ "description": str | null, "ocr_text": str | null, "tags": [str] | null }`; only the fields sent change. Edits keep only the latest (Robert, Oct 9): what a person writes is the one copy. The machine's value of that field is dropped, no machine copy is kept under it, and describing or reading the clip again never replaces it. `tags` is the whole list: the machine no longer changes it. An empty string or list is what the person wrote too (there's none). null removes what they wrote: none is left, and the clip's description (or OCR) is missing again, so the machine makes it again (removing the description or tags drops the machine's description too, made again with them). Stored in `asset_corrections`; search documents, the Postgres search, `tag:` filters and facets use what the person sees. What a person wrote is human data. The clip goes back in the search sync's queue until search has the change. Returns the clip's detail. 404 for an unknown or trashed asset. A field whose every part a person wrote (OCR text; description and tags together) is theirs: made, never redone or counted for a new model. Web: the lightbox's Edit beside each (an unchanged Save saves nothing), and Remove beside what a person wrote; a failed save says why and keeps the edit open.
- **PUT /v1/assets/{asset_id}/video-facet** — Store a video's probe result, replacing any earlier one. Body (all optional except as noted): `{ "duration_sec", "container", "video_codec", "width", "height"` (display dimensions, rotation applied), `"rotation"` (0/90/180/270 clockwise, default 0), `"frame_rate_num", "frame_rate_den"` (nominal rate as a fraction, e.g. 30000/1001), `"start_timecode"` (`HH:MM:SS:FF`, or `HH:MM:SS;FF` drop-frame), `"drop_frame", "audio_codec", "audio_channels", "audio_sample_rate" }`. The facet's `duration_sec` becomes the asset's `duration_sec`. Validated (timecode `HH:MM:SS[:;]FF`, positive rate and sizes, rotation 0/90/180/270, finite non-negative duration): 422 otherwise. Returns the facet. 400 for non-video assets, 404 if not found or trashed.
- **GET /v1/assets/by-path** — Query: `library_id`, `rel_path`. Look up asset by library and path. Returns asset detail or 404.
- **GET /v1/assets/page** — Query: `library_id` (required), `after` (cursor), `limit` (default 500, max 500), `missing_vision` (optional bool), `missing_embeddings` (optional bool), `missing_faces` (optional bool, filters to assets where `face_count IS NULL`), `missing_video_scenes` (optional bool, filters to video assets where `video_indexed = false` and `duration_sec IS NOT NULL`), `missing_scene_vision` (optional bool, filters to indexed video assets with scenes lacking vision descriptions), `missing_transcription` (optional bool), `missing_probe` (optional bool, video assets without a `video_facets` row), `missing_analysis_proxy` (optional bool, videos without an analysis proxy), `person_id` (optional, filters to assets with a face matched to this person). Keyset-paginated active assets for bulk reconciliation. Returns `{ "items": [...], "next_cursor" }`; each item says `has_analysis_proxy`.
- **PATCH /v1/assets/{asset_id}** — Update asset fields. Returns updated asset.
- **DELETE /v1/assets/{asset_id}** — Editor. A person trashes one clip, in sight or archived (`deleted_reason = "user"`, `deleted_at` now: its trash days start). It stays trashed through rescans while the file is on disk. Query: `remove_from_projects` (default false); 409 `in_projects` when projects use it (see Decisions). Returns 204; 404 if not found, already in the trash, or trashed with its library. Search documents go after the response (best effort); the library's revision is bumped.
- **POST /v1/assets/project-usage** — Which projects hold these clips: what deleting them for good would take them out of. Body: `{ "asset_ids": [...], "library_ids": [...] }` (either or both; library ids mean every clip in them). Every project counts, archived, trashed and other people's included; only those the caller can see are named. Returns `{ "assets_in_projects", "projects": [{ "project_id", "name", "status", "in_trash", "clips" }], "other_projects" }`.
- **POST /v1/assets/{asset_id}/restore** — Editor. Take a clip out of a person's trash. It comes back everywhere: library, every project holding it, and search (the asset and its scenes are queued for the next search sync; transcript segments are re-indexed after the response). Returns 204; 404 if not found or in sight; 409 `archived` (unarchive it instead), `file_missing` (it comes back when the file does), `library_trashed` (restore the library) or `path_taken` (another clip in sight is at its path now: a changed file is a new clip).
- **POST /v1/assets/restore** — Editor. The same for a selection. Body: `{ "asset_ids": [...] }` (at most 10,000). Returns `{ "restored": [...], "skipped": [...], "to_archive": [...] }`: skipped = not in a person's trash, their library is in the trash, or another clip in sight is at its path now (of two at one path in one call, the first comes back); to_archive = restored ones archived before they were trashed, back in the archive (a single restore does the same).
- **POST /v1/assets/archive** — Editor. Archive clips: out of sight, kept forever with everything they have; scans leave them archived while the files are on disk, and restore by content never claims them. Body: `{ "asset_ids": [...] }` (at most 10,000), or `{ "library_id", "path" }` for every clip in sight under that folder, recursively (`""` = the whole library; `_` and `%` in names are literal). The folder only picks the clips: a file added to it later shows up as usual. 422 for neither or both, 404 for an unknown or trashed library. Returns `{ "archived": [...], "skipped": [...] }` (skipped: not in sight, or unknown). Search documents go after the response; revisions are bumped.
- **POST /v1/assets/unarchive** — Editor. Bring back clips a person archived, by id or folder as above. A missing file's clip is skipped: it comes back with its file. So is one whose path another clip in sight holds now (of two at one path in one call, the first comes back). Returns `{ "unarchived": [...], "skipped": [...] }`.
- **DELETE /v1/assets** — Batch soft-delete; `"reason": "user"` needs an editor, while marking files missing stays open to any role that can scan. Body: `{ "asset_ids": [...], "reason": "user" | "missing" (optional), "remove_from_projects": false }`. `"user"` = a person's trash: takes clips in sight and archived ones (missing or archived by hand), restarts their clock, never takes a clip trashed with its library, and asks first when projects use them (409 `in_projects` unless `remove_from_projects`). `"missing"` = the scanner no longer finds the file (archived); ingest restores it if it reappears. Omitted is recorded as `"missing"` (what scanners sent before reasons existed; the Mac app still does), so a client trashing on a person's behalf **must** send `"user"`. **Copy, then delete the original:** when the account follows moves, an asset marked missing whose content has an active copy in the same library, made after it and untouched by people (no note, no transcript a person wrote or pasted, no rating, in no project, no confirmed or rejected person; the first made if several), moves to that copy's path with everything it had, takes the copy's size and mtime and any cover set to the copy, and the copy is deleted for good. The copy and its faces are locked before they're checked, so a person's work landing meanwhile keeps the copy; a handover that would wait on a person's action (un-assigning a face, merging people) gives way after 200 ms and the asset stays archived. A person's trash never moves. A handover that fails is logged and the asset stays archived; the request still succeeds. Returns `{ "trashed": [...], "not_found": [...], "handed_over": [...] }`: `handed_over` = those of the trashed that moved to a copy instead (active again, at the copy's path).
- **POST /v1/assets/batch-moves** — A scanner's detected moves. Body: `{ "items": [{ "asset_id", "rel_path" }] }`; each active asset takes its new path and goes back in search, others are skipped. 409 `moves_off` when the account doesn't follow moves (`follow_moves` in `/v1/tenant/settings`). Returns `{ "updated", "skipped" }`.
- **POST /v1/assets/{asset_id}/artifacts/{artifact_type}** — Multipart file upload. `artifact_type` must be one of: `proxy`, `thumbnail`, `video_preview`, `scene_rep`, `analysis_proxy`. An `analysis_proxy` is a video's full-length, low-resolution copy with audio, for transcription, scenes and vision (ADR-016 phase 2; not an edit proxy): videos only (400 otherwise), `video/*` content, its own 64 GiB ceiling instead of 100 MB, and a file whose content changes on ingest (new SHA-256) loses it. Form fields: `file` (binary, required), `width` (int, optional, images only), `height` (int, optional, images only), `rep_frame_ms` (int, required for `scene_rep`, ignored for other types). Streams the upload to disk in 64 KB chunks, computes SHA-256 incrementally, and atomic-renames into place. Updates DB after file is safely on disk. Returns `{ "key", "sha256" }`. Errors: 400 invalid type or missing `rep_frame_ms` for `scene_rep`, 404 asset not found or trashed, 413 file too large. A proxy, video preview or analysis copy says how it was made in the form field `lineage` (JSON), and a thumbnail gives the proxy producer's (it makes both): 422 `lineage_required` otherwise, before the file is written.
- **GET /v1/assets/{asset_id}/{proxy|thumbnail}** — Stream proxy or thumbnail file bytes. Returns `application/octet-stream`.
- **GET /v1/assets/{asset_id}/artifacts/{artifact_type}** — Download an artifact. 404 `artifact_not_ready` until it exists. `analysis_proxy` answers `Range` requests (206) and sends its SHA-256 as the `ETag`; public pages get 403 for it, and so do viewers while the account caps playback (they play videos through `/playback`). `video_preview` is cut to the playback cap for whoever asks. A public page gets 404 for a trashed clip's artifacts and 403 for `scene_rep` frames past the public cap.
- **GET /v1/assets/{asset_id}/playback** — A signed link that streams a video for a `<video>` element, which can't send an `Authorization` header. Public pages pass `public_library_id` or `public_project_id` as elsewhere (both: 400). Returns `{ "url": "/v1/stream/<token>", "expires_at", "source", "max_seconds" }`: `source` is `analysis_proxy` (full length, every audio track) or `preview` (the 10-second clip scan makes) until the proxy exists; `max_seconds` is the cap for this viewer (public pages: the smaller of the public and account caps), `null` for the whole video. Links last an hour; the web player asks for a new one when a link fails. 404 asset missing or trashed, or nothing to play yet; 422 not a video.
- **GET /v1/stream/{token}** — Streams what a playback link points at, with `Range` (206) for seeking. No `Authorization` header: the HMAC signature (keyed from `JWT_SECRET`) is the credential, and the tenant comes from the link, so the route skips the tenant middleware. The cap is read when the video is requested, so a new cap applies to links already handed out: a longer video is served as a stream-copy cut of its first N seconds (video and every audio track), kept under `{tenant}/playback/`. Cuts are cleared when a cap changes and when assets are deleted for good; the daily cleanup drops cuts of assets that are gone and stale temp files. `ETag` names the bytes (source, version, cap); an `If-Range` naming another version gets the whole new file (200), so a cap change mid-play can't splice two files. Whether a video runs past the cap goes by the served file's own length, not a stored duration. `Range`: `bytes=a-b`, `bytes=a-`, `bytes=-n` (the last n); a start past the end is a 416. 403 forged, malformed or expired; 404 asset trashed, gone, or no longer public for a link handed to a public page; 503 `playback_cut_failed` if the cut can't be made. `GET /v1/assets/{id}/preview` honors the cap too, and a public page's `transcript_srt` (asset detail) stops at the public cap.
- **GET /v1/assets/facets** — Same `f=` filters as `/v1/query`, and for a public page's visitor the same rules (every `library:` public, at least one; no rating or person filters; text search within the public cap). Returns aggregated filter facets: `{ "media_types", "camera_makes", "camera_models", "lens_models", "iso_range", "aperture_range", "focal_length_range", "has_gps_count", "has_face_count" }`.
- **POST /v1/assets/{asset_id}/faces** — Submit face detections. Body: `{ "detection_model": "insightface"|"apple_vision", "detection_model_version": str, "embedding_model": str (default "buffalo_l": the model that embedded them; the macOS app converts the same one), "lineage" (required), "faces": [{ "bounding_box": dict, "detection_confidence": float, "embedding": [512 floats] | null }] }`. Bounding box: normalized fractions 0.0–1.0, top-left origin. Accepts `{x, y, w, h}` (position+size) or `{x1, y1, x2, y2}` (two corners) — server normalizes to `{x, y, w, h}` before storage. Each detection that re-finds an existing face of the asset (overlapping boxes, IoU ≥ 0.1, whose embeddings are within cosine distance 0.4; boxes without embeddings at IoU ≥ 0.3; then embedding distance < 0.4 alone) updates that face in place: it keeps its `face_id`, confirmed person assignment and rejections, while machine-made (unconfirmed) assignments are re-derived. Embeddings are compared only within one `embedding_model`: across a face-model switch a face is re-found by box overlap alone, and only a substantial one (IoU ≥ 0.5). A confirmed face re-found by a new model rebuilds its person's centroid from the new embedding; centroids, auto-assignment, clustering and suggestions use only the current face model's embeddings (`people.centroid_model`), so names carried across a switch teach the new model those people. Old faces not re-found are deleted unless a person confirmed them, in which case they are kept as-is. Sets `assets.face_count` (new detections + kept faces). Bumps library revision. Returns 201 `{ "face_count", "face_ids" }`; `face_ids` has one id per submitted detection, in order.
- **POST /v1/assets/{asset_id}/ocr** — The text read in an image. Body: `{ "ocr_text": str ("" when there's none), "model_id"?: str, "lineage" }`. Stored in `asset_ocr` (one row per clip), apart from the description: no description needed, and describing the clip again leaves it alone. Re-syncs search. 404 for an unknown or trashed asset. **POST /v1/assets/batch-ocr** — `{ "items": [{ "asset_id", "ocr_text", "source_sha256"? }], "model_id"?, "lineage" }`; returns `{ "updated", "skipped" }` (skipped: unknown or trashed). `GET /v1/assets/{id}` and `/by-path` return it as `ocr_text`.
- **POST /v1/assets/{asset_id}/transcript** — Upload or replace a video's SRT transcript. Body: `{ "srt": str, "language": str | null, "source": "manual" | <provider id, e.g. "whisper">, "lineage" }` (`source` is required: whose it is). A clip has one transcript, the latest (Robert, Oct 9). Stored as `assets.transcript_source`. A person's (`"manual"`, editors) replaces whatever is there. Machine output never replaces a person's: it's dropped, nothing of it kept (`{ "status": "kept_manual" }`); machine output doesn't need an editor (like `/vision` and `/ocr`, it comes from the scheduler's key). Empty `srt` = checked, no speech (`"no_speech"`). Parses SRT to extract plain text for search indexing; re-syncs search (segments replaced). Returns `{ "asset_id", "status": "transcribed" | "no_speech" | "kept_manual" }`. Errors: 400 if not a video or invalid SRT, 403 a manual one from a viewer, 404 if asset not found.
- **DELETE /v1/assets/{asset_id}/transcript** — Editors. Remove the transcript a video shows. A person's: none is left, and the clip's transcript is missing again, so the machine makes one. The machine's: removed for good, a person's choice that nothing makes again (a machine transcript arriving later is dropped: `kept_manual`). Query: `which` (optional): `manual` (a person's) or `machine`, the one the caller means; a transcript from before `transcript_source` existed (none) is the machine's. When the clip shows the other one, 409 `transcript_changed` with `details: { "shown": "manual" | "machine" }` and nothing is removed (a second click never removes more than meant); when it shows none, nothing to do. Re-syncs search. Returns 204; 403 for a viewer; 422 for another `which`. Web: Remove, which says which of the two it does.
- **PUT /v1/assets/{asset_id}/note** — Add or update a freeform note. Body: `{ "text": str }`. Stores last author (email) and timestamp; a public page's asset detail leaves the author out. Note text is indexed for search. Returns `{ "asset_id", "note", "note_author", "note_updated_at" }`.
- **DELETE /v1/assets/{asset_id}/note** — Delete a note from an asset. Returns 204.
- **GET /v1/assets/{asset_id}/faces** — Signed in only (401 for a public page's visitor). List detected faces. Returns `{ "faces": [{ "face_id", "bounding_box", "detection_confidence", "person": { "person_id", "display_name" } | null }] }`. The `person` field is populated when the face is matched to a named person.

## People API

People are tenant-scoped — a person named in one library is recognized across all libraries.

- **GET /v1/people** — Cursor-paginated list of people sorted by face count descending. Query: `after`, `limit` (default 50, max 100), `q` (optional name search, case-insensitive substring match). Returns `{ "items": [{ "person_id", "display_name", "face_count", "representative_face_id", "representative_asset_id", "confirmation_count" }], "next_cursor" }`.
- **POST /v1/people** — Create a named person. Body: `{ "display_name": str, "face_ids": [str] | null }`. If `face_ids` provided, assigns those faces and computes centroid. Returns 409 if any face is already assigned. Returns 201 `PersonItem`.
- **GET /v1/people/{person_id}** — Get a person by ID. Returns `PersonItem` or 404.
- **PATCH /v1/people/{person_id}** — Update display name. Body: `{ "display_name": str }`. Returns `PersonItem` or 404.
- **DELETE /v1/people/{person_id}** — Delete person and all face matches. Returns 204 or 404.
- **GET /v1/people/{person_id}/faces** — Cursor-paginated faces matched to a person. Query: `after`, `limit`. Returns `{ "items": [{ "face_id", "asset_id", "bounding_box", "detection_confidence", "rel_path" }], "next_cursor" }`.
- **GET /v1/faces/{face_id}/nearest-people** — Named people ranked by distance to this face's embedding (`limit`, default 5, max 20): `[{ "person_id", "display_name", "face_count", "distance" }]`. Empty when the face has no embedding, or one from another face model than the account's (mid-switch, it's in another space than the centroids). 404 for an unknown face.
- **GET /v1/faces/{face_id}/crop** — Serve the 128x128 WebP face crop thumbnail. Generated at face submission time from the asset proxy using bounding box + 40% padding. Returns 404 if no crop available (old faces). Immutable caching (1 year).
- **GET /v1/faces/clusters** — Return clusters of unassigned faces. Uses materialized cache; recomputes lazily when dirty (faces added/assigned/unassigned). Query: `limit` (default 20, max 50), `faces_per_cluster` (default 6, max 20). Returns `{ "clusters": [{ "cluster_index", "size", "faces": [...] }], "truncated": bool }`. Not paginated — bounded by `limit` clusters.
- **POST /v1/faces/{face_id}/assign** — Assign a face to a person (stored as confirmed). Body: `{ "person_id": str }` (existing person) or `{ "new_person_name": str }` (creates new person). Clears an earlier rejection of this face for that person. Returns 409 if face is already assigned. Returns `{ "person_id", "display_name" }`.
- **DELETE /v1/faces/{face_id}/assign** — Remove a face from its assigned person. Clears `faces.person_id`, recomputes person centroid, and records a rejection (`face_person_rejections`) so auto-assignment and the upkeep sweep never put the face back on that person. Assigning a cluster to that person skips the face; merging the person carries the rejection to the merge target. Returns 204 or 404.
- **POST /v1/people/{person_id}/merge** — Merge source person into target. Body: `{ "source_person_id": str }`. Reassigns all face matches, updates `faces.person_id`, recomputes centroid, picks best representative face, deletes source. Rejections ("not this person", from un-assigning) carry over to the target. Where a face ends up both matched to and rejected for the merged person, a machine match always loses, and between a confirmation and a rejection the later decision wins, so the result is the same whichever way two people are merged. Serialized via `SELECT ... FOR UPDATE` on source. Returns updated target `PersonItem`. Returns 400 if merging into self.

## Ingest API

Atomic ingest: create + populate assets in one request. The server normalizes the proxy (WebP, 2048px max), generates a thumbnail (WebP, 512px), and stores all provided metadata atomically. If the client sends a WebP proxy already within size limits, the server stores it as-is (no re-encoding).

- **POST /v1/ingest** — Multipart form. Creates asset record AND ingests proxy + metadata atomically. The asset only appears on the server once fully populated. If the clip in sight at the same `(library_id, rel_path)` has the same content (or either content isn't known: no `exif.sha256`), it is updated (idempotent). A different file at the path is a new clip (Robert, Oct 9: nothing carries over), and the old one is archived as missing where it was (its projects too), back if its content is; it goes even when the new file is refused (its file isn't there any more), and when an empty copy of its content is elsewhere it moves there, as a copy-then-delete does. A file whose own clip is archived or trashed at that path is that clip: back if it went missing, refused if a person trashed or archived it; so a path holds one clip in sight and may hold archived ones. Restoring or unarchiving a clip onto a path another clip in sight holds skips it. Required fields: `proxy` (file), `library_id`, `rel_path`, `file_size`. Optional: `file_mtime` (ISO8601), `media_type` (default `image/jpeg`), `width`/`height` (source dimensions), `exif` (JSON), `vision` (JSON), `embeddings` (JSON array), `video_facet` (JSON, video only; same shape as `PUT /v1/assets/{id}/video-facet`; 400 if not a video; an invalid facet is logged and ignored so it never blocks ingest). Returns `{ "asset_id", "proxy_key", "proxy_sha256", "thumbnail_key", "thumbnail_sha256", "status", "width", "height", "created" }`. Enforces library path filters: 422 if `rel_path` is excluded. 409 if the library is in the trash, if a person trashed or archived the asset (`deleted_reason` `"user"` or `"archived"`) or emptied that file from the trash (see `ignored-paths`; another file at that path is its own clip); an asset the scanner marked missing is restored instead and goes back in search (asset and scenes re-queued, transcript re-indexed). **The archive model** (when the account follows moves): a `rel_path` the library doesn't know, whose `exif.sha256` matches an asset in the same library whose file is missing (never a person's trash or archive), restores that asset at the new path with everything it had (ratings, notes, projects, faces, transcript); with several matches, the most recently archived. Two ingests at once can't both claim one archived asset: the other gets an asset of its own. A new clip whose content went missing elsewhere while it was made (a copy and the overwritten original ingested at once) takes that clip, as copy-then-delete: the response gives the clip's `asset_id` with `created` false. 409 when another ingest just put a clip at this path ("scan again"): one clip in sight holds a path.
- **POST /v1/assets/{asset_id}/ingest** — Ingest into an existing asset record. Same proxy + metadata fields minus `library_id`/`rel_path`/`file_size`. A `sha256` in `exif` that isn't the clip's is 409 `different_file` (details `asset_sha256`, `sha256`): a different file is a new clip, made by `POST /v1/ingest`.

## Decisions the API requires

When an action would surprise the user, the API refuses until the request states the user's choice, so every client (web, CLI, macOS, iOS) has to show the facts and ask. The refusal is **409** in the standard envelope, `{ "error": { "code", "message", "details" } }`, with the facts in `details`:

- `in_projects` — trashing clips (`DELETE /v1/assets` with `"reason": "user"`, `DELETE /v1/assets/{id}`, an exclude filter with `trash_matching`: nothing is added until answered), trashing a library (`DELETE /v1/libraries/{id}`), or deleting them for good (`DELETE /v1/trash/empty`, `POST /v1/libraries/empty-trash`) when projects use the clips. In the trash they're hidden there; the trash deletes them for good on its own later, and then they leave those projects, so the question comes when they're trashed. `details` is the project usage (see `POST /v1/assets/project-usage`). Resend with `"remove_from_projects": true` (a query parameter for `DELETE /v1/assets/{id}`).
- `trash_days_shortened` — `PATCH /v1/tenant/settings` with fewer `trash_days` (or turning them back on) when things already in the trash longer would be deleted for good within minutes. `details`: `{ "trash_days", "clips", "libraries", "projects" }`. Resend with `"confirm_purge": true`.
- `redo_on_change` — changing an AI job's model (`PUT /v1/ai/jobs/{job}`) or a producer's settings (`PUT /v1/producers/{artifact}/settings`) when clips were made another way: they're made again, after anything missing, and until that's done results mix the old and the new. `clips` counts only what would be made again. `details`: `{ "job", "model", "clips", "artifacts": [{ "artifact", "title", "clips" }] }` for a model; `{ "artifact", "clips", "paused", "artifacts" }` for settings. Resend with `"redo": true`; clients name the count on the button ("Change it and redo 1,200 clips").
- `clips_in_trash` — restoring a project (`POST /v1/projects/{id}/restore`) whose clips someone trashed. `details`: `{ "trashed_clips", "missing_clips" }`. Resend with `"with_clips": true` (restore them everywhere) or `false` (leave them).

Moving a project to the trash, or archiving clips, is reversible and needs no decision.

## Trash API

- **GET /v1/trash** — Signed in. Clips a person trashed, most recently trashed first; clips of a library in the trash go with the library and aren't listed. Query: `library_id`, `path` (a folder, recursive), `after` (cursor), `limit` (1–500, default 100). Returns `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", "media_type", "trashed_at", "expires_at" }], "next_cursor", "total", "trash_days", "listed_at" }` (`listed_at`: send it back as `trashed_before` when emptying what was shown, so nothing trashed since goes); `expires_at` is when it's deleted for good (`null` when the trash days are off). Thumbnails and proxies of hidden clips load for signed-in people (never on public pages).
- **DELETE /v1/trash/empty** — Permanently delete trashed assets. Requires admin API key. Body: `{ "asset_ids": ["ast_..."] (optional), "trashed_before": "2026-01-01T00:00:00Z" (optional), "library_id", "path" (optional: only that library's trash, under that folder: what a filtered view showed), "remove_from_projects": false }`. Clips of a library in the trash are never reached: they go with the library. 409 `in_projects` (see Decisions) when any of the clips are in projects, unless `remove_from_projects` is true. Only a person's trash is purged (`deleted_reason = "user"`): archived clips are never deleted this way; trash them first. Whatever was restored since it was listed is left alone, so `deleted` can be lower than the number of ids sent. Scope: intersection when both provided. Deletes DB rows in FK-safe order, then best-effort proxy/thumbnail file removal and Quickwit delete. Assets the user trashed leave an `ignored_files` record (library, path, SHA-256), because Lumiverb never deletes originals and the file may still be on disk; scans and ingest keep skipping that file at that path (a different file there is a new clip) until it is removed with `DELETE /v1/libraries/{id}/ignored-paths`. Returns `{ "deleted": N }`.

## Archive API

Archived clips are out of sight but kept forever with everything they have: a person archived them (`POST /v1/assets/archive`, back with `POST /v1/assets/unarchive`), or their file went missing (back by itself when the file is). Deleting an archived clip moves it to the trash.

- **GET /v1/archive** — Signed in. Archived clips, most recently archived first; clips of a library in the trash aren't listed. Query: `kind` (`all` default, `by_hand`, `missing`), `library_id`, `path` (a folder, recursive), `after` (cursor; 400 if malformed), `limit` (1–500, default 100). Returns `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", "media_type", "archived_at", "file_missing" }], "next_cursor", "total" }`.
- **DELETE /v1/archive/missing** — Admins. Delete for good the clips whose files went missing (Robert, Oct 9: hundreds of licensed clips taken off the storage). Body: `{ "library_id"?, "path"?, "count"?, "missing_before"?, "remove_from_projects"? }`: only that library's, under that folder. The API asks first: 409 `confirm_delete_missing` with `details.count` and `details.listed_at` until the request says that `count` and `missing_before` (the `listed_at`): only clips missing since before then go, so nothing that went missing after the admin looked; a different number asks again. Then, about all of them at once and before any goes, 409 `in_projects` (as emptying the trash) unless `remove_from_projects`. Clips archived by hand, in the trash or in sight never go. Returns `{ "deleted" }`. A file that comes back afterwards is a new clip.

## Projects API

Projects are transient, many-to-many sets of clips for one job (ADR-016), across libraries; what ADR-006 called collections. "Collection" is reserved for a future long-lived container. The pre-rename `/v1/collections` paths and the legacy `collection_id` field are gone (Robert, Oct 9: the API as it should be). New ids start `prj_`; ids from before the rename start `col_`.

**Lifecycle**: `status` is `active` or `archived`. Archived projects leave the default list (sidebar, pickers) but keep their clips and stay readable and exportable.

**Trash** (same pattern as assets: delete → trash → restore or delete forever): `DELETE` sets `deleted_at`. A trashed project is gone everywhere else (lists, pickers, detail, clips, export, public link: 404) until restored; only its owner sees it, in `?status=trashed`. Trash is separate from `status`, so a restored project comes back active or archived as it was. Its clips are untouched throughout; emptying the trash removes only the project.

- **POST /v1/projects** — Body: `{ "name", "description" (optional), "sort_order": "manual"|"added_at"|"taken_at" (default "manual"), "visibility": "private"|"shared"|"public" (default "private"), "asset_ids": [...] (optional), "from_search": { "filters": [{ "type", "value" }, ...], "sort"?, "direction"? } (optional) }`. Creates project owned by current user. When `asset_ids` provided, creates and populates atomically. A project is an explicit list of clips (Robert, Oct 9): `from_search` is a search as filter JSON: one `{ "type", "value" }` per filter, with the types and values of `GET /v1/query`'s `f=type:value` (`GET /v1/filters/capabilities`), and `sort` (a `GET /v1/query` sort column) and `direction` (`asc` | `desc`). It puts in the clips the search finds now, in its order, as the creator sees them (their ratings), and the project doesn't follow the search after; to keep the search, save the search (`/v1/views`). 422 `bad_search` (the message says what) for anything it can't read: an unknown key (only `filters`, `sort`, `direction`; a filter only `type` and `value`), an unknown type, a value that isn't text or doesn't parse, an unknown sort or direction. Never dropped, since that would widen the search. 422 `search_too_big` (details `max`) when more than 10,000 clips match, or when any of a text search's index searches (clips, scenes, transcripts, exact or prefix) comes back full at 5,000, since some matches would be left out. 400 with both `asset_ids` and `from_search`. The clips are checked before the project is made: one not found or in the trash is a 404 and no project. A project created public gets its public link at once. Returns 201 with `ProjectItem`.
- **GET /v1/projects** — Query: `status` (`active` default, `archived`, `all` = active and archived, `trashed` = the caller's trash). List projects owned by user + shared projects. Returns `{ "items": [ProjectItem] }`. Each item includes `ownership` ("own" or "shared"), resolved `cover_asset_id` and computed `asset_count`.
- **GET /v1/projects/{id}** — Get project detail. Returns `ProjectItem`. 404 if not found or not visible to user.
- **PATCH /v1/projects/{id}** — Body: `{ "name", "description", "visibility", "sort_order", "cover_asset_id", "status" }` (all optional, only provided fields updated). Owner only (403). Returns updated `ProjectItem`. 400 for invalid sort_order/visibility.
- **DELETE /v1/projects/{id}** — Move the project to the trash. Owner only (403). Clips untouched. Returns 204. 404 if not found or already in the trash.
- **POST /v1/projects/{id}/restore** — Take the project out of the caller's trash, back to active or archived as it was. Body (optional): `{ "with_clips": true | false }`. If clips in it were trashed by someone, the body must say whether to restore them too (everywhere: library, search, other projects) or leave them: 409 `clips_in_trash` otherwise (see Decisions). Returns `{ "restored_clips", "trashed_clips" (left in the trash), "missing_clips" (files missing from disk), "archived_clips" (back in the archive, where they were) }`. 404 unless it's in the caller's trash.
- **POST /v1/projects/empty-trash** — Delete trashed projects for good. Body (optional): `{ "project_ids": [...] }`; the caller's whole trash when omitted. Clients should send the ids they showed, so nothing trashed meanwhile is swept up. Only the caller's own trash; active projects and other people's are never touched. Clips stay in their libraries; a public project's link is removed. Returns `{ "deleted": N }`.
- **POST /v1/projects/{id}/restore-clips** — Restore the project's clips that someone trashed, everywhere (library, search, other projects). Clips trashed because their files went missing are only counted; they come back when the files do; clips whose library is in the trash are never restored here. Editors who can see the project may call it (it's the same as restoring each clip); tenant viewers get 403. Returns `{ "restored", "missing", "archived" }`: `archived` = taken out of the trash but back in the archive, where they were (still hidden). 404 if the project is trashed or not visible.
- **POST /v1/projects/{id}/assets** — Body: `{ "asset_ids": [...] }`. Add assets to project. Owner only (403). Idempotent (duplicates ignored via ON CONFLICT DO NOTHING). Rejects trashed assets (404). Returns `{ "added": N }`.
- **DELETE /v1/projects/{id}/assets** — Body: `{ "asset_ids": [...] }`. Remove assets from project. Owner only (403). Does not affect source assets. Returns `{ "removed": N }`.
- **GET /v1/projects/{id}/assets** — Query: `after` (cursor), `limit` (1–1000, default 200). Paginated asset list ordered by project's `sort_order`. Owner or shared visibility required. Returns `{ "items": [ProjectAssetItem], "next_cursor" }`.
- **PATCH /v1/projects/{id}/reorder** — Body: `{ "asset_ids": [...] }`. Reorder assets. Owner only (403). Must include ALL active asset IDs in the project. 400 if partial. Returns `{ "ok": true }`.

**ProjectItem**: `{ "project_id", "name", "description", "cover_asset_id", "owner_user_id", "visibility", "ownership", "sort_order", "asset_count", "trashed_asset_count", "missing_asset_count", "library_trashed_asset_count", "archived_asset_count", "created_at", "updated_at", "status", "archived_at", "deleted_at" }`. `asset_count` counts clips that are shown; `trashed_asset_count` counts clips someone trashed (hidden and not exported until restored); `missing_asset_count` counts clips a scan trashed because their files went missing (back when the files are); `library_trashed_asset_count` counts clips whose library is in the trash (back if the library is restored); `archived_asset_count` counts clips a person archived.

**ProjectAssetItem**: `{ "asset_id", "rel_path", "file_size", "media_type", "width", "height", "taken_at", "status", "duration_sec", "camera_make", "camera_model" }`

**Key behaviors**: Projects are user-owned (`owner_user_id`). Visibility: `private` (owner only), `shared` (all tenant users can view), `public` (anyone with link). Mutations (add/remove/reorder/delete) require ownership. Asset count is computed at query time (no denormalized column). The cover shown is the chosen `cover_asset_id` while that clip is in the project and in sight, else the first active clip by position (Robert, Oct 9). The choice is cleared when a person trashes its clip (restoring the clip doesn't bring it back) or it leaves the project (removed, or deleted for good); a clip whose file went missing shows the first active clip meanwhile and is the cover again when the file is back. Trashing an asset hides it from projects but preserves the `project_assets` row; restoring the asset restores project membership and position, in every project, trashed ones included. Deleting an asset for good removes it from every project (409 `in_projects` first, see Decisions).

**Send to editor (ADR-016 v1):**

- **GET /v1/projects/{id}/export** — Query: `format` (`fcp7` = DaVinci Resolve / Premiere Pro, xmeml v5; `fcpxml` = Final Cut Pro, FCPXML 1.8). Returns the file as an attachment (`Content-Disposition` with an ASCII `filename` and the real name in `filename*`). Master clips point at the originals as the libraries know them: each library's root plus `rel_path` (Robert, Oct 9: just the brain's paths; the editor relinks where its paths differ). Photos are in it too, as stills of 5 s (video only, no audio): an image asset of no length on a rate-less format in FCPXML, shown 5 s in the event and as a `<video>` on the timeline. FCP7 output is a bin of master clips (video + audio track) plus a sequence laying them end to end in bin order, since Resolve imports FCP7 XML as timelines; FCPXML is an event of asset clips plus a project whose spine does the same. The timeline takes its rate and frame size from the first probed video (no video with a known size: 1920×1080, and only photos: 30 fps); a video at another rate is rounded down onto that grid so it never runs past its media, and a still is rounded to the nearest frame (5 s is 150 frames at 29.97). Timing comes from the video facet: duration in frames, nominal rate snapped to a standard rate within 1%, start timecode (drop-frame aware; malformed ones ignored); unprobed clips use 30 fps and EXIF duration. Pages through every clip (no 1,000 cap). Headers: `X-Lumiverb-Stills` (photos, in it as stills), `X-Lumiverb-Skipped-No-Duration` (videos with no known length, left out), `X-Lumiverb-Unprobed` (videos exported at the fallback rate), `X-Lumiverb-Skipped-Trashed` (clips someone trashed, left out), `X-Lumiverb-Skipped-Missing` (clips whose files went missing, left out), `X-Lumiverb-Skipped-Library-Trashed` (clips whose library is in the trash, left out), `X-Lumiverb-Skipped-Archived` (clips a person archived, left out). Archived projects export too. 400 unknown format, 404 not found or not visible.
- **GET /v1/export/formats** — `{ "items": [{ "id", "label", "file_extension" }] }` for the format chooser.

**Paging**: `GET /v1/projects/{id}/assets` pages with `next_cursor`. Projects sorted by `taken_at` page by capture time, `COALESCE(taken_at, file_mtime, created_at)`.

**Public project endpoints (no auth required):**

- **GET /v1/public/projects/{id}** — Returns privacy-stripped project metadata: `{ "project_id", "name", "description", "cover_asset_id", "asset_count" }`. 404 if project not found, not public, or in the trash. Resolved via `public_projects` control plane table.
- **GET /v1/public/projects/{id}/assets** — Query: `after` (cursor), `limit`. Returns privacy-stripped asset list: `{ "items": [{ "asset_id", "media_type", "width", "height", "taken_at", "duration_sec" }], "next_cursor" }`. No rel_path, no camera info, no GPS.
- Asset thumbnails/proxies served via existing `/v1/assets/{id}/proxy?public_project_id={id}` — verifies asset membership in the public project.

## Unified Query API

One endpoint for browsing and searching, across all libraries the caller can see. `/v1/browse` and `/v1/search` were removed in its favor.

- **GET /v1/query** — Filters are repeated `f=prefix:value` params, ANDed together. Prefixes: `query` (text search), `library` (comma-separated ids), `path` (rel_path prefix), `media` (`image`|`video`), `camera_make`, `camera_model`, `lens`, `iso`, `aperture`, `focal_length`, `exposure`, `has_exposure`, `has_gps`, `near`, `date` (`YYYY-MM-DD,YYYY-MM-DD`, either side optional), `favorite` (`yes`), `stars` (`4`, `4+`, `2-4`, `-3`), `color` (comma-separated), `has_color`, `has_rating`, `has_faces` (`yes`|`no`), `person`, `tag`. Unknown prefixes are ignored; `GET /v1/filters/capabilities` lists every filter for generic client rendering. Other params: `sort` (`taken_at` default, `created_at`, `file_size`, `iso`, `exposure_time_us`, `aperture`, `focal_length`, `rel_path`, `asset_id`), `dir`, `after` (cursor), `limit` (1–500, default 200). With a `query:` filter, Quickwit BM25 (or the Postgres ILIKE fallback) produces up to 5,000 candidates, the other filters apply in Postgres, and results are ordered by relevance; each item carries `search_context` `{ "score", "hit_type": "asset"|"scene"|"transcript", "snippet", "start_ms", "end_ms" }`. Rating filters join the caller's own ratings. Returns `{ "items": [QueryItem], "next_cursor", "total_estimate", "search_source": "quickwit"|"postgres_fallback"|null }`. A public page's visitor (no auth) may query a public library: every `library:` must be public and there must be one (else 403/404); rating and person filters are refused (403); while public playback is capped, text search leaves out the whole-transcript field and drops scene and transcript hits from past the cap.

**QueryItem**: asset fields (`asset_id`, `rel_path`, `file_size`, `media_type`, dimensions, `taken_at`, `duration_sec`, camera and exposure fields, GPS, `face_count`, `thumbnail_key`, `proxy_key`, `created_at`) plus `library_id`, `library_name` and `search_context`.

## Ratings API

User-scoped asset ratings: favorites (heart), stars (1-5), color labels. Each user has independent ratings per asset. Ratings are private — never visible to other users. All endpoints require auth; user identity comes from JWT `sub` or API key `key:{key_id}`.

Rating filters are available on `GET /v1/assets/page` (`?favorite=true`, `?star_min=3`, `?star_max=5`, `?color=red` (comma-separated for multiple), `?has_rating=true`) and on `GET /v1/query` (`f=favorite:yes`, `f=stars:3+`, `f=color:red`, `f=has_rating:yes`). They LEFT JOIN `asset_ratings` for the current user; without rating filters, no JOIN is added (zero cost).

**Face filter**: `?has_faces=true|false` on `GET /v1/assets/page`, `f=has_faces:yes|no` on `GET /v1/query`. `yes` returns only assets with `face_count > 0`; `no` returns assets with no detected faces (face_count=0 or NULL). Applied in SQL.

- **GET /v1/assets/favorites** — List favorited assets across all libraries for the current user, newest first. Query: `after` (cursor), `limit`. Returns: `{ "items": [{ "asset_id", "library_id", "library_name", "rel_path", ... }], "next_cursor" }`. Paginated by `updated_at DESC`.

- **PUT /v1/assets/{asset_id}/rating** — Set or update rating on a single asset. Body: `{ "favorite": bool, "stars": int (0-5), "color": string|null }`. All fields optional — only provided fields are updated. Color values: `red`, `orange`, `yellow`, `green`, `blue`, `purple`, or `null` to clear. If all fields are default (favorite=false, stars=0, color=null), the rating row is deleted. Returns: `{ "asset_id", "favorite", "stars", "color" }`. 404 if asset not found or trashed. 422 for invalid stars/color.
- **PUT /v1/assets/ratings** — Batch rate multiple assets. Body: `{ "asset_ids": [...], "favorite": bool, "stars": int, "color": string|null }`. Same merge semantics as single — only provided fields are updated across all listed assets. Returns: `{ "updated": int }`. 404 if any asset not found. 422 for invalid values or empty asset_ids. Max 1000 asset_ids.
- **POST /v1/assets/ratings/lookup** — Bulk read ratings. Body: `{ "asset_ids": [...] }`. Returns: `{ "ratings": { "asset_id": { "favorite", "stars", "color" }, ... } }`. Assets with no rating are omitted from the map. Max 1000 asset_ids.

Ownership: when a user is deleted via `DELETE /v1/users/{user_id}`, all their ratings are removed from the tenant DB.

## Admin API

Admin routes live under `/v1/admin` and require `Authorization: Bearer {ADMIN_KEY}` (not tenant API keys). If `ADMIN_KEY` is not set, admin routes return 500.

- **POST /v1/admin/tenants** — Body: `{ "name", "plan": "free|pro|enterprise", "email", "vision_api_url", "vision_api_key" }` (a vision URL becomes the tenant's first AI machine doing vision, named after its host). Creates tenant, provisions tenant DB (pgvector + Alembic), creates routing row, creates default API key. Returns `{ "tenant_id", "api_key", "database": "provisioned" }`. On failure, cleans up and returns 500.
- **GET /v1/admin/tenants** — Returns list of tenants with `tenant_id`, `name`, `plan`, `status` (no API keys, no vision credentials).
- **PATCH /v1/admin/tenants/{tenant_id}** — Body: `{ "vision_api_url", "vision_api_key", "vision_model_id" }` (all optional; only provided fields are updated). Updates tenant vision API config. Returns `{ "tenant_id", "vision_api_url", "vision_model_id" }`. 404 if tenant not found or deleted.
- **POST /v1/admin/tenants/{tenant_id}/keys** — Body: `{ "name" }` (human-readable label). Creates new API key for tenant. Returns `{ "api_key", "name", "tenant_id" }`. Raw key returned once and never stored. 404 if tenant does not exist or is soft-deleted.
- **GET /v1/admin/tenants/{tenant_id}/keys** — Returns list of key metadata: `name`, `tenant_id`, `created_at` (never raw keys). 404 if tenant does not exist or is soft-deleted.
- **DELETE /v1/admin/tenants/{tenant_id}** — Soft delete: sets tenant status to `deleted`, revokes all API keys. Returns 204.

## Search

Search is BM25 via Quickwit. The API queries Quickwit then enriches results with Postgres metadata. Never query Postgres for full-text search.

**Query syntax**: unquoted input is loose — `negative space` matches any document containing either word, with a soft ranking boost when both appear as an adjacent phrase. Wrapping input in double quotes requires the exact contiguous phrase — `"negative space"` only matches documents where those two words appear adjacent. Mixed input like `"negative space" beach` is treated as "must contain the phrase AND must contain beach". Quoted phrases are not prefix-expanded (`"disney"` will not match "disneyland"). Unmatched trailing quotes are ignored. Applies to both the Quickwit path and the Postgres fallback.

Text search runs through `GET /v1/query` with an `f=query:...` filter (see Unified Query API). Asset, scene and transcript hits are merged per asset; `search_context.hit_type` says which matched.

**Similarity:**

- **GET /v1/similar** — Find visually similar assets by vector similarity (pgvector). Query params: `asset_id` (required), `library_id` (required), `limit` (default 20, max 100), `offset` (default 0, max 10000). Optional scope filters: `from_ts`, `to_ts` (Unix timestamp seconds, inclusive capture-time range; uses `assets.taken_at`); `asset_types` (comma-separated: `image`, `video`; restricts by `media_type` prefix); `camera_make` and `camera_model` (repeatable; pairs by index, OR across pairs). Returns `{ source_asset_id, hits, total, embedding_available }`. Excludes the source asset from results. If both `from_ts` and `to_ts` are set, `from_ts` must be ≤ `to_ts` (422 otherwise). Person-aware reranking: if the source asset has identified faces, candidates containing the same named person(s) receive a similarity boost (distance *= 0.85).
- **POST /v1/similar/search-by-image** — Body: `{ "library_id", "image_b64", "limit", "offset", "from_ts", "to_ts", "asset_types", "cameras" }`. Upload a query image (base64) and find similar assets. Returns `{ "hits", "total" }`. Server CLIPs the upload — only works for libraries indexed with `model_id="clip"`.
- **POST /v1/similar/search-by-vector** — Body: `{ "library_id", "vector", "model_id", "model_version", "limit", "offset", "from_ts", "to_ts", "asset_types", "cameras", "image_b64" (optional) }`. Search by a pre-computed embedding vector. For clients that embed locally — iOS uses Apple Vision feature prints, macOS uses CLIP via CoreML. The model_id / model_version must match how the library was indexed. **Hybrid mode**: when `image_b64` is also supplied, the server runs InsightFace face detection on the image, embeds each face with ArcFace, runs per-face cosine search against `faces.embedding_vector`, and fuses the identity matches with the scene cosine results via Reciprocal Rank Fusion (k=60). RRF operates on ranks, not raw distances, so it's robust across embedding model spaces. The face path degrades gracefully when no faces are detected, the InsightFace runtime is unavailable, or the image fails to decode — the response falls back to scene-only ranking. Returns `{ "hits", "total" }`.

## Migrations

Alembic manages schema. Two migration contexts:
- `control_plane` — migrations for the shared control plane DB
- `tenant` — migrations applied to each tenant DB on provisioning and upgrade

When adding a column or table to the tenant schema, always add a corresponding Alembic migration in the tenant context.
